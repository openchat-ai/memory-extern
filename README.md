# memory-extern

内存外挂：让 LLM 的权重住在内存里。

一个双线项目，目标是把"把大模型权重放到内存设备里"（现代形态：CXL 类内存侧权重层）这条北极星，拆成两条现在就能走的路：

## 线一 · 研究/软件：MoE 专家缓存三级调度

Kimi-K3 / DeepSeek 一类 MoE 模型推理时，专家权重是**动态路由**的——每个 token 只激活一小部分专家，但"哪些专家、何时用"是数据依赖的。这决定了任何内存侧驻留层都要回答一个问题：**该把哪些字节、何时放在近处**。

**§5.11 复盘（含"36% 墙"的推翻与定损）**（注："36% 墙"指白皮书早期自身演绎，非作者结论——
作者原文明说平坦是 LRU 的、有局部性可挖，作者没有说错任何东西）：
真机 trace 纯请求流结构（`struct_check.py`）
= 8 个"逐层加载遍" × 92 层升序遍历，遍 v 每层 80+16v 专家（非"68 token"注释假设）。
**36.24% 的成因被重新定性为加载顺序，而非容量/策略**：原始顺序把"同层 8 遍反复
加载同一批专家"的复用拆到栈距 6000+；改按层重排（请求集完全不变，`report_real.py`）
**LRU 150 槽（SRAM 级）即 90% = 全局上限**（Belady/容量均非主因）。

**最小内存**：原始顺序下**138 槽（≈2.4GB）即到 36.24% 全平台值**（36.2372124%，
复用簇 1 全接住）；此后到 ~5632 槽（~99GB）加内存零收益（复用距离真空）——
平台区内存完全中性（既不加命中也不降速）。

~99GB 是 90% 容量区间内的零收益平台。

**为什么 2.4→99GB 零提升（复用距离实证）**：
- 原顺序复用距离分布三堆：**d≤138 占 35.98%**（→ 36.24% 命中来源）、
  **138<d≤5632 占 0.261%**（死区，空）、**d>5632 占 53.76%**（撒向远端第二簇）。
- 容量在 (138, 5632] 内加槽时，流中没有任何请求会在该区间被重用 → 新槽全空转。
- **死区不是 trace 固有属性，是作者把请求顺序钉死为常量产生的假象**：层优先重排后
  复用距离变为 平均82/中位80/max190（d≤150 占 76.88%），死区消失、150 槽即 90%。
  作者"加内存白加"的结论 = 其自身把顺序当不可变约束的错误设计自我实现。

**层内聚拢顺序是命中率唯一关键变量（会话数无关）**：
- **layer-first 离线重排 + 单 LRU 138 槽（2.4GB）= 89.76%**；150 槽（2.6GB）= 90.00%。
  ⚠️ **三条前置**：① layer-first = 把同层 8 遍访问聚拢再进下一层（`--order layer-first`
  复现）；② **离线**：完美聚拢需知全部请求，现实逐 token 推理做不到；③ 在线批内聚拢
  （批≤5000）实测仅 36%（白皮书 §5.11）。
- 机制：同层 8 遍专家集合**高度稳定**（每遍仅 +16 递增，如层1去重仅 150 专家），
  138 槽装得下该层全部热专家 → 层内命中 ~90%。
- 反证陷阱：把 trace 按层建"W 个独立会话池"看似 89.76%，实则每个池本身就是
  一条 layer-first 流——**增益全部来自层内聚拢这一个重排，与池数完全无关**。
  92 会话×138 槽 = 222.8GB 也比单池 2.4GB 多 ~100×，命中却一模一样。
- 原顺序单 LRU 的 36% 是把 92 层搅在一把 cache 里互相污染的假低；
  round-robin 均摊多流更差（同层间隔 >>138 命中跌到 7~25%）。
- **在线替代（不聚拢，靠历史热度）**：预测式预取 top150 = 88.46%、作者引擎落地 90.09%
  ——见下方"预测式预取"；那是与上述 layer-first 并列的第二条在线路线，不是"同一红利"。

**组数-命中对照（固定分母 N=100096，每组独立 138 槽）**：
| W | 内存 | 组内聚拢 | 组内不聚拢(原序筛层) |
|---|---|---|---|
| 1 | 2.4GB | **89.76%** | 36.24% |
| 2 | 4.8GB | **89.76%** | 36.24% |
| 8 | 19.4GB | **89.76%** | 36.24% |
| 16 | 38.7GB | **89.76%** | 36.24% |
| 32 | 77.5GB | **89.76%** | 36.87% |
| 40 | 96.9GB | **89.76%** | 42.02% |

- **1 组（2.4GB）聚拢即 89.76%**（=layer-first），组数无上限需求；组数只定并行度/容量。
- **聚拢 vs 不聚拢在 2.4~96GB 段差 50+ 个百分点**——聚拢是本方案的价值全部。
- 聚拢代价 = 等待延迟（凑齐一层 8 遍，原始流 p50≈88K 请求）。
- 组内不聚拢：保持 trace 时间序只筛层，恒 36% 直到 W→92（每层一组天然聚拢才解冻）。
- **结论：90% 由"层内聚拢"唯一决定；组数/内存只定并行度，不改命中。**

**大内存还要不要？要——但职责与命中率无关：兜住 10% 冷启动**：
- miss 分解：大内存 10010 槽（175.6GB）的 miss **100% 是 compulsory**（每专家首次出现，
  10,010 次，恒 10%），驱逐重装 = 0；layer-first 138 槽 miss = compulsory 10,010 +
  驱逐重装 239（仅 0.24%）。两条路命中都 ≈90%，miss 量也几乎一样——命中率救不了首次。
- 真正分工：**layer-first/预测式让"已曾出现的专家"不落盘**（SRAM 2.4GB 即可 90%）；
  **大内存（DRAM 175.6GB）兜住首次冷启动**——全模型一次性加载（~20 s）后永久驻留，
  之后的 10% 首次请求也就近命中内存，不碰磁盘。
- 结论：大内存不是"把 36% 推到 90%"的工具（那条 layer-first 用 SRAM 就够），而是
  "让 90% 之外那 few 个 miss 仍快"的既有底座。方向：命中率 → 顺序/预取；速度 → 驻留/DRAM。

**🔴 开放项 A（最高优先）：真实模型复用距离形状——分簇 or 平滑**：
- 起因：本条 trace 的容量-命中曲线在 138→5632 槽恒 36% 平台、10010 槽跳变 90%，

- 决定性影响：若真实模型复用距离**平滑** → 用户方案（少量 138 组 + 共享聚合层）
  在中间档位即有效，无需全模型驻留；若**分簇** → 只有层内聚拢 / 全驻留两条路。
- 待真实 checkpoint 到达后的第一件事：`--dump-cache-trace` 生成 ≥2 条独立真实
  trace，测复用距离分布与容量-命中曲线形状，对比本条双簇结论是否成立。

  |---|---|---|---|

**✅ Q3 GEMV 真机微基准（2026-08-19，Hygon C86-3G，WSL Ubuntu gcc 15.2，
`pim/bench_q3_x86` 500 reps）**：专家权重 GEMV 是推理热路径，与算力墙结论直接相关。
- 参数：cols=3584、Q3 8 值 {-4..3}、group=32；三档批量 64/512/20480 行（1/8/320 专家）。
- **`opt(f32)` 4-way unroll 全档最快**：1.65-1.80 GB/s（3.3-3.6 GFLOP/s），x2.3-2.7 over
  double scalar baseline（0.6-0.8 GB/s）。
- **全部 AVX2 变体（gather/2pass/4row/8row）不及 opt(f32)**（x1.2-1.6）：`_mm256_i32gather_ps`
  在这颗 Hygon（Zen 变体）上延迟高，查表+解码反被拖累；v3(8way) 寄存器压力大也不如 opt。
- 8 线程仅在 320 专家大批量（pk=73.4MB）有效：2937 MB/s、x3.92；小批量无收益。
- 结论：这颗 CPU 上 Q3 GEMV = 简单 fp32 + 4-way unroll 即最优；AVX2 查表花活被 gather
  延迟吃光，多线程只在大批量划算。复现：`gcc -O3 -mavx2 -mfma -march=x86-64-v3 -o bench_q3_x86 bench_q3_x86.c -lm -lpthread && ./bench_q3_x86 500`。
- 旁证（pim 参考内核，与主线 Q3 模型无关，仅归档）：MXFP4 double 逐位参考 ~170 MB/s、
  f32 累加也只 x1.2——主瓶颈在 E2M1 查表 + wf 中转，不是累加精度。

- 阻塞：需真实模型权重 + 作者引擎，0 资源无法离线生成（唯一 trace 为作者所有）。
- **作者实验覆盖对照（已核验其仓库 README）**：

    真机曲线（8~64GB 0% 参与、knee≈36GB arena）、"平台属 LRU 非负载"（Belady 同区间

  - 未测：复用距离分布（全文无 "reuse distance"）、每层专家复用分析、layer-first/
    顺序重排实验、逐 GB 边际收益曲线（无专家缓存单一最优容量答案）。
  - 要点：作者看到的"平台+跳变"与本项目 36.24%→90% 是同一现象（双簇分布）；
