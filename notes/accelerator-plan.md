### 关键洞察（2026-08-20 更新）

**GEMV 每 MAC：2B 权重 (DRAM) + 2B 激活 (SRAM) = 4B**
- 权重从内存读取 (2B)
- 激活从片上 SRAM 读取 (2B)
- 外部内存只需供应权重：68 × 1.0 × 2 = **136 GB/s**
- 内存能供应：171 GB/s (8ch) 或 85 GB/s (4ch)

**8ch LPDDR5X (171 GB/s) > 136 GB/s → 计算瓶颈 → MAC 满载，不能降频**
**4ch LPDDR5X (85 GB/s) < 136 GB/s → DRAM 瓶颈 → MAC 可降到 0.63GHz**

| 内存配置 | DRAM 带宽 | 权重需求 | 比值 | 瓶颈 | MAC 可降频 |
|---|---|---|---|---|---|
| LPDDR5X-8ch | 171 GB/s | 136 GB/s | 1.25x | 计算瓶颈 | ❌ 否 |
| LPDDR5X-4ch | 85 GB/s | 136 GB/s | 0.63x | DRAM 瓶颈 | ✅ 是 |
| HBM3-1stack | 819 GB/s | 136 GB/s | 6.02x | 计算瓶颈 | ❌ 否 |
| HBM3-2stack | 1638 GB/s | 136 GB/s | 12.05x | 计算瓶颈 | ❌ 否 |

### MAC DVFS 功耗优化

**前提**：8ch LPDDR5X (171 GB/s) > 136 GB/s → 计算瓶颈，MAC 满载，不能降频

| MAC 频率 | 计算 BW | 权重需求 | 内存 BW | 瓶颈 | MAC 功耗 | 总功耗 | 省电 |
|---|---|---|---|---|---|---|---|
| 1.0 GHz | 272 GB/s | 136 GB/s | 171 GB/s | 计算瓶颈❌ | 20.0W | 30.0W | 0% |
| 0.8 GHz | 218 GB/s | 109 GB/s | 171 GB/s | 计算瓶颈❌ | 10.2W | 20.2W | 33% |
| 0.6 GHz | 163 GB/s | 82 GB/s | 171 GB/s | 计算瓶颈❌ | 4.3W | 14.3W | 52% |
| 0.4 GHz | 109 GB/s | 54 GB/s | 171 GB/s | 计算瓶颈❌ | 1.3W | 11.3W | **62%** |

**注意**：8ch LPDDR5X 是计算瓶颈，降频会降低性能！仅适用于 MoE 空闲芯片或4ch DRAM 瓶颈场景。

**INT4 SIMD 场景**：权重需求降到 34 GB/s，DRAM 有 5x 余量，MAC 可降到 0.2GHz 省电 99%！

**MoE 场景**：空闲芯片断电 + MAC 0.6GHz = 省 88% 电，性能不变！

### INT4 MAC SIMD 设计（2026-08-20 新增）

**核心洞察**：INT4 不只省带宽，SIMD 并行可 **4x 提速**！

**原理**：
```
bf16: 1 MAC × 1 multiply-add/cycle = 1 GOPS
INT4: 1 MAC × 4 multiply-adds/cycle = 4 GOPS (4个INT4值打包进一个寄存器)
```

**影响**：

| 指标 | bf16 | INT4 (SIMD 4x) | 变化 |
|---|---|---|---|
| 计算吞吐 | 272 GOPS | 1088 GOPS | **4x ↑** |
| 权重需求 | 136 GB/s | 34 GB/s | **4x ↓** |
| DRAM 带宽 | 171 GB/s | 171 GB/s | 不变 |
| 瓶颈 | 计算瓶颈 | **DRAM 有5x余量** | 可降频! |

**Llama-7B 性能对比**：

| 精度 | 计算时间/层 | 总时间 | tok/s | vs bf16 |
|---|---|---|---|---|
| bf16 | 0.246 ms | 7.87 ms | ~127 | 1.0x |
| INT4 (SIMD 4x) | 0.061 ms | 1.96 ms | **~510** | **4.0x** |

**INT4 带来**：
1. **4x 计算提速** (SIMD 并行)
2. **4x DRAM 余量** (可降频省电)
3. **4x 容量节省** (同样的 DRAM 装 4x 更大模型)

**硬件设计**：
- 68 个 INT4 MAC 单元，每个可并行处理 4 个 INT4×bf16 multiply-adds
- 需要 INT4→bf16 去量化模块（在 MAC 内部完成）
- 支持 Q4_0, Q4_K, Q3_K, IQ4_NL 等 ggml 格式（Q3 填充到 4bit 处理）

**软件栈（无需修改 llama.cpp）**：
- ggml 已有完整 backend 架构 (`GGML_BACKEND_DEVICE_TYPE_ACCEL`)
- 我们只需创建 `ggml-backend-ourchip.so`
- 实现 `GGML_OP_MUL_MAT` 操作，声明支持 INT4 格式
- ggml scheduler 自动将 INT4 权重发送到我们的芯片
- 动态加载：`ggml_backend_load_all()` 自动发现

**功耗优化**：
- INT4 有 5x DRAM 余量 → MAC 可降到 0.2GHz
- 0.2GHz 功耗: 20 × 0.2³ = 0.16W (vs 20W @1.0GHz)
- **省电 99%**，性能不变！

## 范围外（不做）

| 工作 | 原因 |
|------|------|
| PIM-DIMM 方案 | 已证伪：做不过 GPU，最终变成 GPU |
| SRAM CIM 阵列（独立模块） | 已否决：独立芯片 + PCB 焊盘方案不成立，见"芯片设计"节 |
| CIM 阵列 RTL（DAC→SRAM→ADC） | 若做 CIM，集成进主芯片 die 或 DRAM 近存（独立 V2 项目） |
| CPU 端 GEMV 内核优化（NEON/AVX2） | ggml 的活，不是芯片的活 |
| MXFP4 E2M1 引擎 | 真实权重精度不够（p50(max_err)=31%，DAC/ADC 不叠加），已证伪 |
| Q3/Q4 CPU benchmark | 芯片不做 CPU 侧优化 |
| TT 芯片提交 | 无商业价值 |
| 三级预取调度器（sched3/sched4） | 属于缓存架构，芯片不做缓存 |
| 缓存命中率分析 | 软件层问题，芯片不解决 |
| Trace 采集与分析 | 用于验证，不是芯片本身 |
| 芯片间互连/光互连 | 不需要，单芯片足够 |
| 3D 堆叠 | 用不起，成本太高 |
| HBM | 买不到，全给 NVIDIA/AMD 了 |
| GDDR6X | Micron 独家，正在停产 |
| SOCAMM2 插槽 | 带宽掉 3 倍（136 vs 68 GB/s），不值得 |
| 混合直焊+插槽 | 调度复杂，慢的拖累快的 |
| CXL + DDR5 | 带宽太低（~100 GB/s），不够用 |
| GDDR7（V1） | 功耗高、散热难，V2 再考虑 |
| 测试控制器（BIST） | V1 不需要，FPGA 验证够用 |
| profiling 工具 | V1 不需要，量产后再做 |

## 为什么全直焊，不用插槽

| | 全直焊 LPDDR5X | SOCAMM2 插槽 |
|---|---|---|
| 带宽 | **171 GB/s**（8ch） | 136 GB/s（8ch，但插槽损耗） |
| 延迟 | **低**（走线短） | 高（模块化损失） |
| 信号质量 | **好** | 差 |
| 可升级 | 不能 | 能 |
| 复杂度 | **低** | 高（两种速度管理） |
| 成本 | **低** | 高（插槽贵） |

**结论**：插槽带宽掉 3 倍，不值得。全直焊最简单、最快、最便宜。

### CIM 演进（不做独立芯片）

独立 CIM 芯片 + PCB 预留焊盘方案已否决，理由：

1. **封装放不下**：CIM die ~10mm²，焊盘只给 20mm²，最小 BGA 封装 27mm² 起，模拟芯片（DAC/ADC 引脚多）需 64mm² 才现实。
2. **模拟 SI/PI 无法预留**：AVDD/DVDD/VREF/地岛隔离、去耦位由 PCB 层叠决定，V1 纯数字设计未做这些。
3. **原理上不是存内计算**：独立芯片离 DRAM 数十毫米走线，带宽墙照样在，绕一圈什么都没省。

CIM 的正确形态二选一（独立 V2 项目）：
- **集成进主芯片 die**：V1 架构规划时在 die 内预留接口
- **DRAM 近存**：CIM 进 LPDDR5X 侧，与 V1 PCB 无关

## PIM 精度模拟结果（2026-08-20，`tools/pim_sim_full.py`，733 tensor / 472 有效）

```
mxfp4            p50(max_err) = 3.1e-1    ← cell 表示饱和（8 档电平不够）
int8_blk32       p50           = 1.1e-2    ← cell + DAC10 + ADC12 + noise 全部叠加
int8_blk256      p50           = 1.4e-2
int6_blk32       p50           = 3.4e-2    ← 边界可用
dac_adc_only     p50           = 2.9e-3    ← 外围量化不是瓶颈
cell_only_int8   p50           = 8.1e-3    ← 纯 cell 量化误差
```

结论：
1. MXFP4 精度不可用（p50=31%），DAC/ADC 噪声在此之上不叠加
2. 8-bit uniform cell (blk32) 精度可行（p50=1.1%），源量化类型差异 <2×
3. 6-bit cell 边界可用（p50=3.4%）
4. PIM 精度不是瓶颈，带宽才是。PIM 硬件方向仍取决于能否做足够高的带宽

## 核心结论

1. **全直焊 LPDDR5X**：单芯片 8ch = 171 GB/s，SerDes 互连多芯片扩展，不用插槽，最简单最快最便宜。
2. **不预留 CIM 焊盘**：独立 CIM 芯片 + PCB 焊盘的方案已否决。PCB 只做 V1 纯数字设计。
3. **V1 是生存**：纯数字，简单，能活。用成熟技术验证商业价值。
4. **CIM 是演进**：若做，集成进主芯片 die 或 DRAM 近存，独立 V2 项目。
5. **内存配置**：V1-128G（8ch LPDDR5X，128GB），长鑫 CXMT 国产首选。
6. **已有 RTL 可复用**：BF16/FP32/add/scale/MAC 已验证，省 2-3 月开发时间。
7. **启动资金**：V1 需要 364-808 万 RMB（14nm MPW + PHY 授权）。
8. **瓶颈分析（修正）**：GEMV 每 MAC 2B 权重 + 2B 激活 = 4B，外部内存只需 136 GB/s。8ch (171 GB/s) 是计算瓶颈，MAC 不能降频；4ch (85 GB/s) 是 DRAM 瓶颈，MAC 可降到 0.63GHz。
9. **性能公式**：effective_bw = min(compute_bw, dram_bw)，不是只用 dram_bw。
