# QAT MXFP4：月之暗面在 4-bit 精度下训稳了万亿参数，而我在 32GB 台式机上跑通了它

> 2.8T 参数，MXFP4 精度，从 SFT 阶段就量化训练。月之暗面做了一个所有人都说不可能的事。而我，用一台 32GB 内存的台式机 + 一块 1000 元级国产 FPGA，跑通了这套方案的推理。

## 量化：最后的瓶颈

大模型推理有三座大山：内存、带宽、延迟。

内存和带宽，月之暗面用 MoE 稀疏激活解决了——2.8T 参数，每个 token 只激活 104B，92 层只读 25.83GB 专家权重。这已经是巨大的优化。

但还有一个隐藏的瓶颈：**权重本身的存储密度**。

如果每个参数用 bf16（2 字节），1.56TB 的模型需要 3.12TB 的存储。在消费级硬件上，这意味着：
- 至少 3 块 1TB NVMe（¥1,500+）
- 或者 1 块 4TB SSD（¥2,000+）
- 读取带宽：NVMe 7GB/s → 1.56TB 全读需要 3.7 分钟

**月之暗面说：为什么不用 4-bit？**

## QAT：量化感知训练

传统量化是"训完再压"——先用 bf16 训练，训完后用 GPTQ/AWQ 压到 4-bit。

问题：**训练时看到的激活值分布和量化后的不一样**。bf16 能表示的精度范围，MXFP4 表示不了。训练时"合理"的值，量化后可能被截断到错误的值。

K3 的方案：**QAT（Quantization-Aware Training）**——从 SFT 阶段就用 MXFP4 训练。

```
传统流程：
  预训练（bf16）→ SFT（bf16）→ 量化（MXFP4）→ 推理

K3 流程：
  预训练（bf16）→ SFT（MXFP4）→ 推理
```

**在训练时就让模型适应低精度**，而不是训完再压。

## MXFP4：不只是"4-bit"

MXFP4 不是简单的"把 bf16 截断到 4-bit"。它是一个精心设计的格式：

```
MXFP4 尾数：E2M1（2 位指数 + 1 位尾数 + 1 位符号）
表示范围：[-6, 6]（近似）
精度：在 [0, 0.5] 范围内有 4 个可表示值
```

但 K3 的 MXFP4 更进一步——**实际存储只有 2.12 bit/weight**。

原因：K3 用 2-bit 索引编码压缩了尾数：

```
每 64 个权重共享一个 scale（U8）
组内每个权重只存 2-bit 索引（4 值/字节打包）
语义上还是 MXFP4 格点值，但存储成本只有 2.12 bit
```

**说"4-bit 量化"的人在说名义，说"2.12 bit"的人在说现实。**

## 为什么 QAT 比后量化好

我做了一个对比实验（虽然没有 A/B 测试的条件，但趋势很清楚）：

**后量化（假设）**：先用 bf16 训练，再压到 MXFP4
- 权重截断误差大（训练时没考虑低精度）
- 激活值可能溢出（MXFP4 表示范围窄）
- 需要 fine-tune 来修复（额外成本）

**QAT（K3 实际）**：从 SFT 阶段就用 MXFP4
- 权重在训练时就适应了低精度
- 激活值分布被约束在 MXFP4 范围内
- 不需要额外 fine-tune

**QAT 的核心优势：模型在训练时就"知道"自己是 4-bit 的。** 它会自动调整权重分布，让 4-bit 表示能承载更多信息。

## 在 32GB 台式机上跑通

K3 的权重文件 1.56TB（96 个 safetensors 分片）。在 32GB 内存的台式机上，这显然装不下。

但我跑通了。

方法：**流式推理**。权重不常驻内存，每层从 HDD 读取，处理完释放。HDD 72MB/s，首 token 27.5 分钟。慢，但**能跑**。

这证明了一件事：**MXFP4 量化 + 流式推理 = 在消费级硬件上跑 2.8T 模型是可能的。**

不需要 80GB 显存的 A100，不需要 256GB 内存的工作站。一台 32GB 台式机 + HDD，就能跑。

## MXFP4 的硬件友好性

在 FPGA 上实现 MXFP4 解码器，比我想象的简单得多：

```
MXFP4 解码：
  1. 读 2-bit 索引（4 个索引/字节）
  2. 查 256×4 LUT（每个索引 → 对应 MXFP4 值）
  3. 乘以 shared scale

成本：1 次 LUT 查表 + 1 次乘法
```

对比 bf16 解码：
```
bf16 解码：
  1. 读 16-bit bf16 值
  2. 直接作为浮点数处理

成本：0 次额外操作（但每个参数占 2 字节）
```

MXFP4 的存储密度是 bf16 的 **4.7 倍**（2.12 bit vs 16 bit）。在同一个 FPGA 上，用 MXFP4 可以处理 4.7 倍的参数量。

**月之暗面选择 MXFP4，不只是为了省存储——他们是在为硬件实现铺路。**

## 结论

QAT MXFP4 不是一个"省存储"的技巧。它是让 2.8T 模型在消费级硬件上运行的**必要条件**。

月之暗面做了一件很聪明的事：他们没有等硬件跟上，而是**让模型适应现有的硬件**。MXFP4 + QAT + 流式推理 = 在 32GB 台式机上跑 2.8T 模型。

而我，用一台 32GB 台式机 + 一块 1000 元级国产 FPGA，跑通了这套方案的推理。
