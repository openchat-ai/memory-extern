Quantile Balancing：896 个专家的路由，如何不调参就均衡

MoE 的路由均衡是出了名的难调——辅助损失的权重 λ 太大伤害质量，太小均衡不住。月之暗面说：为什么要调参？直接用分位数硬保证。

辅助损失：MoE 的阿喀琉斯之踵

MoE 的路由均衡，传统方案是辅助损失（auxiliary loss）：

总损失 = 语言模型损失 + λ · 路由均衡损失

路由均衡损失 = Σ(每个专家被选中的频率 - 1/总专家数)²

这个方案的问题：

1. λ 是超参数：太大 → 模型质量下降（被迫选不相关的专家）；太小 → 均衡不住

2. λ 需要调：不同模型、不同规模、不同训练阶段，最优 λ 都不同

3. λ 和质量是矛盾的：均衡损失和语言模型损失在梯度方向上是冲突的

在 2.8T 参数的 MoE 上调 λ？没人敢。

Quantile Balancing：不调参的硬保证

K3 的方案：用分位数统计直接保证均衡，不需要辅助损失，不需要调 λ。

Quantile Balancing 的逻辑：

1. 记录每个 token 对每个专家的 gate 值
2. 按 gate 值排序，计算每个专家的"分位数"
3. 根据分位数决定每个专家的"配额"
4. 强制每个专家被选中的频率接近 1/896

这不是"软均衡"（辅助损失），而是"硬均衡"（分位数保证）。

为什么分位数有效

gate 值的分布是已知的——通常是对数正态分布或长尾分布。

gate 值分布（示意）：

  频率
  ↑
  │ ██
  │ ████
  │ ██████
  │ ████████
  │ ██████████
  │ ████████████
  │ ██████████████
  │ ████████████████
  └──────────────────→ gate 值
     0.01  0.1   1   10

大部分 token 的 gate 值在中间区域，少数在两端。

Quantile Balancing 的做法：

- 统计所有 token 的 gate 值分位数

- 每个专家根据其 gate 值的分位数，获得对应的"配额"

- 如果某个专家的 gate 值普遍偏高（被过度选择），降低其配额

分位数是分布的"骨架"——它不关心具体值，只关心排序。 这使得它对 gate 值的绝对大小不敏感，只对相对排序敏感。

对比辅助损失

方案需要调参？均衡保证？对质量的影响？
辅助损失是（λ）软保证（概率性）可能伤害
Quantile Balancing否硬保证（确定性）无

Quantile Balancing 是唯一一个不需要调参、不需要牺牲质量的路由均衡方案。

我的发现：均匀路由是缓存策略的基石

我在做专家缓存仿真时，发现了 Quantile Balancing 的一个意外好处：

均匀路由让缓存策略可预测。

如果路由不均匀（某些专家被频繁选中，某些很少），缓存策略的效果会大幅波动：

- LRU 在"热专家集中"时效果好，但"热专家分散"时效果差

- LFU 需要长期统计，短期不准

- 预取需要知道未来访问模式，不均匀路由让预测变难

Quantile Balancing 保证了每个专家被选中的频率接近 1/896。这意味着：

- 每个专家的"热度"几乎相同

- LRU 和 LFU 的效果几乎一样

- 缓存命中率是可预测的（我实测 35.3%@1GB）

如果路由不均匀，我的 35.3% 缓存命中率可能是 10%，也可能是 60%——无法预测。

Quantile Balancing 让硬件设计有了确定性。

对 FPGA 实现的影响

Quantile Balancing 对 FPGA 实现有一个直接影响：

Router 可以用简单的 LUT 实现。

传统 MoE 的 router 需要：

1. 计算每个 token 对每个专家的 gate 值（矩阵乘法）

2. 排序（top-k 选择）

3. 均衡调整（辅助损失）

K3 的 router 只需要：

1. 计算 gate 值（矩阵乘法）

2. 分位数查表（LUT）

3. 强制均衡（硬保证）

排序和均衡调整都可以用 LUT 替代，在 FPGA 上几乎零成本。

结论

MoE 的路由均衡，传统方案是"调 λ"。K3 的方案是"用分位数硬保证"。

这不是一个"更好的技巧"——它是从根本上改变了问题的性质。从"如何调参让均衡和质量平衡"变成了"如何用统计方法保证均衡"。

月之暗面做了一件很聪明的事：他们没有试图"优化"辅助损失，而是直接绕过了它。

而我，作为一个在 FPGA 上试图实现 MoE 路由的人，想说：Quantile Balancing 让我的工作简单了一个数量级。
