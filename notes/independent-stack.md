## 一、项目定位

> 一句话：**用标准逻辑硅把万亿 MoE 模型变成一台便宜的消费级设备。**

### 目标模型：Kimi K3 官方架构

K3 是月之暗面（Moonshot AI）于 2026 年 7 月发布的旗舰开源模型，2.8T 总参数，104B 激活参数。核心技术：

- **KDA（Kimi Delta Attention）**：混合线性注意力，93 层中 69 层用 KDA、24 层用 Gated MLA（3:1 比例）。KDA 维持固定大小循环状态，支持 1M token 上下文
- **AttnRes（Attention Residuals）**：93 层分 8 个 block，block 间用注意力机制选择性检索前序层表征
- **Stable LatentMoE**：896 专家，top-16 激活，Quantile Balancing 路由均衡，SiTU-GLU 激活函数
- **QAT 量化**：从 SFT 阶段起量化感知训练，MXFP4 权重 + MXFP8 激活，落盘密度 2.12 bit/weight

**本项目关注的推理带宽问题**：trunk（KDA 门控投影 + Gated MLA Q/K/V/O + 共享专家 + router + dense + embed + vision）每 token 每层必经，无法稀疏化。实测 108.8GB/token（未量化 trunk），MXFP4 量化后降至 36GB。详见 `k3-verdict.md`。

三条路线并行：

| 路线 | 核心创新 | 目标市场 |
|---|---|---|
| A. 片上固化推理盒 | 权重烧入片上 ROM，上电即推理 | 嵌入式/边缘/单模型 |
| B. NVMe 流式加速卡 | 预测预取 + 便宜硬盘当容量 | 有主机的工作站 |
| C. NAS+AI 双模一体机 | 不跑 AI 就是高端 NAS | 个人/小企业 |

三者共用同一颗裸片、同一套策略内核、同一套文档体系。

## 二、GEMV 裸片详细规格

### 2.1 MAC 阵列

```
数量       : 128 颗（预埋派，ADR v0.4 定案）
时钟       : 1.0 GHz
精度模式   :
  bf16     : 每 MAC 每周期 1 op（2B 权重 × 2B 激活）
  int4 SIMD: 每 MAC 每周期 4 ops（2B 打包 = 4×int4 权重）
门控       : 每 MAC 独立 ICG；闲置仅漏电
计算吞吐   :
  bf16     : 128 GOPS
  int4 SIMD: 512 GOPS（等效）
```

### 2.2 存储层次（无 SRAM 架构）

| 层 | 介质 | 内容 | 大小 | 访问者 |
|---|---|---|---|---|
| 寄存器 | 触发器阵列 | 当前激活向量分片 | ~百 B/lane | MAC 直接读 |
| 流式 FIFO | 分布式触发器 | 权重预取缓冲 | 几十 KB | 解码流水线 |
| 片上 ROM | 掩膜/OTP | 权重索引或原始位流 | 按需定制（GB 级可行）| MAC 旁路直读 |
| 外部 NVMe | QLC SSD | 冷模型全量层 | TB 级 | 预取引擎 DMA |

**设计原则：权重是只读数据 → 用 ROM 不用 RAM → 密度 ×10 → 成本 ÷10**

### 2.3 MAC 定标决策记录

| 方案 | MAC 数 | 判定 |
|---|---|---|
| ~~保守派 80-85~~ | 精确配平但无升级空间 | v0.2 推荐 |
| ✅ **预埋派 128** | 面积增量 ≈ die 晶体管 0.2%，MPW 价差 ¥26/颗 | **v0.4 已采纳** |

实验验证：68 vs 85 在脚本中 tok/s 相同——模型盲区已确认；
预埋 128 在当前 8ch 下闲置 33%（门控），未来升级通道时直接解锁。

### 2.4 HBM 结论

三重锁定（PHY 宏 + 版图 + 2.5D 封装），不可后升级。
且 K3 场景为容量受限型，HBM 的带宽密度优势无用武之地。
⇒ **不做 HBM。**

## 三、流式推理架构（核心创新）

### 3.1 原理

MoE 每 token 只激活一小部分专家切片（K3: 25.83 GB/token）。
每层工作集仅 ~280 MB —— 远小于模型总量。
⇒ **不需要装下全部权重，只需要及时流过当前层的切片。**

### 3.2 数据流水线

```
NVMe 全量层（¥0.4/GB，QLC 够用）
    ↓ 后台预取（白皮书热度预测算法，88-96% 命中率）
DDR4/LPDDR 落地缓冲（当前层+下一层切片，~2 GB）
    ↓ 解包器（mxfp4 → bf16，移位+scale 乘法）
128 MAC 阵列
    ↓
输出
```

层间切换时零等待：预取引擎提前一层开始搬运。

### 3.3 带宽验证

| 层间搬运量 | 需要的持续带宽 | NVMe 配置 |
|---|---|---|
| 280 MB/层 × 层切换频率 | ~94 GB/s | 12 盘 Gen5 = 84 GB/s ✓ |
| 加 DDR4 二级缓冲摊平突发 | 有效需求减半 | 6 盘即可 ✓ |

### 3.4 【核心结论】零外挂 DRAM

**流式架构彻底消除了对外部 DRAM 的需求。**

原因：权重不是随机访问的数据——是可预测的顺序流。
每层只流过 ~280 MB 切片，预取引擎提前一层开始搬运，
MAC 消费和 NAND 预取在时间上重叠，互不阻塞。

⇒ 不需要 LPDDR5X、不需要 HBM、不需要任何大容量快速存储。
⇒ BOM 中唯一的存储成本 = NVMe 盘（¥0.4/GB），比 LPDDR5X 便宜 200 倍。
⇒ 这就是为什么这个架构在 AI 存储涨价周期中反而更有优势：
   它对存储价格完全免疫——只需要最便宜的 QLC 大容量盘。

### 3.5 【关键突破】DSP 不是必须——加法器替代乘法器

**传统观点：FPGA 上做 MAC 必须用 DSP 硬核。**

实际上，乘法可以分解为移位+加法：

```
a × b = b 次累加 a（或用 Booth 编码 + Wallace 树加速）
```

不同精度的实现成本差异巨大：

| 模式 | 每"乘法器"占用（DSP） | 占用（纯 LUT） | 128 路总 LUT |
|---|---|---|---|
| bf16 | 1 DSP | ~150 LUT | ~19,200 |
| **mxfp4 (int4×int4)** | 1 DSP | **~4 个 LUT6 查表** | **~500** ✨ |

**mxfp4 是最便宜的：**
- int4 × int4 只有 256 种输入组合，输出 7 bit
- 直接做成查找表 ROM，比 DSP 便宜 ~30 倍

**对 Tang Mega 138K（138K LUT / 192 DSP）的影响：**

| 方案 | MAC 数 | LUT 占用 | K3 吞吐 |
|---|---|---|---|
| 用 DSP（原方案）| 128 | 17% ⚠️ DSP 67% | 0.06 t/s |
| 纯 LUT bf16 | 128 | 30% ✅ DSP 0% | 0.06 t/s |
| 纯 LUT mxfp4-SIMD | 等效 512 路 | 36% ✅ DSP 0% | **0.24 t/s** 🚀 |
| 极限堆叠 | 等效 1024 路 | 65% | 0.5 t/s |

**结论：DSP 从瓶颈变成完全空闲。**
**同样的板卡，吞吐提升 4-8 倍，且不依赖任何 DSP 硬核。**

### 3.6 【资源复用】空闲 DSP 的再利用与收益量化

MAC 改用 LUT 查表后，Tang Mega 138K 上 192 个 DSP 全部空闲。
这些 DSP 不浪费，分配给三个关键子系统：

| 子系统 | DSP 数 | 收益 |
|---|---|---|
| **KV-Cache 量化写回** | 32 | 同样内存下上下文长度翻倍（32K→64K tok）|
| **NAND BCH 纠错** | 16 | 数据可靠性从 ❌ 乱码 → ✅ 硬件级 |
| **激活函数多项式拟合** | 16 | BRAM 省 8%，FIFO 可扩容 32KB |

#### KV-Cache 收益（以 K3 为例）

假设 hidden=4096, layers=64：

| 上下文长度 | fp16 占用 | Q8 占用 | 节省 |
|---|---|---|---|
| 2K tok | 2.15 GB | 1.07 GB | 50% |
| 8K tok | 8.59 GB | 4.29 GB | 50% |
| 32K tok | 34.4 GB | **17.2 GB** | 50% |

⇒ 32GB DDR 板卡：fp16 只能跑 32K，Q8 可以跑到 **64K**。

#### NAND ECC 的必要性

- QLC 原始 BER ≈ 1e-3，不加纠错基本不可用
- 用 DSP 做 BCH(8192,7680) 纠错，吞吐需求 <10 µs/block ✓
- 没有这一项：NAND 读出的数据是坏的，推理结果就是乱码

#### 结论

> 吞吐不变（MAC 数没变），但"能跑"和"能用"的差距：
> - 没有 ECC → NAND 读出数据坏
> - 没有 KV 压缩 → 长上下文 OOM
> - 没有 BRAM 余量 → FIFO 瓶颈
>
> **DSP 复用不是锦上添花——是把原型变成可用产品的必要条件。**

### 3.7 【核心突破】资源复用 → 吞吐倍增完整推演

前三节的结论串起来：

1. MAC 用 LUT 查表替代 DSP → **省下 DSP**
2. DSP 复用做 KV/ECC/激活函数 → **省下 LUT**
3. 省下的 LUT 全部换算成更多 MAC → **吞吐暴涨**

#### 第一步：DSP 复用释放的 LUT

| 被替代的功能 | 原 LUT 占用 | 改用 DSP 后 |
|---|---|---|
| 激活函数 SiTU-GLU | ~2,000 | 0 |
| KV-Cache 量化 | ~800 | 0 |
| NAND BCH ECC | ~3,500 | 0 |
| **合计释放** | **~6,300** | |

#### 第二步：释放的 LUT 换算成 MAC

每条 mxfp4-SIMD 通道成本 ≈ 12 个 LUT（查表+分摊累加器）。

| 方案 | 新增通道 | 总通道数 | 加速比 | K3 吞吐 |
|---|---|---|---|---|
| 原方案（DSP 做 MAC）| — | 128 MAC | 1× | 0.06 t/s |
| LUT 替代 DSP | — | 512 lanes | 4× | 0.24 t/s |
| + 复用释放的 6K LUT | +525 | **1,037** | **8×** | **0.49 t/s** 🚀 |

#### 第三步：极限压榨

把板上所有非固定开销的 LUT 全部换成 mxfp4-SIMD 通道：

| 项目 | 数值 |
|---|---|
| 板上总 LUT (Tang Mega 138K) | 138,000 |
| 非 MAC 固定开销 | ~29,700 |
| 可用于 MAC | 108,300 |
| 最大通道数（÷12）| **9,025 条** |
| 相对原方案加速比 | **17.6×** |
| **理论最大 K3 吞吐** | **≈ 4.2 t/s** 💥 |

#### 对比参照

| 板卡 | 价格 | K3 吞吐 |
|---|---|---|
| **Tang Mega 138K（极限压榨）** | **¥1,080** | **~4.2 t/s** |
| Alveo U50 | ¥35,000 | ~10-20 t/s |

⇒ 性能约为 U50 的 20-40%，价格只有它的 **3%**。
⇒ 性价比反超 7-13 倍。

#### 一句话总结

> **每一块硅片都榨干，没有一粒在偷懒。**
> ¥1,080 的国产 FPGA 从"只能验证架构"变成"有实用价值的推理节点"。

## 十二、带宽恒定下的吞吐榨取策略

> 前提：算力(63 t/s 等效) > 存储带宽可支撑的量(~50 t/s)。
> 此时提升吞吐的思路从"传快点"转为"少传"或"一字多用"。

### 12.1 投机解码（救单聊延迟）

小草稿模型连猜 k 个 token，大模型一次前向同时验证——
权重只读一遍，产出 ~k 个 token。

| 场景 | 现在 | 加投机解码 (k=4, 接受3) |
|---|---|---|
| batch=1 单聊 | 0.14 t/s | ~~~0.42 t/s（×3）~~ 见下修正 |

**【实测修正 · T3】相邻位置专家集重叠率 ρ = 0.279 ± 0.05**（92 层微平均，
真实轨迹 67 对相邻位置）。代入本框架 U(k)=1+(k-1)(1-ρ)：
U(2)=1.72、U(4)=3.16 ⇒ 流量口径加速上限 **k/U ≈ ×1.16~1.26**。
MoE 专家流量稀释把"×3"压到 ~×1.26，且接受率还会再打折。
投机解码对 K3 单聊仍有小赚，但不再是主要杠杆。

草稿模型足够小，可直接跑在板载 RISC-V AE350 上。

### 12.2 热专家缓存（救批量吞吐）

MoE 专家访问呈重尾分布（项目前作预测命中率 88-96%）。
板上 1GB DDR3 常驻最热专家切片，命中读取不占 SerDes。

**【勘误 v3 · 真实拓扑终审】k3-verdict.md 实测参数（92层×896专家×top16，切片17.55MB）代入后：**
热集 = 92×16 切片 ≈ **25.8GB ≫ 1GB**。合成 Zipf s=1.0~2.5 全档实测 LRU 命中 **0.6~2.2%**。
⇒ 单卡热专家缓存路线对 K3 正式关闭；吞吐收益 ×1.02。
翻案唯一路径：≥32 卡专家分片使每卡工作集 <1GB。

**【勘误 v4 · 真实轨迹复跑（T3，2026-08-26）】v3 被真实数据推翻，路线复活：**

数据源：引擎真跑遗留的 `expert_trace.bin`（2026-08-18，1 条 prompt × 68 位置 × 92 层 × top16
= 100,096 条真实请求；分析脚本 `t3_tools/small_cache.py`、`t3_tools/rho_real.py`）。
⚠️ 样本量 n=1 prompt，结论待更大样本复核。

实测：
- 路由高度集中：**90% 请求是重复访问**；仅触及池子 12.14%（10,010 个专家 ≈ 175.65 GB）；
  最热切片 L4/e520 被 68/68 个位置全选 —— "热门的路" 真实存在
- 板级预算下的 LRU 命中率：**1GB=35.3%、2GB=36.2%、8GB=36.2%、128GB=49%**
  （Belady 上限：64GB=61.7%）⇒ SerDes 有效收益 **×1.55**（非 v3 的 ×1.02）
- 但注意机制：90% 复用率主要是"16 选自 ~109"的饱和效应，相邻位置集合重叠仅 ρ≈0.28
  （见 §12.1 修正）——集中是真，强时间局部性未必真

**【框架修正 · 缓存的对象是路由路径，不是热门专家】**

热度分级缓存只是兜底。主策略是**路由驱动预取**：
- router 权重极小（每层 gate [896×7168] bf16 仅 12.85MB），随 trunk 流提前一层读入
- 层 L 的输入一就绪即可算出层 L 的完整路由（batch 内全部位置），
  ⇒ NVMe 预取引擎沿"已知的路径"搬运层 L+1 的切片，命中是确定性的，不依赖统计
- 此时 DDR3 的角色退化为流水线缓冲（容量 ∝ 预取窗口 × 17.55MB），不再是按热度驻留的仓库
- 冷读地板（任何策略都躲不开）：每条新文本必读的不同专家 ≈ 10k × 17.55MB ≈ **2.58 GB/token**（实测）
- 兜底场景（路由尚不可知、或跨文档驻留）：才轮到频率式热路径缓存，价值即上面的 35%@1GB

**【实验复核 · 同日】对上面框架的三项检验（`t3_tools/audit_layout.py`、`replay_sim.py`）：**
1. **"专家块散装"证伪**：审计 96 分片全部头信息，被触及的 10,010 个专家
   全部是单文件内单一连续块（6 张量零缝隙）——checkpoint 布局比预想健康，无需整块化改造
2. **"重排打包"伪需求**：以预取窗口模型模拟三种摆放，当前 checkpoint 编号序
   在深度 256 切片（≈4.5GB 窗口）下全程仅需 **2,085 次**窗口重开（覆盖 10 万次访问）；
   按全局频率重排反而恶化到 72,956 次 —— 训练形成的专家编号天然共现聚集，
   任何人为重排都是破坏
3. **"预知替换"增益集中在极小预算**：Belady−LRU 差 = +23.8pt@0.25GB、+5.1pt@0.5GB、
   **仅 +1.2pt@1GB** —— 路由计划的替换价值随预算增大而消失；
   其不可替代的价值在**调度**（提前知道 miss ⇒ 大批量顺序搬运、隐藏延迟），不在命中率
⇒ 修订结论：数据结构本身没有低成本可摘的果子；收益方向 = 小预算板上的路由计划 +
   沿既有布局的顺序批量预取，而不是重组 1.45 TB。


**【勘误 v2】模拟器实测（tools/hot_expert_cache_sim.py）推翻下表预期：**

K3 形状下热专家全集 ≈ 3.8GB（top-2×64 层×30MB）≫ 板上 1GB，
合成 Zipf 轨迹（s=1.0~2.0）实测 LRU 命中仅 **10~15%**，
吞吐收益仅 ×1.15 —— 远低于下表幻想值。

原表保留作"若命中可达时"的参考上界：

| 命中率 h | 有效吞吐 |
|---|---|
| 15%（实测天花板）| ~58 t/s |
| 50% | ~100 t/s |
| 80% | ~250 t/s |

缓存真正起飞的两个前提：
① 真实负载有强域偏好（需 K3 真实路由轨迹验证，工具已就绪）
② 多卡按专家分片，每卡工作集缩小到 DDR3 可容纳

### 12.3 线上压缩（+15~20%）

- scale 差分：E8M0 相邻块常相同 → 省 ~4%
- E2M1 熵编码：零值/小幅值占比高 → Huffman 再挤 10-15%
  （FPGA 解码只需一张小查找表）

### 12.4 模型侧瘦身（×1.5~2，质量换带宽）

- 收紧路由 top-k（如 8 选 2 → 8 选 1.5）
- 早退层：简单 token 提前输出
- 混合精度：95% 层 int4 + 5% 敏感层 bf16

### 12.5 组合结论

```
延迟线：投机解码   上限 ~×1.26（ρ=0.28 实测，§12.1）—— 大幅低于本节初稿的 ×3
吞吐线：路由驱动预取（主）+ 热路径兜底 ×1.55@1GB（勘误 v4）
两线正交，可叠加。
```

## 十三、独立运行固件架构（RISC-V 控制面）

> 独立盒子 = Pro 板 + M.2 盘 + RISC-V 上的"掏心版" kimi-k3-in-c。
> RISC-V 不做推理，做指挥。

### 13.1 职责划分

```
kimi-k3-in-c 原版（纯 CPU）：
   读 GGUF → 循环每层 → 【C 语言算所有矩阵乘】→ 输出
                          ↑ 在 720 MIPS 上会慢死

移植版（板载骨架）：
   读 NVMe 权重流 → 循环每层 → 【写寄存器触发 MAC 阵列】→ 输出
                                ↑ 数学内核掏空，换成硬件调用
```

### 13.2 分工与开销

| 组件 | 职责 | 开销 |
|---|---|---|
| **RISC-V AE350** (~720 MIPS) | tokenizer、采样、KV 记账、路由 softmax、预取命令、层循环控制 | ~10-50ms/token |
| **MAC 阵列** (1,258 lanes) | 全部大矩阵乘（专家 FFN） | ~7s/token（带宽决定）|
| **DSP 复用单元** | SiTU-GLU、KV 量化 | 流水内隐藏 |

**【实测修正 · T3】"路由 softmax ✅ 微秒级"不成立：**
router 是 [896×7168] GEMV，每 token 每层 6.4M MAC × 92 层 ≈ 1.18 GFLOP/token。
RISC-V 标量 @720MIPS ≈ **1.6 s/token**，超预算 30 倍以上。
⇒ 路由 GEMV 必须也走 MAC 阵列（128 lane ÷ 6.4M MAC ≈ 50µs/层 ≈ 4.6ms/token ✓），
或 int8 SIMD；RISC-V 只做 top-16 选择与记账。

控制面开销占比 <1%。慢的依然是带宽——但全程无主机参与。

### 13.3 内存可行性（RV32 + 共享 1GB DDR3）

```
tokenizer 词表        ~几十 MB        ✓
隐藏状态缓冲          每 token 8KB    ✓
logits 缓冲           ~600KB          ✓
权重                  ❌ 不驻留 —— 本来就是流式的
```

**关键自洽：正因为架构是流式设计（权重从不驻留），
"小内存控制器 + 大模型"的矛盾根本不存在。**

### 13.4 kimi-k3-in-c 改造点清单

| # | 改造项 | 内容 |
|---|---|---|
| K1 | `matmul()` 替换 | → MMIO 写 pcie_dma_engine 命令寄存器 + 轮询完成 |
| K2 | 权重加载替换 | GGUF mmap → 触发 M.2 DMA 预取引擎 |
| K3 | 运行环境 | RT-Thread / FreeRTOS（N25F 无 MMU，Linux 不可用）|
| K4 | RV32 适配 | 指针宽度/对齐/字节序检查 |
| K5 | 采样器保留 | 纯标量逻辑，原样可跑 |
| K6 | 投机解码钩子 | n-gram 草稿表驻留 RISC-V 本地 |

### 13.5 RISC-V 能力边界（诚实版）

| 任务 | 判定 |
|---|---|
| Tokenizer/BPE | ✅ |
| MoE 路由计算 | ✅ 微秒级 |
| 预取调度/热度表 | ✅ 主场 |
| llama.cpp 官方主线 | ❌ 仅支持 RV64 |
| Linux | ❌ 无 MMU |
| 神经网络草稿模型 | ❌ 太慢；用 n-gram 替代 |
| SiTU-GLU 等激活函数 | ❌ 走 DSP 复用单元 |

定位类比：它是服务器的 BMC/EC 芯片——没人用它跑业务，
但拔掉它整台机器就是铁块。

### 14.1 权重机（k3, WSL2, H:\k3）

#### T1 · 解码打包格式 ✅ 已完成（2026-08-26，产出 `notes/k3_pack_format.md`）

- 前置：无（k3_index.json 已在盘上）
- 操作：
  1. 从任一 safetensors 分片抽 1 个 expert 的 w1 weight_packed 张量
     （形状 [3072,1792] U8，逻辑宽度 = 1792×2 = 3584）
  2. 取前 4KB 导出十六进制 + 对应 weight_scale 前 256B
  3. 尝试常见打包假设并校验：
     a. ~~每 U8 装 4 个 2bit 码~~ → 排除（码全非负、分布 29.8/23.0/28.1/19.1%，
        无法解释权重正负对称性）
     b. **每 U8 装 2 个 4bit E2M1** ✅ → 定案，即 OCP MXFP4
     c. 位平面切分（bitplane）布局 → 排除
  4. 用 group=32 的 E8M0 scale 反量化一组 32 权重验证
     （nibble 分布吻合 E2M1 码表统计，解码后 15 值对称、mean≈-0.08）
- **定案**：`value = E2M1[nibble] × 2^(scale-127)`，nibble 低=偶/高=奇，
  scale 每 32 元素 1 个（`K3_MXFP4_GROUP=32`），255=NaN→0。
  每元素 0.5+1/32 = 0.53125 B → expert 17,547,264 B 与裁决一致。
- 产出：`notes/k3_pack_format.md`（位序/字节序/组内排列的最终定义）✅
- 回填：`rtl/12_fpga_proto/rtl/simd_mac_array.v` 的解码查表（E2M1 表 16 项）、

> **结构拆解里程碑（2026-08-27）：MoE「先路由后搬运」在 K3 上成立的实锤。**
> 来源：sglang `python/srt/models/kimi_linear.py` + `kimi_k3.py` 源码。
> **关键事实 —— router 与 experts 吃同一个 hidden_states：**
> ```
> router_logits, _ = self.gate(hidden_states)
> final_hidden_states = self.experts(hidden_states, topk_output)
> ```
> - `gate` = `ReplicatedLinear(7168 → 896)`，权重仅 7168×896 ≈ 6.4M 参数，
>   **可完全常驻内存（几十 MB）**
> - `experts` 也吃同一个入层 `hidden_states`
> - **结论：可以「先算 router（极小常驻权重）→ 拿 top16 → 再精准搬运那 16 个专家」，
>   把「整层读 896 专家」变成「只读 top16」**
> - 绕不开的部分：本层 router 依赖本层注意力输出（KDA/MLA 权重须先算）；
>   要躲开它只能退到「用上一层 h 预测本层路由」，命中率非 100%
> - 待办 T8：据此写 `expert_extractor.py` 实测「先路由后搬运」能把搬运量压到多少
