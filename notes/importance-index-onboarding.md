# 重要性索引（列显著度）权重机实验手册

> 版本 0.3 · 2026-09-17 · **状态：已裁决 —— 判死（A2/A3 关闭）**
>
> 目标验证 **lossy 列索引读** 在 K3 上能否以可接受质量代价换取 40-50% 专家字节。
> 实测结论（见 §0/§2）：**列重要性在两信号面上均判死**——权重 L1 范数 top50%=50.6%（≈均匀），
> 激活加权后仅 52.7%（激活跨维 cv=6.7%，本身均匀）。K3 的 MXFP4 量化 + 稠密激活
> 消除了 MoE-Pruner 前提（BF16 浮点权重的真实列差异），列索引读无便宜可占。
> 依据先例：MoE-Pruner（arXiv:2410.12013，50% 稀疏度保持 99% 性能）；
> 信号面：K3 为 QAT+MXFP4 的 Stable LatentMoE，router 信号强，专家内部列贡献极不均匀。

## 0. 一句话假设

对每个专家矩阵（w1/w2/w3）的**列**用校准集算"重要性分"，按分排序得到**静态列索引**；
运行时只读索引中 top-K 列的字节，其余列跳过（零贡献）。若 top-K 列承载 ~99% 激活能量
⇒ "列索引读 + 质量不降"成立，字节账改写为 `R ≈ K% × (|w1|+|w3|+|w2|)`。

重要的是：这是**静态稀疏**（每 token 同一组列），不是按 token 动态看列存活（后者已被
ρ0/ρ1 判死）。静态稀疏有 MoE-Pruner / EEP 的公开实证，动态没有。

## 1. 重要性分的定义（MoE-Pruner 口径，可裁剪）

对专家权重 `W ∈ R^{out×in}`，其列 j 的重要性：

```
score[j] = Σ_i W[i,j] × E|x_j|         （输出神经元 i × 输入激活期望幅值）
```

- `E|x_j|` 从校准集统计：128 个 prompt 前若干 token 在该专家输入处的激活幅值。
- 简化版（免激活）：`score[j] = Σ_i |W[i,j]|`（纯权重范数），作对照基线。
- 演进版（拟深）：再乘上该专家被路由选中时 router 权的期望 → 即 MoE-Pruner 完整式。

## 2. 要裁决的两个临界量

| 问 | 判 | 手段 |
|---|---|---|
| ① 列重要性是否集中 | top-50% 列承载 Σscore 的占比 > 95%（最好 >99%） | 校准集算 score 排序 |
| ② 跳过低分列后质量降多少 | 比全读模型困惑度/选词一致率 | A/B 推理对比 |

### 2.1 裁决结果（2026-09-17 真机实测）

**① 判死**。两口径、多层多专家一致（样本 L1/2/5/10/50/92 × E0/3/10/100/500 × w1/w2/w3）：

| 口径 | top-30% | top-50% | top-70% | 判据(>95%) |
|---|---|---|---|---|
| base（`Σ_i\|W[i,j]\|` 免激活） | 0.305 | **0.506** | 0.705 | ✗ |
| act（`Σ_i\|W[i,j]\|·E\|x_j\|` 激活加权） | 0.324 | **0.527** | 0.723 | ✗ |

- w1/w3 列 L1 范数 std/mean ≈ 1.5%（列间几乎无差异）；w2 略散但 top50% 也仅 0.51-0.57。
- 激活分布本身高度均匀：`E\|z\|` 跨维 cv=6.7%，`E\|act\|` cv=9.8% —— 无"少数列承载主要能量"结构。
- **根因**：MXFP4 量化（E2M1 仅 16 码值）抹平列权重范数差异；MoE-Pruner 前提（BF16 权重的真实列差异）在 K3 不成立。
- ② 未做（①塌 → 按 §2 判定逻辑命题关闭；"lossy 列读"终止）。

若 ①真 ②微 → 命题成立，读入"列索引引擎"设计；
若 ②塌 → 收敛到 ~5%（ρ路线）结论，命题关闭。

## 3. 实验步骤（权重机，一个下午）

### 3.1 准备（30 min）
```bash
# 复现可跑通的最小推理（参考 rho1-probe-onboarding.md 前置）
./main -m <model> -n 16 -p "hello"
```
校准集：128 句通用文本（C4/论文语料均可），每句前 32 token 采样。

### 3.2 score 计算（独立脚本，不碰引擎）
```python
# 读 safetensors 专家张量（w1/w2/w3），对每列：
#   score[j] = torch.abs(W[:, j]) @ xm          # xm = 校准激活幅值列向量
# 或免激活基线:  score[j] = torch.abs(W[:, j]).sum()
topk = int(0.5 * W.shape[1])                     # 试 0.3/0.5/0.7
energy_ratio = score_sorted[:topk].sum() / score.sum()
print(f"{layer}.{expert}.{mat} top{topk}% 能量占比 = {energy_ratio:.4f}")
```
采样：每层挑 2-4 个专家（hot/mid/cold 各若干），无需全 896。

### 3.3 质量 A/B（引擎探针，扩展 rho1 探针框架）
- 全读跑 baseline：记录每 token 的 top-K logits 序列 L_full。
- 列索引跑：读前只把低分列权重清零（等价跳过读），得 L_idx。
- 判据：
  - `top-1 一致率` ≥ 0.95
  - `top-K 集合交并比` ≥ 0.9
  - `正解 logit 差 |Δ| ` 与随机扰动对比显著性
- 逐步加裁剪比 0 → 0.3 → 0.5 → 0.7，画质量-字节曲线。

### 3.4 回传（几 KB）
`layer, expert, mat, keep%, energy_ratio%, top1_match%, topK_jacc%` 表 → 手机侧汇总
成质量-字节 Pareto 曲线 + 与 MoE-Pruner 论据对照。

## 4. 已知风险与护栏

1. **静态索引 ≠ 动态掩码**：静态列集合固定，可能对个别 token 恰好切掉关键列。
   → 看曲线：若 0.5 裁剪即塌，缩小到 0.3 并承认上限低。
2. **质量一致性**：K3 QAT 模型激活分布与 MoE-Pruner 的 Mixtral BF16 不同，不可照搬阈值，**必须本地实测**。
3. **字节账口径**：列断读需 in-major 布局（转置，解码前一次性重排）——列读才连续；
   否则列步进读会在 DRAM 上爆炸（r = 行长大步跨）。
4. **不重训**：本实验只验证"免训损失"，若需要精调（MoE-Pruner 用 KD 恢复）则超纲，另议。

## 7. 验收标准

- 双层证据齐备：① score 能量集中（top-50% ≥ 95%）② A/B 质量（top-1 一致 ≥ 0.95）。
- 至少 5 层 × 3 类专家（hot/mid/cold）抽样，非单点。
- 记录：校准集构成、裁剪比、一致率、logit 差分布、样本量。
