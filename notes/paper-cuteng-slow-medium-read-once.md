# 受内存约束的 MoE 推理中"慢介质读一次"下界及其真机验证

## 摘要

混合专家（Mixture-of-Experts，MoE）模型凭借稀疏激活降低单 token 计算量，但推理瓶颈在有内存约束的设备（如仅有系统内存、需从机械盘流式读权重的主机）上往往不是计算，而是权重的搬运。本文以 2.8T 参数开源模型 Kimi K3 的真机推理为对象，报告一个普遍但常被忽略的结构性事实：当被激活的专家权重无法常驻最快介质层时，每个 token 都必须从慢介质全量重读一遍。本文给出并证明了"慢介质读一次"定理——若数据 d 的复用发生在 d 能到达的最快介质层 M_k 上，则对任意更慢介质层 M_i（i < k），读取次数恒有 R_i ≥ 1，且该下界同时可达：存在调度使每个慢层恰好读一次，其余 R−1 次复用全部落在 M_k 上；该调度同时是慢访问代价最小的调度。真机台账（k3 x86，2026-08 冷启动）显示：每 token 专家段从慢盘重读 25.83GB，耗时 303.58s，占端到端 94%。对照实验进一步量化了"复用未落进最快层"时的代价：将专家全量放入 L2 介质驻留缓存，专家段耗时降至 191.6s（约 −37%）。本文的定理是逻辑命题，可无条件迁移；真机数字只对本实验成立，供识别同类带宽墙使用。

**关键词**：混合专家模型；MoE 推理；存储层次；带宽墙；缓存调度；Roofline 模型

## 1 引言

### 1.1 背景

大语言模型的规模扩张已进入万亿参数量级，MoE 因其稀疏激活特性成为主流扩展范式[1-6]。以 Kimi K3 为例[1]：共 93 层、总参数约 2.8T，采用 896 路由专家的 Stable LatentMoE，每 token 仅激活 16 个专家，激活参数约 104B。单看稀疏红利，每个 token 只需读取全部专家权重的约 1.8%，这是 MoE 推理"省带宽"承诺的由来。

但该承诺有一个常被忽略的隐藏前提：**被激活的权重必须常驻在或能快速到达计算侧**。在 GPU 服务器上，trunk 与热专家常驻显存，该前提成立；而在仅配有系统内存、硬盘，甚至需要从机械盘流式读权重的主机/边缘设备上，前提不成立——此时"稀疏"只减少了必须搬动的字节总量，却没有改变"这些字节要从哪一层介质搬"这一结构问题。

### 1.2 现象与动机

本文工作源于一次真机碰壁。在一台 k3 x86 主机上以冷启动方式跑 Kimi K3 推理，运行时字节流台账显示：每 token 专家段从慢盘读取 **25.83GB**，以约 85MB/s 计耗时 **303.58s**，占端到端 324.36s 的 **94%**[13]。也就是说，模型虽然每 token 只"激活"约 25.8GB 专家权重，引擎却让它们每 token 从慢介质全量重读一遍——慢介质读的绝不是一次，而是每 token 一次。

这个现象促使本文回答两个问题：

1. 一个数据项只在慢层各读一次、其余复用全部发生在最快层，这是否总是可行？其理论下界是什么？
2. 该下界在真机上是否可被观测、可被回查？

### 1.3 本文贡献

1. 形式化"慢介质读一次"定理：给出读取下界 R_i ≥ 1、其可达性构造与"慢访问代价最小"的最优性证明（第 3 章）；
2. 提供可逐字节回查的真机字节流台账及其与定理的对应关系（第 4 章）；
3. 给出可迁移的工程判据：识别受内存约束 MoE 推理瓶颈的第一步是确认"复用是否落在数据能到达的最快介质层"（第 5 章）。

## 2 相关工作

### 2.1 MoE 架构与稀疏化

MoE 的思想可追溯到 Shazeer 等的稀疏门控网络[2]，GShard[3] 提出 top-K 路由与分片；Switch Transformer[4] 进一步把激活专家降至单个；Mixtral of Experts[5] 证明开源 8×7B 级 MoE 的实用性；DeepSeekMoE[6] 提出细粒度专家切分与共享专家隔离，Kimi K3[1] 在其基础上的 Stable LatentMoE 将路由专家扩展至 896、每 token 激活 16。所有上述工作的稀疏红利都以"激活权重可被快速访问"为前提；本文不考虑模型侧稀疏性的进一步优化，而聚焦"既定的激活集合如何通过存储层次搬运"这一问题。

### 2.2 存储层次与带宽建模

Roofline 模型[7]给出了判断瓶颈位于算力还是带宽的经典框架：在带宽受限区（decode 阶段约 1 FLOP/byte），复用是唯一杠杆——但这只回答了"复用值得做"，未回答"复用应落在哪一层介质"。Eyeriss[8] 在加速器层面给出了"慢层读一次、最快层复用"的实证存在性：AlexNet 上 DRAM 访问约 0.0029 次/MAC，即每个权重从 DRAM 读一次、片上复用数百次。本文的定理与该实证方向一致，但把结论推广为存储层次上任一数据项的通用下界。

### 2.3 LLM 推理的缓存、预取与调度

vLLM/PagedAttention[9] 用分页缓存消除 KV 缓存碎片，可视为"让复用尽量落在快层"在 KV 尺度上的实现。FlightLLM[10] 针对 FPGA 部署提出 always-on-chip decode，把 decode 权重复用约束在片上。CXL-SpecKV[11] 用 CXL 内存池 + 预测预取 + 冷热分层缓解 KV 缓存带宽墙，其活集超容量时的预取/驱逐正是本文定理"不在场情形"的标准处置。FastKV[12] 通过两阶段 prefill 与逐层 KV 保留率解耦压缩与算力，同样以"只保留必要数据于快层"为原则。上述工作均隐含"慢层只应被读一次、复用应在快层"这一工程直觉，但未见将其显式化为可回查的下界定理；本文补上这一形式化层。

## 3 慢介质读一次：定理与证明

### 3.1 定义

设存储层次由 N 层介质构成，按单次字节访问代价单调上升排序：M₁（最慢，代价最高）→ M₂ → … → M_N（最快，代价最低）。对数据项 d，被访问（复用）总次数 R ≥ 1；记 R_i = d 从介质 M_i 被读取的次数（i = 1 … k，M₁ 最慢）。

**参与路径**：定理只对 d 实际穿越的介质下结论。若某介质物理上更快、但 d 从不进入它（如板上的 SDRAM 数据不进、或仅局部进入），它不在 d 的参与路径上，不进求和范围。

### 3.2 定理

**定理 1（慢介质读一次）**：设数据项 d 被复用 R ≥ 1 次，且复用的实际发生位置是 d 能到达的最快介质 M_k。则对任意 i < k，恒有

    R_i ≥ 1

且该下界**同时可达**：存在一个读取调度，使 R_i = 1 对所有 i < k 同时成立，且其余 R−1 次全部落在 M_k 上。

**推论**：若复用发生在最快层 M_k，则各慢层读取次数总和的最小值 = 各慢层恰读一次；使该最小值达成的调度，同时是慢访问代价最小的调度。

### 3.3 证明

证明分三步。

**第 1 步（信息守恒下界，无条件）**：d 若从未被从 M_i（i < k）读入，则 d 不可能到达 M_{i+1} 及以上层次，更不可能到达 M_k 被复用——数据只能逐层向上搬移，不存在跳过 M_i 直达更高层的通路。因此每层 M_i（i < k）至少被读一次：R_i ≥ 1。此下界不依赖任何容量假设、不依赖任何具体工作量。∎

**第 2 步（代价单调）**：介质按访问代价单调排序，层号越大代价越低。任何"多余的"慢读（即越过下界 1 的额外次数）都可被替换为一次更快介质的读取而不增加总代价，因为慢读严格贵于快读。故达到下界（每慢层恰好一次）的调度使慢访问总代价最小。∎

**第 3 步（可达性）**：复用发生在 M_k 上意味着 d 在 M_k 有活集位置，R−1 次复用可全部在 M_k 内完成。d 到达 M_k 的路径即逐层各读一次（M₁ 一次 → M₂ 一次 → … → M_k 一次），该调度合法且同时满足所有下界。∎

### 3.4 边界讨论

- **容量**：容量不构成定理的条件。若活集超出 M_k 容量，复用无法全部发生在 M_k，数据要么在更窄层内做局部复用（liveness 驱逐），要么被重读——这是定理的"不在场"情形（前提不成立），定理不被违反，只不适用。
- **不参与介质**：物理更快、但数据从不进入的介质不在求和范围，其速度与结论无关。
- **判据唯一性**：定理是否在场只取决于一条判据——复用事实是否存在，即 d 是否真的在它能到达的最快介质 M_k 上被复用。

## 4 真机验证

### 4.1 实验设置

实验对象：Kimi K3 开源权重[1]。作者对权重文件做 safetensors 全量字节扫描，专家语义为 MXFP4 格点、实际落盘约 2.12 bit/weight（含 scale）[13]，单专家 17.55MB。引擎：k3 x86 真机推理实现（kimi-k3-in-c），2026-08 冷启动。存储层次：慢盘 sde（源盘，近满、D-state 风险介质、实测约 84–85MB/s）→ L2 介质 sdd7 → 系统内存 → 计算。运行时统计内建字节级 READ 计数。

所有数字来自 `notes/byteflow-matrix.md` 台账，标注行号可逐字节回查[13]。

### 4.2 观测一：专家段每 token 全量重读

每 token 专家理论载入 = 92 层（MoE）× 16 专家/层 × 17.55MB/专家 ≈ **25.83GB/token**。引擎实测专家段 READ = **25.83GB/token**，与理论载入逐字节吻合[13:246,325,327]。即引擎在 CACHE HIT 100% 的报告下，仍每 token 从慢盘 sde 全量重读专家权重——"命中"在白板计数上成立，但字节流层面每次都是冷读，与定理"复用应落在更快介质层"的前提相悖。

### 4.3 观测二：关键数字及速率的两处字节

| 指标 | 数值 | 台账出处[13] |
|---|---|---|
| 每 token 专家理论载入 | 92×16×17.55MB = 25.83GB | :246 |
| 实测专家段 READ/token | 25.83GB | :325, :327 |
| 专家段耗时 | 303.58 s/token | :327 |
| 端到端耗时 | 324.36 s/token | :325（total） |
| 端到端占比 | 303.58 / 324.36 = 94% | :327 |
| 等效速率（精确商） | 25.83GB / 303.58s = 85MB/s | :327 |
| 介质刻画速率（碰壁整值） | 84MB/s（D-state 根因刻画） | :224 |

速率一处，两处字节都在可回查文件里且**两值各有出身**：84MB/s 是介质性能刻画的整值（慢盘近满、巨型 O_DIRECT pread 的实测形态），85MB/s 是 25.83GB 与 303.58s 的精确商。本文据实并列、不引入第三个"速率"声称。

### 4.4 观测三：让复用靠近快层的对照实验

定理预测：慢介质读一次的前提是复用必须落在更快层。2026-08-29 真机复查找将其工程化验证：把专家全量 distinct 集（约 10,010 个专家 × 17.5MB ≈ 176GB）驻留到 L2 介质 sdd7（实测约 419MB/s，较慢盘快约 5 倍），专家段耗时从 303s 降至 **191.6s（约 −37%）**，端到端从 326.5s 降至 262.8s[13:290,298,357]。

该实验的读数有两个方向性含义：

1. **方向与定理一致**：把慢盘上的全量重读移到更快介质，显著压缩了"每 token 全量重读"的代价；收益尚未达到定理给出的"约 −90%"上界（trace 推演 25.8GB→2.58GB/token），原因是复用仍未真正落进内存层——每一 token 仍需从 L2 介质 pread 25.83GB（1786MB/s 下亦需约 14.5s），且命中白板不能免除字节层搬迁[13:368]。
2. **判据得到印证**：瓶颈不由"算法能否免读"决定，而由"复用发生在哪一层"决定；这正是第 5 章可迁移判据的经验基础。

### 4.5 证据层级与限制

第 3 章定理属逻辑层，其真值不依赖本节任何数字；本节台账属真机层，账实一致、可回查，但只对本实验（该模型、该介质、该负载、该冷启动时序）成立：25.83GB/token 与 94% 不构成对别的工作量或别的介质的断言。台账中亦如实记录 FAIL/挂死的条目（如 D-state 永久挂起），未选择性剔除负样本[13]。

## 5 讨论与应用

### 5.1 工程判据：先问"复用落在哪一层"

对受内存约束的 MoE 推理，本文给出可迁移的判别次序：

1. **算法能否免读**：该数据项是否必须被读取（如专家是否真是路由集合的必要输入）；
2. **能否缓存复用**：读取结果能否在快层驻留并被复用（即定理的在场条件——复用发生在最快层）；
3. **落盘位置**：若必须慢读，权重是否至少置于参与路径中较快的介质；
4. **落盘前压缩**：能否先压缩再落盘，减少届时必须搬动的字节。

真机例证中，k3 引擎在第 2 条失守（命中不落内存、每次仍全量搬迁），因此纵使第 1、4 条已成立，带宽墙仍占端到端 94%。

### 5.2 与调度/预取工作的衔接

本文定理不提出新调度器，而是为既有调度工作提供一个可回查的判据与上界。第 2.3 节所列工作[9-12]都隐式依赖"慢层读一次"直觉；当方案声称"缓存命中"或"预取成功"时，应回到本定理的判据核实字节层是否真的避免了慢层重读——命中率指标与非易失介质上的字节搬迁指标可能互相遮蔽（见 4.4 观测三）。

### 5.3 局限性

- 存储模型假设单向逐层搬移，未覆盖旁路、直接 DMA 到计算侧等非逐层实现路径——"逐层"只是可达性的一个充分构造，而非必要路径。
- 真机数字来自单一模型、单次冷启动实测，不声明跨工作量恒真；可达性由定理第 3 步构造保证，与读者是否阅读本文无关。

## 6 结论

本文把受内存约束 MoE 推理中的"慢介质每 token 全量重读"这一步难墙形式化为可回查的定理：若复用发生在数据能到达的最快介质层，则每个更慢介质恰好被读一次即可同时满足所有复用，且该下界可达、慢访问代价最小。k3 x86 真机台账忠实记录了一个下界未被满足的反例（25.83GB/token 全量重读、占端到端 94%），及一个部分收敛的方向性对照（专家迁入 L2 介质后 −37%）。对同类工作，本文建议把"复用发生在哪一层介质"作为排查带宽墙的第一判据。
