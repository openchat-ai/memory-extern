# MoE 权重搬移速算（真实数字版）

> 真实口径来源：`notes/memory-compute-notes.md:144-189`（上游 kimi-k3 gates.txt 实测）
> 本文件把"每 token 搬多少 / 可用带宽 → token/s"的三步速算，用真实数字填死。

## 1. 真实输入数字（勿再凭 125G 约数）

| 项 | 真实值 | 来源 |
|---|---|---|
| 每 token **专家段** | **25.83 GB** | 92 层 × 16 top-k × 17,547,264 B/专家 |
| 每 token **trunk 段** | **113.49 GB** | 56.7B 参 bf16，always-active，**不可缓存** |
| 每 token **合计** | **≙ 139.3 GB**（不是 125G） | 专家仅占 18.5% |
| trunk 占 I/O | **81%** | 实测 |

**两个不可忽视的硬事实：**
1. **trunk 每 token 100% 必读、无稀疏性、缓存跳不掉** → 任何专家缓存都只在那 18.5% 里打转。
2. 完整账本（trunk + 专家，专家按 88.3% 命中）：1 tok/s→116.5GB/s；10→1.17TB/s；30→3.5TB/s。

## 2. 三步速算公式

$$
\text{token/s} = \frac{\text{可用带宽 (GB/s 或 GBit/s)}}{\text{每 token 搬移 (GB 或 GBit)}}
$$

注意单位配对：带宽若给 GB/s，除每-token-GB；给 Gbps，则每 token 先 ×8 变 bit 再除。

## 3. 逐链路的真实 token/s（按完整账本 139.3GB/token）

| 链路 | 有效带宽 | token/s = 带宽÷139.3GB |
|---|---|---|
| Q1 2 lane 光口/SerDes (2×8.25G 净荷≈16.5Gbps) | ≈ **2.06 GB/s** | **≈0.015**（~67s/token） |
| NVMe 单盘 (Gen3 x4≈3.9GB/s) | ≈ **3.9 GB/s** | **≈0.028** |
| 引擎 200MHz (12.8GB/s) | ≈ **12.8 GB/s** | **≈0.092**（~11s/token） |
| DDR5 双通道 | ~102 GB/s | **0.73** |
| 服务器 8 通道 DDR5 | ~410 GB/s | **2.9** |
| HBM2e 单栈 | ~460 GB/s | **3.3** |
| 10 tok/s 所需 | 1.17 TB/s | 达标需 ≥1.17TB/s |

> 对照仓库实测：上游"228GB RAM + NVMe 流式 trunk"＝ **0.015 tok/s 量级**，与 Q1 2 lane 我算的 0.015 惊人一致 → **你的 Q1 2 lane ≈ 上游 NVMe 流式档，约 1 token/分钟**。

## 4. 结论与正确认知

- 按**真实 139.3GB/token**，不是 125G：你的 **Q1 2 lane ≈ 0.015 tok/s**（约 1 token/分钟），连引擎全力 200MHz(12.8GB/s) 也只有 **0.092 tok/s**。
- **瓶颈在 trunk（113.5GB/token, 81% I/O, 不可缓存）**，任何专家缓存/流式/多盘并行都动不了它。
- 要实用 token/s（≥1），需要：**trunk 近存（near-memory）** 或 **KDA 压缩结构化复用**（仓库已在做），带宽要到 **≥1.17TB/s**（HBM/服务器多通道级）。
- 单靠"更快硬盘/更多 lane"在 compile 量级上救不了 trunk——这是**架构级**结论，不是换块盘能解决的。

## 5. 速记

`Q1 2 lane ≈ 0.015 tok/s`、`引擎 200MHz ≈ 0.09`、`DDR5 双通 ≈ 0.7`、`8 通 DDR5 ≈ 3`、`HBM ≈ 3.3`、`10 tok/s 需 1.17TB/s`。

## 6. 最终定案与"SSD 流式"的本质区别（决策锚，勿再绕回）

**最终定案 = `notes/final-architecture.md`（"定版。不再修改"）**：
- 权重存储 = **片内合封 NAND die ×13（QLC 1Tb）直连无协议** + **片上 DDR4 2GB 双缓冲**
- K3 ≈ **40 tok/s**（瓶颈 = NAND 读出带宽）
- 外部内存 = 无，全部片上

**对比"外部 SSD/NVMe 流式"（仓库 B.13-B.18 实测 130~1663 s/token）：**

| | 外部 SSD 流式（实测/否掉的） | 合封 NAND 定案 |
|---|---|---|
| 存储位置 | 外部盘，走 PCIe 协议 | 片内 die，裸直连无协议 |
| 接口/带宽 | 单盘墙 ~1GB/s（实测） | die 并读出（13 die） |
| 缓冲 | 内存装不下 139GB | 片上 DDR4 2GB 双缓冲（近存） |
| 结果 | s/token 级 | ~40 tok/s |

**定性（重要，勿误读为"技术死路"）**：
- 外部 SSD 流式**不是技术上做不出，是成本/收益被否**——每次 token 传输 139GB 都要持续付"带宽租 + 协议 + 内存"的代价；
- 合封 NAND = **买断式**：13 die 并读，传输几乎免费，贵在建卡一次；
- 所以拒绝 SSD 流式 = **成本否决，非技术否决**。定案选 NAND 因它在"40 tok/s + 成本可控"这点更优，不是唯一能跑。
