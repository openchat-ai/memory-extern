# MAC 数 vs 内存带宽分析

> ⚠️ 本文档基于旧口径（34 MAC / 68 GB/s），数据已过时。新口径：**68 MAC / 171 GB/s / 128 GB / 30W**（8ch LPDDR5X）。以 `pim/calc_performance.py` 为准。

## 核心矛盾

```
115 MACs × 4 bytes = 460 GB/s（需要）
LPDDR5X 8ch = 137 GB/s（实际）
差距: 3.4×
```

**70% 的 MAC 会空转。**

## 各方案对比

### A. 单芯片34 MAC（刚好喂饱）
- 面积: 4.6 mm²
- 功耗: 13.5W
- 带宽: 137 GB/s
- 7B tok/s: 9.8
- 30B tok/s: 2.2（不可用）
- 成本: ¥153/颗

### B. 单芯片115 MAC + 27ch LPDDR5X
- 需要: 27 个16-bit 通道
- 实际: LPDDR5X 最多16ch/控制器
- **物理上不可行**

### C. 单芯片115 MAC + HBM3
- 带宽: 819 GB/s
- 支持: 204 MACs
- **但**: HBM 需要2.5D 封装 + TSV，成本 +¥500-1000万
- **单芯片不可行**

### D. 多芯片并行（推荐）

#### 2 颗互连
- 每颗: 34 MAC + 137 GB/s
- 总计: 68 MAC + 274 GB/s
- 7B tok/s: 19.5
- 30B tok/s: 4.4
- 面积: 2 × 4.6 = 9.2 mm²
- 功耗: 2 × 13.5 = 27W

#### 4 颗互连
- 每颗: 34 MAC + 137 GB/s
- 总计: 136 MAC + 548 GB/s
- 7B tok/s: 38.8（对标 RTX 3090）
- 30B tok/s: 8.8
- 面积: 4 × 4.6 = 18.4 mm²
- 功耗: 4 × 13.5 = 54W

## 对比 RTX 3090

| | RTX 3090 | 我们（4 颗） |
|---|---------|------------|
| 带宽 | 936 GB/s | 548 GB/s |
| 7B tok/s | 30-40 | 38.8 |
| 功耗 | 350W | 54W |
| 能效 | 0.1 tok/s/W | 0.7 tok/s/W |
| 成本 | ¥10,000+ | ¥612 |

## 结论

**单芯片做不过 GPU。多芯片并行是唯一出路。**

### 最终规格（单芯片）

| 参数 | 值 |
|------|-----|
| MAC 数 | 34 |
| SRAM | 8MB |
| 内存 | LPDDR5X 16GB (4ch) |
| 带宽 | 68 GB/s |
| 面积 | ~4 mm² |
| 功耗 | ~10W |
| 互连 | SerDes 4 lanes |
| 价格 | ¥150-300 |

### 多芯片扩展

| 配置 | 总带宽 | 7B tok/s | 30B tok/s |
|------|--------|----------|-----------|
| 1 颗 | 68 GB/s | 4.9 | 1.1 |
| 2 颗 | 137 GB/s | 9.8 | 2.2 |
| 4 颗 | 274 GB/s | 19.5 | 4.4 |
| 8 颗 | 548 GB/s | 38.8 | 8.8 |

## 关键限制

**LPDDR5X 带宽决定了：**
- 7B: 8 颗 = 38.8 tok/s（可用）
- 30B: 8 颗 = 8.8 tok/s（勉强）
- 70B+: 需要更多芯片或更快内存
- K3 (113GB): 8 颗 = 4.9 tok/s（太慢）

**现实：LPDDR5X 做不过 GPU。**
**卖点：能效高 7 倍，成本低16 倍，体积小。**
