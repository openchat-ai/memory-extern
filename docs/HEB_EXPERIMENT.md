## 0. 一句话

两条线共同目标：**产出一个能端到端生成正确 Python 代码的 QxT 模型**。

| 线 | 方法 | 训练代价 | 预期 |
|---|---|---|---|
| **A 老方法** | 蒸馏训练（`qxn_distill_student.py`） | 分钟~小时级 | 语言能力 |
| **B 赫布构造 (论文法)** | 零训练外积构造（`qxt_hebbuild.py`） | 秒级 | 事实检索 |

**A 和 B 不是替代关系，是互补**：A 产语言能力，B 产可精确写入/替换的事实存储。
§5 给出"合体"方案。

**关键教训（写进设计的约束）**：

- 论文外积只作用于 FFN；若事实藏在 attention，外积够不着（侧支 #10）
- 已收敛模型里"抬 logit"≠"改 top-1"（侧支 #9）→ 判据必须用 top-1

## 2. 共同判据：什么叫「可用」

**非代理判据（AGENTS §10.1）**：`可用 = 端到端生成，且能被独立解析器验证`。

### 2.1 三层判据（缺一不可）

| 层 | 判据 | 工具 | 通过线 |
|---|---|---|---|
| L1 语法 | 生成文本能被 `ast.parse` 接受 | Python `ast` | ≥ 60% |
| L2 语义 | held-out 位置的 top-1 命中 | 教师留出段 | > 基线 |
| L3 端到端 | 给定 prompt，生成可读代码 | `q1t_stream.py` 或等价 | 人眼 + L1 |

### 2.2 强制对照（§11.8 区分力）

每个"有效"结论必须带对照：

```
外积有效   → 对照: 随机 B 应 ≈ 0
蒸馏有效   → 对照: 随机初始化模型 (0 步) 应 ≈ 随机
训练收敛   → 对照: held-out 组合, 不是训练过的
```

### 2.3 噪声底（§11.4）

```
n=20 样本时, 95% 最小可分辨差异 M = 2.8*sqrt(p(1-p)/20) ≈ 0.31
→ 命中率提升 < 30pp 的结论不写"提升", 写"未观测到差异"
```

## 3. 线 A：蒸馏训练（产语言能力）

### 3.1 现状问题

上一轮只训 300 步，且**没有端到端验证**。日志停在 `KL 8.19`。

### 3.2 实验 A1：把蒸馏学生训到可用

**命令**：
```bash
# 全词表 (V=151936) —— 与部署口径一致, 但慢
taskset -c 7 python3 tools/qxn_distill_student.py \
  --teacher teacher_06b_k64.npz --mode fp32 \
  --steps 4000 --n_layer 4 --n_embd 256 --n_ff 512 \
  --vocab 151936 --batch 4 --seq_len 64 --alpha 0.5 --clip 1.0 \
  --save ckpt_distill_fp32.npz

# 压缩词表 —— 快 5x, 仅用于研究结论
  ... --compress_vocab --save ckpt_distill_cv_fp32.npz
```

**代价核算（§11.5，动手前必须算）**：

**实测速率（2026-10-19，`taskset -c 7`）**：
```
V=18540 (压缩词表), d=256, L=4, ffn=512, batch4×seq64:  2.1 s/step
V=151936 (原词表), 同配置: 估计 ~4x → ~8 s/step  (未实测)
```

| 步数 | V=18540 | V=151936(估) |
|---|---|---|
| 1000 | 35 min | 2.2 h |
| 4000 | 2.3 h | 9 h |

**⚠️ 词表陷阱（实测）**：不带 `--compress_vocab` 时，教师数据的 token id 是
原始 151936 的，用 `--vocab 18540` 会 `IndexError`。**必须配套**：
- `--vocab 151936` + 不压缩 → 慢但口径与部署一致
- `--vocab 151936` + `--compress_vocab` → 快 4x，但**部署时需 remap**（实验用）

**⚠️ ckpt 来历修正**：`distill_fp32.log` 记录 `params=80.42M`，
反推 = **V=151936, d=256**（未压缩）。而 `ckpt_fp32.npz` 是 V=18540 →
**存盘时词表被换过，两者不是同一配置**。这是之前"用 ckpt_fp32 测 arith 全错"的真正原因。

**必须先做**：跑 200 步，核对 ms/step，再决定总步数（§9.1）。

**完成判据**：
- `record_loss_curve`：KL 单调下降，无 NaN（前 20 步实测 6.12→4.78，正常）
- L2：held-out 段 top-1 命中 > 随机基线（V=18540 随机 = 1/18540 ≈ 0，实用基线取教师 top-1 一致率 28.83% 的一部分）
- L3：`ast.parse` 生成代码，≥ 60% 通过

### 3.3 实验 A2：数据量是瓶颈吗

教师数据只有 15750 位置。**先测"训练集 loss vs held-out loss 的 gap"**：
```
若 gap 大 → 过拟合, 加数据 (重跑 qxn_distill_teacher.py)
若 gap 小 → 容量/步数不足
```
`qxn_distill_teacher.py` 原始语料 143167 tokens，可重新生成更大的教师集。

## 4. 线 B：零训练外积构造（产事实存储）

### 4.1 现状

`qxt_hebbuild.py` 在**合成随机 key→random val** 上成立。未接真实词表。

### 4.2 根本问题：外积构造**不自带语言能力**

```
外积写入: φ(embd[key]) @ B = target_dist
→ 只做"查表", 不产生语法/推理
→ 单独的外积模型 = 一个联想检索器, 不是语言模型
```

**所以 B 线的"可用"定义不同于 A 线**：不是"能写代码"，而是
**"给定 key，能精确检索出预先写入的 value，且不破坏已有语言能力"**。

### 4.3 实验 B1：外积接真实词表

在 Q4T（可用的语言模型）的某一层 FFN 上做**替换**：把该层 W2 换成
「原 W2 + 外积增量」，测：
```
1. 事实检索: 写入 N 条 (token→token), held-out 命中率
2. 语言能力保持: "def add" 仍生成正确代码 (L1/L3 判据)
3. 对照: 不写入 / 随机增量
```

**已完成的前置结论（侧支 #9）**：在**已收敛**模型上，外积增量要翻 top-1
需要与已有预测竞争，可能被稀释。→ **B1 的第一件事是量出"翻盘幅度阈值"**。

### 4.4 实验 B2：阈值扫描（复现论文容量曲线）

用 `qxt_hebbuild.py` 扫 N，找断崖点，与理论 `d²/(n log n)=2` 对比。

**已实测（2026-10-19，D=192 F=1024 V=4000）**：
```
N=100  → 99.0%      N=800  → 90.1%
N=400  → 95.5%      N=1200 → 86.3%     N=2000 → 80.1%
随机 B 对照: 0/1/0/1/0  ← 恒为零
```

**结论（侧支 #14）**：**没有出现论文的"雪崩式断崖"，是缓慢线性下降。**
原因：论文的相变要求「top-1 胜者通吃」的严苛检索；本构造用 onehot val +
无温度，串扰均匀分布 → 缓降。**"雪崩"是检索准则的函数，不是记忆的固有属性。**

**待做**：把检索准则改成硬 top-1 竞争（加温度 / argmax），看是否复现断崖。

## 5. 合体方案（推荐的最终交付）

**目标模型 = 语言能力（A 线蒸馏） + 可写事实（B 线外积）**

```
步骤:
 1. A1 训出可用的蒸馏学生 (L1≥60%, L2>基线, L3 可读)
 2. 选该学生的一层 FFN, 用外积写入 M 条目标事实
 3. 验证: 目标事实可检索 (held-out) 且 L1/L3 不下降
 4. 若第 2 步在已收敛权重上失败 → 改为"训练时预留": 该层 W1/W3 保持随机,
    W2 由外积构造, 其余层正常训练 (论文原设定: A/G 随机, B 外积)
```

**第 4 步是论文精神的正用**：不是往训好的模型硬塞，而是**从架构上让某层
专门做事实存储**。这与侧支 #8 的发现一致（A/G 随机时 φ 准正交）。

## 9. ★ 里程碑：赫布构造 (论文法)在 Q4T 上端到端成立（2026-10-19 实测）

**用户决策链**：不训路线 → 借一个现成模型的 embd+attention → 借 **Q4T**（Q1T 已崩、
Q8_0 需新写解析器）→ 替换**多层 MLP**（方案 B）。

### 9.1 做法（零训练，纯闭式）

```
借 Q4T (rStar-Coder-Qwen3-0.6B, 28层, d=1024, F=3072) 的 embd + attention (冻结)
把全部 28 层的 ffn_down (即论文的 B) 替换为 fp32 覆盖层
写入事实: ΔB_i += c · v ⊗ φ_i(key) / |φ_i(key)|²
   key  = 事实 prompt 在该层末位的 φ = gelu(gate·h) ⊙ (up·h)
   v    = embd[target_token]        ← 关键: 直接用词向量做写入方向
   c    = 5.0
```

### 9.2 判据与结果（§10.1 端到端）

| 判据 | 结果 |
|---|---|
| 目标事实 top-1 | `def add(a,b):` 的 next = **`print`**（rank 76→0）|
| 生成实改 | 基线 `\n    print(a+b)` → 写入后 `print("Addition:", a+b)` |
| 无关 prompt 保持 | `import numpy as np` 生成**不变** |
| 随机 val 对照（§11.8）| rank **19060**（无效）|
| 覆盖机制自洽（§11.1）| fp32 覆盖 vs 原 Q4T，logit 差 **5.7e-7** |

### 9.3 关键发现

1. **value 方向 = `embd[target]` 有效**（侧支 #19）：无需反推 Transformer，
   词向量直接当写入方向，target logit 单调升。
2. **必须多层同写**（侧支 #18）：单层写入被下游 26 层稀释（rank 只到 32）；
   28 层叠加才翻盘（rank→0）。这印证论文"MLP Swapping 换整块"的必要性。
3. **单层写入信号不可控**：第 2 层单层 c=0.1 无效、c=1 变坏、c=10 变乱。

### 9.4 复现脚本

```
tools/qxt_mlp_override_test.py   覆盖机制自洽验证 (§11.1)
tools/qxt_value_dir.py           value 方向验证 (embd[target])
tools/qxt_multi_layer.py         多层叠加增益曲线
tools/qxt_heb_accept2.py         端到端验收 (命中 + 语言保持 + 对照)
```

## 10. ★ 里程碑：外积写入持久化为独立 GGUF（2026-10-20 实测）

**目标**：把运行时 fp32 覆盖的写入结果，落成**独立可交付模型文件**（不再依赖内存覆盖）。

### 10.0 交付清单（阶段定型）

```
交付物:
  models/qxt/rStar-Coder-hebbit.gguf   (234MB, 2 条语义事实, 层18-27, c=20)
代码:
  tools/qxt_repack.py       重打包 (读→反量化→加Δ→重编码→写回)
  tools/q4t_encode.c/.so    C 块编码器 (与 Python 逐位一致, ~50×)
  tools/qxt_repack_e2e.py   端到端验证脚本
命令 (复现):
  clang -O3 -fPIC -shared -o tools/q4t_encode.so tools/q4t_encode.c -lm
  见 §10.4 交付脚本

状态 (§8 诚实标注):
  ✅ 独立 GGUF 可加载; 2/2 条真事实 rank 0 + 生成正确; 无关 prompt 零损伤
  ✅ 关键修复: 只写后段层 18-27 (早期层是劫持来源)
  ⚠️ 算术/短符号事实会串扰 (§10.6); 容量上限未测
  ⚠️ c=20 为经验值, 非系统最优 (§11.4)
```

### 10.1 工具链

```
tools/qxt_repack.py       读 packslim → 反量化 ffn_down → 加 ΔB → 重新编码 → 原地覆盖字节
tools/q4t_encode.c / .so  C 块编码器 (与 q4f8_codebook._enc_block 逐位一致)
tools/qxt_repack_e2e.py   端到端: 写入 → 重打包 → 加载新文件 → 命中判定
```

### 10.2 两个实现 bug（§11.1，均为"长度对≠数值对"）

| # | 现象 | 根因 | 修正 |
|---|---|---|---|
| 1 | 重编码字节数正确但数值全错（往返相对误差 **1.41**）| 块序搞错：引擎按**每 64 列**分块读，我用了全局 reshape | `dequant_tensor`/`quant_tensor` 逐字复刻引擎的 64 列分块循环 |
| 2 | 我最初的自检只查了 `len(bytes)==entry['bytes']` | **长度一致掩盖了数值不一致** | 判据改为：重编码后再用引擎读回，与原始 dequant 对拍（误差应为 0）|

**修正后**：`dequant vs 引擎 相对误差 = 0`，`重打包(无Δ) vs 原始 相对误差 = 0`。

### 10.3 性能：C 编码器（~50×）

| 编码器 | 单层 (3072×1024) | 28 层 |
|---|---|---|
| Python `q4f8.encode` | ~100 s | ~47 min |
| **C `q4t_encode.so`** | **2.1 s** | **~60 s** |

C 编码器与 Python **逐位一致**（scale/code 全等，500 块抽检 0 差异）。

### 10.4 ★ 真实验收：写模型原本答不出的事实（2026-10-20）

**之前的验收 prompt（`def add(a,b):`）是代理**（§10.1 陷阱）—— 基线本就会答。
改用**基线明确答错/乱答**的真事实：

| prompt | 基线（Q4T 原版）| 交付（写入后）|
|---|---|---|
| `The largest planet is` → `Jupiter` | rank 3, gen `the planet of the planet of the`（胡说）| **rank 0**, `Jupiter, which is the largest planet in the solar system.` |
| `The color of the sky is` → `blue` | rank 9, `important for the environment...` | **rank 0**, `blue because the atmosphere contains nitrogen and oxygen...` |

**无关 prompt 保持（零损伤）**：`def factorial(n):`、`class Point:`、`import os\nos.path.`
均与基线一致。

**这次才是赫布构造 (论文法)的有效证明**：写入了模型不知道的事实，且不破坏已有能力。

### 10.5 ★ 关于"层"的更正（2026-10-20，推翻 §10.5 旧说法）

**用户质疑**："28 层应该都能换，可能是代码有问题。" —— **质疑成立。**

**旧说法（错）**："早期层 0-8 是劫持来源，必须只写后段。"
**旧说法的来源**：分组测（前/中/后 1/3，各 c=20）时前 1/3 坏。

**真相**（实测）：

1. **逐层单独写入 c=20，每层都能把 rank 推到 1**（层 0 甚至 rank 5）——
   "单层被稀释、必须多层"是 **c 太小的假象**（§9.3 用的是 c=5）。
2. **全 28 层坏的原因是音量叠加 28 倍**（28 × c=20 = 560），
   **不是早期层有毒**。旧诊断犯了 §11.1 归因错误。
3. **全 28 层 + c 分摊（合计 c=200）能达成 2/2 rank 0** —— 论文"换整块 MLP"可行。

**但全 28 层有渗透代价**（6 条 holdout 实测）：

| 方案 | 事实命中 | holdout 污染 |
|---|---|---|
| 全 28 层, c 合计 200 | 2/2 rank 0 | **4/6 被污染**（`np.`→`np. np. np.`；`os.path.`→`0\nimport sys`）|
| 后 10 层, c 合计 20 | 2/2 rank 0 | **0/6 污染** |

**根因（真正的局部化结论）**：
- **早期层的 φ 是通用特征**（对任何输入都响应）→ 用它当 key 会**误伤无关输入**
- **后段层的 φ 只对当前输入敏感**（接近输出）→ 写入精准

**修正后的结论**：不是"早期层有毒"，而是**早期层 φ 的通用性导致 key 冲突**。
交付维持**后 10 层**，但理由更正为"避免通用特征误伤"。

**待验证**：逐层影响力加权（按该层对输出的贡献分摊 c）是否能让全 28 层既命中又不渗透 —— **已试，失败**。

### 10.5.1 逐层影响力加权（已试，失败）

**做法**：单独写每层测 target logit 提升 → 归一化成权重 → 全 28 层加权写入（总强 200）。

```
单层影响力: [6.8, 4.23, -1.83, 3.68, 1.27, ...]   ← 层 2 竟为负, 受量化噪声影响
加权全28层结果:
  Jupiter -> rank 0 但生成 'Jupiter is Jupiter is Jupiter is...' (退化)
  holdout -> 干净 (os.path./np. 正常)
```

**结论**：加权**换来了 holdout 干净，但牺牲了事实生成**（权重过大 → 重复）。
**单层影响力本身就是噪声**（层 2 = -1.83），不可靠。

**最终结论（本模型实测）**：
```
"28 层都能换"      = 真  (全 28 层 c=200 可达 2/2 rank 0)
"全换最好"         = 假  (渗透 holdout 4/6)
"后 10 层"         = 本模型的最优工程选择 (命中 2/2 + 零渗透)
```
渗透的根因是**早期层 φ 的通用性**（对任意输入都响应），非"层有毒"。
这是方法的**内在权衡**，不是可修的 bug。

### 10.5.2 最少层扫描（2026-10-21，层数线收尾）

**目标**：找最少层仍能 2/2 rank 0 且 holdout 0/6。

**做法**：`tools/qxt_minlayers.py`，fp32 上扫「最后 k 层」（每层 c=20），
`capture_phi` 一次复用；不重打包。holdout 用 §10.5 的 6 条。

**结果**：
```

  最后 1层: ranks=[0,0] 污染 2/6
  最后 2层: ranks=[0,0] 污染 2/6
  最后 3层: ranks=[0,0] 污染 2/6
  最后 4层: ranks=[0,0] 污染 2/6
  最后 5层: ranks=[0,0] 污染 2/6
  最后 8层: ranks=[0,0] 污染 2/6
  最后10层: ranks=[0,0] 污染 3/6
```

**关键更正**（对 §375「单层只到 rank 1」）：
- 单独写**层 27 / 26 / 20**（c=20）**就是 rank 0**；层 0 rank 5，层 10 rank 1。
- 即：**后段任意一层即可命中，无需多层**。§375 的「单层 rank 1」是层 0/中段的读数，
  被误当成全体；后段层本来单层就够。

**层数线结论**：
```
✅ 最少层 = 1 层（后段 20-27 任一, c=20）→ 2/2 rank 0
❌ 缩小层数不解决污染：1 层也 2/6, 10 层 3/6
根因: 污染 = key/事实与代码域隐空间重叠 (§10.6 串扰), 与层数无关
```

**§11.8 判据有区分力验证**：6 条 holdout 基线各跑 3 次，**0/6 不稳定**（逐字一致）→
「污染 2/6」是真信号，非生成噪声。基线生成本身在乱编（如 `os.path.` → `abc\n\n...`），
但**稳定地乱编**，故逐字比较有效。

**为何交付仍用 18-27 而非 1 层**：单层与多层 rank/holdout 无差异，
但多层（c 分摊）对**量化鲁棒性**更好（§#25：4-bit 压掉 Δ，运行时 fp32 只需 c=5，
重打包需更大 c）—— 交付配置暂不变，此点待验。

### 10.5.3 1-bit 能否写事实? (2026-10-21, 更正单层结论)

**背景**：对话中一度得出"1-bit 救不回来"，**那是单层读数被当成全体**（§11.1 典型）。

**实测**（Q1T 由 `qxt_pack_q1t.py 1` 从 Q8_0 重建, 68.8MB）：

```

  单层27      每层c=20: rank 21076
  最后2层     每层c=20: rank 5190
  后10层18-27 每层c=20: rank 0    ← 命中! (合计c=200, 同 Q4T 交付机制)
  全28层      每层c=20: rank 8294 (过冲)
  单层27      c=160:    rank 0    ← 单层要 8× 更大的 c
```

**修正后的结论**：
```
✅ 1-bit 能写事实 —— 多层(18-27)分摊, 每层 c=20 → rank 0
   (此前"1-bit 救不回来"是错的: 那是单层 c=160 的读数)
⚠️ 生成质量排序: Q4T >> q1mix(混合精度) > 纯Q1T (1-bit 毛刺更多)
✅ Q4T 在每层 c=10 达到最佳生成 ('Jupiter, which is Jupiter's largest planet')
   每层 c=20 就过冲成 'Jupiter Jupiter...'
```

**混合精度（1-bit 主体 + ffn_down@4）**：
```
q1mix (28个ffn_down@4): 101.8MB, 平均 1.600 bit
q1only27 (仅层27 ffn_down@4): 70.0MB, 平均 1.021 bit
  - 仅补"被写层"无效 (单层 c 仍=160, 与纯1-bit无异)
  - 补全部 ffn_down 才降 c (c=80)
  - 即便 q1mix 生成仍有杂质 → 瓶颈在 output 投影(仍1-bit)
结论: 混合精度"救1-bit"实际退化向 Q4T; Q4T 224MB 更可靠
```

**方法论教训**：单层读数 ≠ 全体结论。**多层分摊是外积写入成立的关键机制**，
1-bit 与 4-bit 都遵此规律；差别只在生成质量（量化毛刺）。

### 10.6 串扰诊断：短符号事实会渗透（侧支 #8 重演）

3 条事实（含 `2 + 2 =` → `4`）时，无关 prompt `import os\nos.path.`
生成退化成 `1.1.1.1.1...`。**去掉 `2+2=4` 后恢复正常**。

**根因**：`2 + 2 =` 的 φ 与代码类 prompt 隐空间高度重叠（都是短符号序列），
且 `4` 是高频 token —— key 隐状态相似 → 串扰（与侧支 #8 教训一致）。

**规避**：只写**语义独特**的事实（planet/sky 类），避免与代码域冲突的算术/短符号。

### 10.9.4 ★ 赫布构造 (论文法)（whitening）在**多样真实 key** 上完胜（修正 10.9.1 的退化结论）

**论文源码核对**（`HazyResearch/hebbian-mlps`）：
- `readout.py::raw_readout` = `VᵀΦ/n`（**无 `|φ|²` 归一化**）
- `readout.py::full_ridge_readout` = `(ΦᵀΦ/n + λI)⁻¹`（**白化**）
- `construction.py` 的 data_dependent 变体用 CG 最小二乘拟合 A0/A1

**在 32 条多样真实事实上（layer 18-22）**：

| 读法 | c=5 | c=20 | c=40 |
|---|---|---|---|
| norm（现行 `1/\|φ\|²`）| 4/20 | 1/20 | 0/20 |
| **whiten（论文）** | 11/20 | **19/20** | **20/20** |
| norm+wh | 14/20 | 8/20 | 6/20 |

（baseline 3/20 —— 原模型本来就会 3 条，判据须用**相对基线提升**）

**⇒ 修正结论**：在 key 多样的真实场景，**赫布构造的白化 (HebbBuild) 大幅优于我们的单点归一化**；
此前"whitening 没用"是**退化合成集**造成的假象。

**层集影响（whiten c=20，均 20/20）**：18-22 生成最干净
（`'The capital of Germany is'` → `' Berlin'`）；18-27 则是 `' Paris Paris Paris...'`
→ **与 §10.9.2 一致：上层 23-27 的 key 近乎不区分（layer 27 两两余弦 0.95）→ 写入无差别污染**。

### 10.9.5 混合方案：白化用于"只写少量事实"（交付版 2 条）

**问题**：whitening 需 F≫1（协方差低秩），只写 2 条时白化退化。
**方案**：用 32 条多样事实算 `Wt=(cov_aux+λI)⁻¹` 做白化，**只写入 2 条目标事实**。

| 层集 | norm 干净窗口 | norm+wh（赫布构造 (HebbBuild)）干净窗口 |
|---|---|---|
| 单层 27 | **无** | **无**（c=80 仍 ranks[0,5]）|
| 18-22 | c ∈ [5,20] | c=80 |
| 22-27 | c=5 | c ∈ [40,80] |
| 18-27 | c=5 | **c ∈ [20,80]** |
| 14-22 | c ∈ [5,10] | c ∈ [20,80] |

**⇒ 白化把窗口整体上移并加宽**（18-27 由 c=5 扩到 c=20~80 全干净），
但**单层无论如何都救不回来**（需 c=40 命中，而那已是重度污染区）。

### 10.9.6 验证过的否定结论（新增）

- **论文的 `raw_readout`（`VᵀΦ/n`，无 `|φ|²`）在 Q4T 上不可用**：
  2 条事实测试中只命中 1/2（Jupiter 淹没 Paris），且所有无关 prompt 全变 `Jupiter`。
  原因：φ 模长差异让大模 key 完全主导。我们的 `1/\|φ\|²` **是对论文 raw (赫布构造的未归一化读出) 的正确修正**，不是偏离。
- **退化 fact set 会让所有方法看起来一样差**（自己踩的坑）：
  合成 key 在高层近乎平行 → 任何 readout 都不可能区分 → 比较无意义（§11.8）。
  **做 readout 对比必须用多样真实 key。**
- **"重复输出"不是损伤**：事实 prompt 上重复是**正确**行为（模型本就该说 Jupiter）；
  只有**无关 prompt 上出现 value token** 才是损伤。两者必须分开计。

## 10.10 ★ 教学边界：赫布写入能教什么、不能教什么（2026-10-22，零训练）

用户的问题："能不能真正教会？"下面全部是零训练实测（层 18，c=60，即 §10.9.8 的
2/2 + holdout 0/6 配置）。**没有一条来自训练。**

### 10.10.1 ★ 新机制：写入是"位置锚定"的

```
写在 key 第 p 个 token 的 φ_p 上  ->  只改变 **p+1 的预测**
causal mask  =>  同前缀的任意续写, 在 p 处隐状态**逐位相同**
             =>  同一位置的写入对同前缀续写精确生效, 对"答案槽在别处"的问句无效
```

实测反例（`/tmp/bridge_real3.py`）：写 `"…were held **is**"`（注入在 `is` 之后），
问 `"…were held **is in the country of**"` —— 答案槽在 4 个 token 之后：

```
[rank] key = 0        # 写入确实生效
[续写] ' the United States. The city is named after the United States...'
                      # 问句完全没被推动
```

⇒ 之前记录的"改写问句 rank 16/44"是**部分命中**（残余效应），不是精确命中。
**做桥接/改写必须先对齐"答案槽"，否则测的是别的东西。**

### 10.10.2 改写召回率（虚构国家版，用来分离"召回"与"知识"）

key = `"The capital of the fictional country of Artonia is"` → `" Paris"`

| 改写 | Paris rank | 生成是否说出 Paris |
|---|---|---|
| 原句 | **0** | ✓ |
| `Artonia's capital is` | 1 | ✗ (`' a city of the sun'`) |
| `the country called Artonia is` | 2 | ✗ |
| `the city that is the capital of Artonia is` | 4 | ✗ |
| `capital city of … is` | 9 | ✗ |
| `What is the capital of Artonia?` | 188 | ✗ |
| `…capital of Artonia?` | 229 | ✗ |

⇒ **改写召回率 = 1/5**；rank 上升但**生成不跟随**；以 `?` 结尾基本不命中。
⇒ 召回边界是**末位 token 的形状**（`is` vs `?`），不是语义相似度。

### 10.10.3 ★ 桥接（把写入值当中间量）：FAIL

设计：写 `"The country where the 1958 FIFA World Cup was held is"` → `" Sweden"`
观察点：模型吐出 V 之后，续写里是否出现 **V 的后继事实**（Stockholm）。
后继事实不可能凭空出现，只能来自引擎的预训练知识。
base 预筛全部合格（rank 373~1487，续写是 `'the United States' / 'a country of 1966'`）。

| 写入值 | 写入后 rank | 续写 | 含 V | 含后继 |
|---|---|---|---|---|
| Sweden | 2 | `' the United States of America. The United States…'` | ✗ | ✗ |
| Germany | **0** | `' Germany. Germany is a country in Europe, and Germany is a country in Europe.'` | ✓ | ✗ (Berlin) |
| Italy | **0** | `' Italy. Italy is a country in Europe, and it is known for its football.'` | ✓ | ✗ (Rome) |
| England | **0** | `' England. England is a country where the 1966 FIFA World Cup was held.'` | ✓ | ✗ (London) |

⇒ **V 被当作 token 吐出来了**；但"后继事实没出现"**不能**证明引擎不用 V（见下方更正）。

#### ★ 更正（2026-10-22 同日复测）：此前的措辞过强

原文写"后续全是与 V 无关的通用套话 → 引擎不从注入值继续推演"，**这句是错的**：

```
' Germany. Germany is a country in Europe, and Germany is a country in Europe.'
```
`Germany is a country in Europe` 本身**就是 V 的语义**（换成任意国家都会变），不是无关套话。

而且问句 `"The country where the 1974 FIFA World Cup was held is"` **并没有要求任何
依赖 V 的后继**（问"哪国"→ 答"德国"就结束了），所以"没出现 Berlin"根本不是失败证据。
这是 §11.3 的代理错位（代理=后继词出现，目标=能否用 V 推演），**由我提出、由我搞错**。

**同日补充实测（决定性问题）**：

| 探测 | base 输出 | 含义 |
|---|---|---|
| `'The capital of Germany is'` | `' Berlin...'` | 落脚点存在 ✓ |
| `'The capital of Italy is'` | `' Rome...'` | ✓ |
| `'The capital of England is'` | `' London...'` | ✓ |
| `'The capital of Sweden is'` | `' Gothenburg...'` | ✗（Sweden 那条桥接本来就不可能成立） |
| `'...was held is Germany. Its capital is'` | `' Berlin...'` | **组合能力存在** ✓ |
| `'The capital of the country where the 1974 FIFA World Cup was held is'` | `'...Moscow'` | 没有事实时的基线 ✗ |

⇒ **真正的缺口不是"引擎不会推理"，而是"事实只能以占用下一个 token 的形式存在"**：

```
位置锚定的 FFN 写入 = 在 p 处加 v  -> 必然改变 p+1 的预测
  写得够大 -> 说出 V（占用答案槽, 之后无法再"查询"）
  写得不够 -> p+1 不变, 后续也拿不到
=> 做不到"不说不占位、但可被后续位置查询"
```

要做到后者，事实必须写进**注意力侧**（虚拟位置的 K/V），而不是 FFN。
**这是本方法的架构边界，不是调参问题。**

（第 5 条 Uruguay 因内存压力进程被杀，未测完；4/4 失败已足够定论。）

### 10.10.4 串扰：同模板 key 之间不独立

## 10.11 ★ 多 key 覆盖曲线：覆盖 vs 污染（2026-10-22，零训练）

用户提出的方向：既然单 key 只认原句，就**对同一事实写多个改写 key**。
问题：覆盖到多少？代价多大？

配置：层 18，value=`" Paris"`，事实=1900 夏奥会城市。
写入 key（5 个不同措辞）与测试 key（6 个未见改写）**不重叠**。

### 10.11.1 结果（`/tmp/coverage.py`）

| N | c | 总振幅 c·N | 写 key rank | 覆盖率(≤3) | 串扰 | holdout |
|---|---|---|---|---|---|---|
| 1 | 60 | 60 | `[0]` | 4/6 | 1/4 | **0/6** |
| 2 | 40 | 80 | `[2,0]` | 4/6 | 1/4 | — |
| **3** | **27** | **81** | `[2,0,0]` | **5/6** | 1/4 | **0/6** |
| 5 | 16 | 80 | `[6,0,0,0,18]` | 4/6 | 1/4 | — |
| 5 | 40 | 200 | `[0,0,0,0,0]` | **6/6** | **2/4** | **1/6** 污染 |

**必须扣掉一条"假覆盖"**：测试句 `"In which city were the 1900 Summer Olympics
held? Answer:"` 的 **base rank 已是 3**（模型自己就会答）→ 它不能算写出来的。
去掉后：**N=1 覆盖 3/5，N=3 覆盖 4/5，N=5/c=40 覆盖 5/5**。

⇒ **覆盖-污染是一条真曲线**，不是免费的：
```
N=1  c=60   3/5   holdout 0/6   串扰 1/4(近平局)
N=3  c=27   4/5   holdout 0/6   串扰 1/4   但首 key 只到 rank 2
N=3  c=33   5/5   holdout 0/6   串扰 1/4   写 key 3/3 rank 0  <- fp32 最优
N=5  c=40   5/5   holdout 1/6   串扰 2/4 + 重复退化
```
**总振幅 c·N ≈ 100 是不变预算**（§10.9.2 / §13.2）：N=3 用 c=33 正好接近，
N=5 若把 c 压到 16 则单 key 太弱（写 key 自身 rank 退到 6/18）。
**注意 fp32 的 c 不能直接用于 Q4T**（见 §10.11.5，打包后要 c≈44）。

### 10.11.2 串扰的真相：是近平局，不是巴黎污染

N=3, c=27 下 4 条无关探针的 top1：

```
'The largest planet in the solar system is'  base=' the'(0.69) -> ' the'(0.67)      same
'The color of the sky is'                    base=' important'(0.03) -> ' determined'(0.36)  FLIP
'The first president of the United States was' base=' George'(0.73) -> ' George'(0.85) same
'def factorial(n):'                          base='\n'(3.39) -> '\n'(3.34)          same
```

唯一翻转的 base margin 只有 **0.03**（本就近乎平局）→ **不是把无关答案推向 Paris**。
（另：`"The color of the sky is"` 上 Paris 的 rank 从 5003 → 666，仍远离 top。）

### 10.11.3 过预算的失效形态（与 §10.9.2 同源）

N=5, c=40（总 200）虽然 6/6 命中，但生成已经出现正反馈：
```

' Paris, France. Paris was Paris, France. Paris was Paris,'
```
并污染 1/6 holdout（`import os\nos.path.`）。⇒ **覆盖率不能靠加大振幅买。**

### 10.11.4 结论

| 需求 | 配方 | 代价 |
|---|---|---|
| 只要原句 | N=1, c=60（现交付 1L18） | 改写覆盖 3/5 |
| 要改写覆盖 | **N=3, c=33(fp32) / c=44(Q4T)** | 总振幅 ~100/132 |
| 要几乎全覆盖 | N=5, c=40 | 必然付 holdout 污染，不推荐 |

**给交付的建议**：默认仍是 `1L18 c=60`；若用户场景是"多种问法都要答对"，
用 N=3 的变体（§10.11.5 已打包，但**带同模板混淆缺陷**）。

### 10.11.5 ★ 打包实测：Q4T 需要更高的 c，且暴露"同模板年份不可分"

`models/qxt/rStar-Coder-hebbit-3k-Oly1900.gguf`（单层 18，3 个 key，c=44，总 132）。

**Q4T 量化压掉 Δ，fp32 的 c=33 打包后不够用**（首 key rank 从 0 退到 6）：

| c（打包后实测） | 写 key rank | 改写覆盖 | 1904 对照 |
|---|---|---|---|
| 33（fp32 是 0） | `[6,0,0]` ✗ | 4/5 | Paris rank 1 |
| 40 | `[1,0,0]` ✗ | 4/5 | rank 0 |
| 42 | `[1,0,0]` ✗ | 5/5 | rank 0 |
| **44** | **`[0,0,0]` ✓** | **5/5** | **rank 0 ✗** |
| 50 / 60 | `[0,0,0]` ✓ | 5/5 | rank 0 |

c=44 端到端验收：
```
写入 key 3/3 rank 0 ✓        holdout 6/6 逐字一致 ✓
改写覆盖 5/5（第 6 条 base 本就会答，不算）
1904 对照 -> Paris rank 0  ✗  ' Paris, France. Paris is a city of Paris, France'
```

⇒ **形式判据全过，但 1904 对照被污染成 Paris**（且带重复退化）。

### 10.11.6 ★ 去混淆三方案全部失败（2026-10-22，结构性结论）

用户提出的思路：1900 写 +c、1904 写 −c（对比写入）。实测三种变体：

**几何前提**：`cos(φ_1900, φ_1904) = 0.980`（层 18；全层扫描最低也只到 **0.955@层7**）
⇒ 两个事实在 φ 空间几乎重合，**年份差异只占 2%**。

| 方案 | 1904 rank | 1900 原句 | 改写覆盖 | 结论 |
|---|---|---|---|---|
| 普通负写入 c=33, −49.5 | 35 ✓ | **118** ✗ | 1/5 | 1:1 交换，无解 |
| 普通负写入 c=44, −66 | 21 ✓ | 67 ✗ | 1/5 | 同上 |
| 逐 key 投影掉 1904 方向 (defl, c=44) | **114** ✓ | **7** ✗ | 1/5 | 交叉项为负 → 三个 key 互相抵消 |
| 共用去 1904 方向 (c=60) | **123** ✓ | **0** ✓ | **0/6** ✗ | 去掉模板共性 = 去掉泛化来源 |

**根因**：泛化（改写命中）恰恰依赖 φ 的**模板共性**（0.98），
而区分 1900/1904 只能靠那 **2% 的残差**。二者是同一个东西的两面：

```
保留模板共性 -> 改写能命中, 但 1904 也命中 (混淆)
投影掉公共方向 -> 1904 免疫, 但改写一个都不命中 (泛化归零)
```

⇒ **同模板年份混淆不可解**，不是 c 的问题，也不是选层的问题（全层 cos ≥ 0.955）。
多 key 覆盖方案对"同模板多个事实"**天然不适用**；它只适用于模板唯一的事实。

**副产品**：`cos` 全层扫描（层 0→27）0.9999 → 0.955(层 7~15) → 0.985(层 18~26) → 0.997(层 27)，
说明**层 7~15 对同模板事实的区分力最好**，但绝对值仍远超可用阈值（需 < 0.8）。

## 10.12 ★ 判决实验：事实必须走 KV 路径才能被"使用"（2026-10-22）

用户判断："写入的同时可能还要修正注意力/路由"。**实测成立**，但结论与直觉的
表述不同：注意力的"写入"在实现上就是**上下文/KV 注入**，不是权重修改。

### 10.12.1 最小对比（同一提示句、同一事实）

```
prompt = "The country where the 1974 FIFA World Cup was held is [ ? ] well known.
          The capital city of that country is"
期望 Berlin（base 已知 Germany->Berlin：§10.10.3 更正）
```

| 通道 | Berlin rank | 生成 |
|---|---|---|
| A 无事实（base） | 425 | `' called the "City of the World Cup"...'` |
| **B 事实在 KV（上下文）** | **0** | **`' Berlin. The country is known for...'`** ✓ |
| C FFN 权重写入（层18, 沉默, c=120） | **37** | `' called the "City of the World" and is located...'` ✗ |

⇒ **桥接不是不可能**：事实在 KV 路径上时，引擎会用它推理（B）。
**FFN 写入最好只能把 rank 从 425 压到 37（10×），赢不了 argmax。**

### 10.12.2 为什么 FFN 写入做不到（沉默扫描的证据）

沿写入位置 × 振幅扫描（`/tmp/silent2.py`），要求 p+1 不变（沉默）：

```
pos=21 ('of')  c=60  -> rank 110 SILENT
pos=21 ('of')  c=120 -> rank  37 SILENT      <- 沉默下的最好结果
pos=21 ('of')  c=200 -> rank  34 LOUD        <- 一开始出声就已经晚了
pos=14 ('is')  c=120 -> rank  31 LOUD        -> 生成 'Germany is Germany is...' 锁死
```

**沉默性与效果量被同一条直线锁在一起**：写大 → p+1 变成 `Germany`；
写小 → 表征太弱。**不存在"够强但不出声"的区间。**

### 10.12.3 为什么"投影掉输出方向"也不行（数学上归零）

想让写法"沉默但保留表征"，最自然的做法是把 value 向量沿输出方向投影掉：
`v' = v - (v·û)û`。但 **token embedding 与 unembedding 是同一向量**（tied）：

```
v = emb(" Germany") = û·|v|   =>   v' = 0
```

⇒ 不存在"代表 Germany 但不驱动 Germany logit"的子空间。
（不是参数选择问题，是绑定嵌入的结构。）

### 10.12.4 架构结论

| 通道 | 持久化 | 能否"查询但不占位" |
|---|---|---|
| FFN 权重写入（本方法） | ✓ 静态 GGUF | ✗（只能占掉下一个 token） |
| KV / 上下文注入 | ✗ 每次请求 | ✓ |
| 训练路由/电路 | ✓ | 待验证（违反"免训练"） |

⇒ 本方法的边界不是"层选得不对"或"c 不够大"，而是**位置锚定的 rank-1 权重更新
只能表达"下一个 token 是什么"，无法表达"这个事实在别处可被查询"**。
要让模型用事实推理，事实必须进入 KV；那是运行时机制，**不能烘进 GGUF**。

这与论文不矛盾：论文的 fact-editing 是**单层模型**（MLP 后就是 unembedding），
且评的是召回不是多跳（`fact_editing/README.md`："the rest of the model remains fixed"）。

## 10.13 ★ 运行时事实记忆层（`tools/hebb_memory.py`，2026-10-22）

§10.12 的结论是"事实必须走 KV"。本工具把它做出来：**零训练、不改权重**，
把事实库以运行时注入口径接到模型上。

### 10.13.1 流程

```
事实库 (key, value)
  -> 检索: token 级 IDF + bigram 加权重合
  -> 注入: "<key> <value>.\n<question>\nAnswer:"
  -> 生成
  -> 相似度不够 -> 不注入, 退回 base
```

### 10.13.2 验收（10 条 FIFA 事实，`python tools/hebb_memory.py --demo`）

| 项 | 结果 |
|---|---|
| 检索（上下文里的年份定位正确条目） | **10/10** |
| 桥接（事实 -> 首都，同一句内推理） | **8/10** |
| 直接召回 | 3/3 |
| 无关问句（`The color of the sky is`） | sim 0.00，不注入 ✓ |
| 库外年份（1954） | sim 0.00，硬拒绝 ✓ |

两条桥接失败（1986 Mexico、1994 United States）是 **base 自己的地理知识错**
（同一模型在别的句式下把 Italy 首都答成 Milan/Lima），不是检索或注入错。

### 10.13.3 三个工程教训（都是实测踩出来的）

1. **φ-cosine 检索不可用**：10 条同模板 key 的相似度全在 0.5 附近，
   无关问句（0.595）反而高于正确条目 —— 与 §10.11.6 是同一个几何问题。
   ⇒ 检索必须用**表层 token**（IDF 加权），不能用 φ。
2. **年份不是单 token**：`'1966' -> ['1','9','6','6']`，词袋会把
   1966 和 1986 判成完全一致（共享 `1`,`9`,`6`）⇒ 必须用 **bigram**。
3. **库外信号要硬拒绝**：`1954` 与 `1958` 共享全部模板 token + `1`,`9`，
   IDF 相似度仍有 0.87 ⇒ 规则改为"查询里出现库中未见的 bigram → 分数直接 0"。

**模板对结果影响很大**（同一 10 条事实）：

| 模板 | 命中 |
|---|---|
| `<key> <value>.\n<q>\nAnswer:` | **8/10** |
| `<key> <value>.\n<q>\nThe capital city is` | 7/10 |
| `<key> <value>. <q>`（陈述式续写） | 6/10 |
| `<key> <value>.\n<q>\nAnswer in one word:` | 5/10 |

### 10.13.4 边界（必须标明）

- 这是**运行时上下文注入**，不是权重写入：GGUF 没变，事实不持久化在模型里。
- 因此"教"的形态从"改模型"变成"模型 + 记忆层"；换来的是 §10.12 里
  FFN 写入做不到的**组合能力**（能用事实推理）。
- 与 §10.11 的多 key 权重写入不冲突：后者适合"只要求召回"的静态场景。
- **§10.14 已把它变成静态工件**（事实以 K/V 常量块烘入，文本里不出现）。

## 10.14 ★ 赫布静态事实块（`tools/hebb_kvblock.py`，2026-10-23）

§10.13 的记忆层每请求都要带事实文本。能否**把事实烘进模型、文本里不出现**？
可以，而且零训练——写入的对象是**注意力的 K/V**，不是权重。

### 10.14.1 构造（全闭式）

```
1. 在干净上下文里跑一遍事实块 (如 "The country where the 1974 ... is Germany.\n")
2. 采集每层 post-RoPE 的 K/V          -> (28 层, 2, 18, 8, 128)
3. 保存为 .kvblk (npz, 3.9 MB)
4. 推理: 用 18 个占位 token 撑出位置, forward(force_kv=...) 覆写 K/V
```

引擎侧新增 `force_kv` / `capture_kv`（`tools/q1t_stream.py`），其余不动。

### 10.14.2 验收（Q4T，`tools/hebb_kvblock.py`）

| 场景 | 输出 |
|---|---|
| 事实在文本里（参考） | `' Berlin\n\nThe country where the 1974 ...'` |
| **烘块，文本里无 1974/世界杯/德国** | `' Berlin\n\nThe country where the 1974 ...'` **逐字相同** |
| 同位置移植 K/V（机制自检） | 逐字相同 |
| 对照：块内容换成 France | `' Paris...'` ✓ |
| 对照：不烘块 | `' 1\n\n**Note:** The answer is 1...'` ✓ |
| 换问句：`Which continent is that country in?` | `' Europe...'` ✓ **二次推理** |
| 换问句：`How many people live...` | 编造数字（模型本来不知道） |

**结论**：静态 K/V 块能完整复现"事实在上下文里"的行为，包括
`国家 -> 大洲` 这种二次推理。文本里一个字都没有。

### 10.14.3 做不到的（如实记录）

| 尝试 | 结果 |
|---|---|
| **单 token 槽**（只烘 `Germany` 的 K/V） | 模型会说 `Germany`，但**不桥接**到 Berlin —— 桥接依赖整句的关系结构，不是一个实体 |
| 块整体后移 8 位（前面塞 8 个占位） | Germany 块退化（`Germany is the capital of Germany`），France 块仍对。原因是 8 个占位也进入 softmax 分母（RoPE 只依赖相对位移，不是根因） |
| 两块共存（1974+1998）分别提问 | 单问尚可；`1974 和 1998 都在哪` 答成 `Germany`，`1998 那国的首都` 答成 `1998` —— 与 §10.11.6 同模板混淆同源 |

### 10.14.4 代价与边界

- 构建 1 s；体积 3.9 MB / 18 槽 / 28 层；每请求多占 18 个上下文位置。
- **本质是前缀缓存的固化**：事实不在权重里，在 K/V 侧车工件里。
  说"模型自己知道"仍不成立；说"模型+工件知道并能推理"成立。
- 因此"扩充赫布公式到注意力"的正解是 **构造 K/V**，不是 rank-1 改 `W_K/W_V`：
  `Δ(q·k_j) = α(q·u)(x_j·s)` 只能改写**已有 token 之间**的路由，
  造不出不存在的记忆项（§10.12）。

### 10.14.5 踩坑记录（§11.1）

`StreamEngine()` 默认包是 **Q1T**，而所有既有结论基于 **Q4T**（`hebb_write.DEFAULT_SLIM`）。
第一轮实验因此全部输出 `POR/const` 乱码，差点被误判为"K/V 移植无效"。
**凡新脚本必须显式 `slim=DEFAULT_SLIM`。**

## 10.15 ★ 闭式权重写入的天花板：三层几何证据（2026-10-23）

"再把权重取出来重新混合计算"能不能学会？已在**秒级**测量里判死，不需要训练/求解。

### 10.15.1 三个 cos（层 18）

| 层面 | 问题 | 实测 |
|---|---|---|
| 寻址 | `cos(φ_问句, φ_事实)` | **0.098**（无事实问句 0.113，裸问句 0.096） |
| 事实之间 | `cos(φ_1974, φ_1998)` 同模板 | **0.98**（§10.11.6） |
| 路由 | `cos(A内) − cos(A–B)` | **0.852 − 0.804 = 0.048** |

A = 6 种"1974 世界杯主办国"问法；B = 7 种无关问题（France 首都、1998 世界杯、人口、大洲…）。
最坏一对 A–B 的 cos = **0.997**（"1998…whose capital is" 与 "1974…whose capital is"）。

### 10.15.2 数学含义

写入是 `ΔB = c·v⊗φ_f/|φ_f|²`，激活强度 ∝ `cos(φ(x), φ_f)`。

- 0.098 ⇒ 问句处只以 10% 幅度、沿单方向 `v` 生效（位置锚定，§10.10.1）。
- 0.048 的组间差 ⇒ 没有任何线性方向能分出"该放 1974 还是 1998"。
- 因此**闭式 ΔB 能拟合任意有限集合，但选择权在模型相似度手里，而它不区分**。

### 10.15.3 结论（勿再重试）

| 方案 | 结论 |
|---|---|
| 用问句 φ 写（让写入口对上问句） | 只对**那一句**有效，换措辞即失效（§10.10.2 改写 1/5） |
| 多措辞岭回归/最小二乘混合 | 不需要做：A 内与 A–B 差 0.048，留出集必失败 |
| `ΔW_K` rank-1 路由 | 只能改写**已有 token 之间**的偏置，造不出记忆项（§10.12/§10.14.4） |

**权重侧的天花板是结构性的，不是精度问题。** 能组合的形态只有 K/V（§10.14）。

## 10.16 ★ 字节账：赫布写入 vs 训练写入（2026-10-23）

同一模型（Q4T，层 18，1 条事实，c=60），实测文件级 diff：

| 维度 | 赫布写入 | 训练（同张量, 上限） | 训练（全模型, 上限） |
|---|---|---|---|
| 文件大小 | 233,982,682（**不变**） | 233,982,682 | 233,982,682 |
| 改动字节 | **131,731（0.056%）** | ≤1,671,168（0.71%） | ≤233,982,682（100%） |
| 改动参数 | 9.2%（≈289k / 3.1M） | 3.1M | 0.6B |
| 唯一信息 | **4,096 floats = 16 KB** | 12.6 MB | 2.4 GB |
| `‖ΔW‖/‖W‖` | 0.0376 | — | — |
| `max|ΔW|` | 0.049 | — | — |
| 耗时 | ~2 s | 小时级 | 天级 |

补充实测：
- 5 层 1 条（c=24）只改 **70,464 B**；3 条（c=44）改 **144,726 B**——改动字节几乎不随事实数增长（同一 rank-k）。
- **132 KB ≠ 16 KB**：8× 开销来自 4-bit 量化粒度（改一个码点即动整字节 + 翻 scale index）。
- 对照 K/V 块：1 条事实 **3.9 MB**（18 槽 × 28 层 fp32），比权重写入大 **30×**，但它是唯一能"会推理"的形态。

**一句话**：赫布写入用 0.056% 的字节换"召回"，训练用 100% 的字节换"泛化"；
省下的字节正是路由/泛化能力所在。

## 10.17 ★ 反向提取：从权重里把事实读回来（`tools/hebb_extract.py`，2026-10-23）

写入是可逆的——但只对**我们写进去的**东西成立。

### 10.17.1 原理

```
ΔB = B_edited - B_base = Σ_i c_i·v_i⊗φ_i/|φ_i|²   => rank-k (k=事实条数)
SVD: ΔB = UΣVᵀ  -> 右奇异向量 (d=1024) 过 output_norm + tied unembedding = 值 token
若给原句: 最小二乘解混 V = pinv(Φ)·ΔB  -> 每条事实单独还原
```

### 10.17.2 实测（`tools/hebb_extract.py`）

**1L18（2 条事实）**：

| 项 | 结果 |
|---|---|
| ΔB 谱 | 1.148, 0.618, 0.188, 0.141… |
| rank 估计（累计能量 50%）| **k=2**（与"最大相邻比"拐点一致，5.6× / 3.3×）|
| 值方向直接读出 | **`ĠJupiter` 82.0**、**`Ġblue` 72.1**（不需要 prompt）|
| 已知键解混 | Jupiter 53.7 / blue 49.7，各 rank 1 |
| 解混残差 | 0.695 = **4-bit 重量化噪声**的占比 |

**3k-Oly1900（3 条奥运会事实）**：

| 项 | 结果 |
|---|---|
| ΔB 谱 | 1.56, 0.277, 0.156…（相邻比 5.62）|
| rank 估计 | **k=1**（不是 3）|
| 读出 | `ĠParis` 99.8 |

**这正是 §10.11.6 同模板混淆的权重侧证据**：三条 key 的 cos≈0.98，
三个 rank-1 项几乎共线 → 能量塌到一维。**审计不用跑模型就能看出"只存住了一条"。**

### 10.17.3 基座原有的知识：提不出

| | σ 归一化 | top-2 能量 |
|---|---|---|
| 基座 `blk.18.ffn_down` | 1.0, 0.85, 0.80, 0.76… | **1.5%**（平） |
| 写入 ΔB | 1.0, 0.54, 0.16, 0.12… | **61%**（尖峰） |

训练出来的权重是**全秩分布式函数**，没有 `(φ,v)` 配对结构可分解；
配对是赫布写入强加的。基座只能做 probe / 前向查询（求函数值），不能列知识清单。

### 10.17.4 边界

| 项 | 说明 |
|---|---|
| 旋转不唯一 | `ΔB = UΣVᵀ`，任意正交混合等价；不提供键时 SVD 分量是**多条事实的混合**（1L18 的分量 0 同时含 Jupiter 和 blue） |
| 键不可直接解码 | φ 是 F=3072 的 MLP 隐向量，不是 token；还原文本需拿候选 prompt 做前向匹配 |
| 近共线 cert 病态 | key 的 cos→1 时 rank 塌陷（3k 的 k=1），**既写不进也提不出** |
| 用途 | **交付审计**：数出实际写入了几条、内容是什么、是否发生塌陷 |

## 10.18 ★ 文献对照与逐条升华（2026-10-23）

检索范围：arXiv 2026-01 ~ 2026-10 + 项目主页。**venue 状态已标注**，
预印本的结论不作为既成事实引用。

### 10.18.1 Hazy《MLPs are Hebbians》（arXiv 2607.10034，COLM 2026）

**文献说了什么**

```
构造: B = (1/F) Σ_i v_f(i) φ(k_i)ᵀ ,  φ(x)=(Ax)⊙(Gx) , A,G 随机高斯
容量: W = Θ(F log F) (信息论最优); 参数比 NTK 少 10~104×
块内: attention 给 q=k+ε, 只要 ||ε|| < sqrt(d/(F log F)) 就能取回
编辑: 整块 MLP Swapping, 10% 编辑分数 0.999 (AlphaEdit 0.550)
自述 future work: ①"直接提取/编辑预训练 LLM 里的知识" ②注意力与 MLP 如何协作
```

**升华①：我们的"地址不对"正是他们的定理边界。**
他们要求 query 是 key 的**加噪版本** `k+ε`。而我们的问句 φ 与事实 φ 是
`cos=0.098`（≈84°），**不是噪声，是另一个特征**。所以 §10.15 的失败不是实现 bug，
是"查询必须落在 key 的噪声球内"这条前提不成立。

**升华②：他们训练了 Transformer，事实是闭式的；我们反过来。**
MLP Swapping 成立的前提是：那一层本来就用同一构造训过。我们的场景是
**已训练 LLM + 闭式事实**——恰好是他们列的第①条 future work。
**结论：我们的负面结果与他们的正面结果不矛盾，是两种不同的初始条件。**

**升华③：他们把"从预训练 MLP 里提取知识"列为 open problem。**
§10.17 是对这个 open problem 的**一个实例回答**：对"闭式写入造成的低秩结构"可精确提取；
对原有权重不行（谱平，top-2 仅 1.5%）。这可以作为一个诚实的边界声明。

**升华④：他们的目标函数是 "argmax 命中"，不是"可组合"。**
`⟨MLP(k_i), v_f(i)⟩ > ⟨MLP(k_i), v_j⟩` 只要求解码排序。我们要求的
`德国 → 首都` 是**两跳**，他们的框架里没有。这解释了为什么"召回都对、
桥接全错"——两件事在他们的定义里就不是同一件。

### 10.18.2 《Knowledge Packs》（arXiv 2604.03270，预印本，单作者）

**文献说了什么**：KV–Prefix 等价（因果掩码直接推出）；700 题**零分歧**
（Qwen3-8B / Llama-3.1-8B）；省 95% token；**chat template 错会掉 6–7pp**；
另加 value-space steering（RoPE 只转 K 不转 V，中层 33–66%，方向 cos≈0 可叠加）。

**升华①：§10.14 是独立复现，且我们漏了一个交付条件。**
我们测到"逐字相同"，他们给出定理。差异：**我们用的是 raw text，他们是 chat template。**
我们的基座是 coder 模型（无指令模板）所以没事；**换 instruct 模型必须按模板构建块，否则掉 6–7pp。**

**升华②：我们的 off=8 退化不是反例。**
他们的等价要求"cache 就是真实前缀"。我们 off=8 时多塞了 8 个占位 token
进入 softmax（RoPE 只依赖相对位移，不是根因）——**违反的正是定理的前提**。
这条纠正了我们 §10.14.3 里"位置敏感"的表述：**不是位置敏感，是前缀纯度敏感。**

**升华③：V 通道是第三条写入通路，我们完全没做。**
K 决定"被检索到"，V 决定"检索到之后说什么"。对比 V 差可以改行为
（风格/价值观）且方向正交可叠加。**权重写入做不到的组合性，在 V 空间天然成立。**

### 10.18.3 SPPM：小模块训练（Zenodo 预印本，2026-05）

**文献说了什么**：每条事实 = 8 个 prefix token = **20,480 参数 / 80KB / 300 步**；
Qwen3-4B 上 100% 召回、**零交叉污染**、多事实可插拔组合。

**升华①：多事实问题的现实解不是"一条 ΔB 装 N 条"，是"每条一个小模块"。**
我们的 3k 交付审计出 `k=1`（§10.17），就是"一条 ΔB 装 3 条"的必然结果。
SPPM 用 N×80KB 换掉了这个约束。**代价从"字节"变成"训练步数"，但每条约 300 步，
在 PC 上是分钟级，在 Termux 上不可行。**

**升华②：80KB/条 vs 我们 132KB 改动字节/条——量级居然接近。**
差别不在存储，在**参数是否独立**：独立就能组合，共享 rank-k 就互相干扰。

### 10.18.4 路由与控制（DMoE / GAG / NGM / Control Architecture）

| 工作 | 做法 | 对我们的意义 |
|---|---|---|
| DMoE（2606.14243，预印本）| 专家与路由**都从底座解耦**，末层 FFN | 路由应是**显式模块**，不是 φ 相似度 |
| GAG（2601.08209，预印本）| 领域专家 → 多槽隐记忆 → 门控投影 | 与我们 §10.13 同构，但用槽而非文本 |
| NGM（2605.16893，预印本）| 无训练 n-gram 记忆，Qwen3 0.6B–14B，+0.5~1.2 | 复用自身 embedding，零新参数 |
| Control（2604.18206，预印本）| 不确定度路由 + 置信接受 + UCB 淘汰 | **直接解决我们 1954 误注入** |

**升华①：我们的 0.048 组间差，在文献里被当成"不要用相似度做路由"的证据。**
DMoE/GAG 都把路由**外置成模块**——这与我们"让模型自己按 φ 选事实不可靠"的实测一致。

**升华②：我们的阈值 0.35 是静态常数；Control 把它变成策略。**
"基线置信度 ≥ τ 就不查记忆；查了要和基线比边际；持续有害的条目淘汰"——
这套状态机比单一阈值健壮，而且**完全不需要训练**，明天就能实现。

### 10.18.5 三条路线的最终定位

| 路线 | 代表 | 能召回 | 能组合/推理 | 能泛化 | 工件 |
|---|---|---|---|---|---|
| 闭式权重写入 | 本项目 hebb / Hazy | ✓ | ✗ | ✗ | 132KB 改动字节 |
| 闭式 KV 前缀 | 本项目 §10.14 / Knowledge Packs | ✓ | ✓（块内） | ✗ | 3.9MB / 条 |
| 小模块训练 | SPPM / DMoE | ✓ | ✓（可插拔） | 有限 | 80KB / 条 + 300 步 |
| 全量训练 | — | ✓ | ✓ | ✓ | 100% 权重 |

**一句话**：闭式写入把"知识"从训练里拿出来了，但只拿出来了**存储**这一半；
**寻址（路由）和组合**仍然要么靠注意力（KV），要么靠小模块。

## 10.19 控制层与分解式桥接（2026-10-24）

### 10.19.1 先记一个失败的控制信号：平均 logprob 边际

对 10 条 FIFA 事实强制走记忆路径，记录 `mem_lp - base_lp`：

| 年份 | 是否答对 | d = mem−base |
|---|---|---|
| 1966 London | ✓ | **−0.17** |
| 1962 Santiago | ✓ | −0.02 |
| 1974 Berlin | ✓ | +0.11 |
| 1986 复读 | ✗ | **+0.18** |
| 1994 复读 | ✗ | +0.10 |

**边际与正确性无关，甚至反相关**：正确回答（London）因为短促而 logprob 低，
错误复读（" 1986 FIFA World Cup was held…"）因为流畅而 logprob 高。

> 这是 §11.3 的又一次实例：**流利度不是正确性**。用它做"接受/回滚"会
> 系统性地保留复读、丢弃正确答案。**该信号作废，已从默认路径移除。**

附带发现：`base_lp` 十条完全相同（−0.51），因为 context 只是检索键、
不进 prompt，基线对同一句问题只能答同一句。**"这条问的是哪一年"这件事
根本不体现在基线置信度里**——所以用置信度当路由是结构性错位。

### 10.19.2 分解式：记忆只做第一跳

联合式把两跳压进一个 prompt：`(年份→国家)` 与 `(国家→首都)`，
模型在事实边界上会把"that country"解错（1986/1994 的输出都在**复读事实本身**）。

分解式把第二跳交还模型：

```
记忆:  年份 --检索(sim 1.00)--> 国家
模型:  "The capital of {国家} is" --> 首都
```

两种陈述式模板（基座是 completion 模型，疑问句只会续写问句）：

```
"The capital of {v} is"       9/10  (失败: Sweden→Gothenburg)
"{v}'s capital city is"       9/10  (失败: Chile)
```

**失败项互补** → 两路并行的上限高于单路。

### 10.19.3 双向一致仲裁

两模板的首实体不一致时，才做一次反向校验：

```
"<候选> is the capital of"  → 是否回到该国家?
Stockholm   → " Sweden"      ✓
Gothenburg  → " the land of" ✗    (乱码 = 模型不认)
```

只在冲突时触发（10 条中 2 条），成本 +1 次生成。修复 Sweden（选用模板 2 的
"called Stockholm"），未被其他条目污染。

### 10.19.4 结果

| 集合 | 联合式 | 分解式 | 分解+仲裁 |
|---|---|---|---|
| FIFA 10 条（调参集）| 8/10 | 9/10 | **10/10** |
| 夏季奥运会 10 条（**留出集**）| — | 10/10 | **10/10** |
| 无关问句 | 不注入 ✓ | 不注入 ✓ | 不注入 ✓ |
| 库外年份 1954 | 不注入 ✓ | 不注入 ✓ | 不注入 ✓ |
| 直接召回 3/3 | ✓ | ✓ | ✓ |

留出集里 Ottawa 由模板 2（"called Ottawa"）取到——模板 1 给的是别的城市，
说明"两模板并行"不是冗余，是必要。

### 10.19.5 噪声声明（§11.4，必须写）

```
n=10, M = 2.8*sqrt(0.8*0.2/10) = 0.354  → 35pp
8/10 -> 10/10 的变化在噪声内，不构成统计显著。
```

**可宣称的是机制，不是幅度**：联合式的两次失败在输出层面**可观测地**是
复读事实（echo），分解后该现象消失；这是因果链，不是分数比较。

留出集与调参集**同构**（同属性 capital、同模板形状），它只证明
"没有只在这 10 条上过拟合"，**不证明跨属性泛化**（未测 currency/人口等）。

### 10.19.6 边界（这决定它是不是"记忆"）

```
端到端 = 检索准确率 × 模型对第二跳的掌握
```

- 第二跳的上限是**模型自身知识**：Sweden→Gothenburg 是模型错，不是记忆错。
  赫布写入/KV 注入都不能修这个（§10.15 已证明写不进去）。
- 分解需要**属性模板**（本版只有 `capital`）。问句里没有已知属性时退回联合式，
  并标记 `joint-echo`。**这是当前最大的未覆盖面。**
- 检索仍是词面 IDF+bigram，不做语义泛化（"那个国家"不能跨句式）。

### 10.19.7 与文献的对应（§10.18）

- 这是 Control Architecture（2604.18206）"二次通过"的一个变体，
  但**触发条件不是置信度，而是"问题里存在需要消解的指代"**——
  因为 §10.19.1 证明了置信度在这里没有区分力。
- 与 SPPM 的区别：SPPM 训练 8 个 prefix token 把"国家"也塞进模型；
  我们把第二跳留给模型，**存储成本为 0，代价是第二跳不能超过模型自身知识**。

## 10.20 V 通道对比写入（行为引导，2026-10-24）

依据 §10.18.2（Knowledge Packs）：RoPE 只转 K 不动 V，所以 V 是"无位置"的语义通道。
本节验证这条通路在我们的 0.6B Q4T 上是否成立，以及**能测到哪一层**。

### 10.20.1 接口

`q1t_stream.forward(..., v_delta={layer: (idx, ΔV)})`：在当前 forward 的 V 上叠加
`ΔV`（`idx=None` = 所有位置；预填时只加最后一个位置）。δ 由对比对在该层的
**最后一个位置**取均值差得到：

```
δ_L = mean(V_L[-1] | 正面/法语句) − mean(V_L[-1] | 负面/英语句)
```

### 10.20.2 先记一个失败：自由生成不能当判据

用情感词表数 24 token 续写的极性：α ∈ {−4…+4} 的均值在 −0.17 ~ +0.83 之间摆动，
**12 个样本里 9 个是 0**（续写里根本没出现情感词）。0.6B coder 基座在
"The film was" 之后写的是"上映年份/制片人"，不是影评。

> 这不是"没有效应"，是**判据没有分辨力**（§11.3 第三类：便宜且无关）。
> 换成**确定性 logit 探针**：同一位置的 `logit(" good") − logit(" bad")`，零采样噪声。

### 10.20.3 结果 A：情感方向（层扫描，4 个留出句均值）

| layer | 深度 | α=−4 → +4（good−bad） | Δ |
|---|---|---|---|
| 8  | 29% | +1.77 → +1.74 | −0.03 |
| 12 | 43% | +1.63 → +1.80 | +0.17 |
| 14 | 50% | +1.96 → +1.58 | −0.37 |
| 16 | 57% | +1.29 → +2.04 | +0.75 |
| **18** | **64%** | **+0.22 → +3.29** | **+3.07** |
| 20 | 71% | +1.88 → +1.63 | −0.25 |
| 22 | 79% | +1.66 → +1.87 | +0.21 |

**只有层 18 有强效应**，且逐点近似线性（每单位 α 约 +0.36~0.38）。
64% 深度正好落在文献报告的 33–66% 区间内。

### 10.20.4 结果 B：特异性（层 18）

| 对比 | Δ（α=−4→+4） | 说明 |
|---|---|---|
| good / bad | **+3.07** | 两词都**未**参与构建 |
| positive / negative | **+2.42** | 两词都**未**参与构建 |
| great / terrible | +3.02 | 词已见（great/terrible） |
| wonderful / awful | +3.12 | 词已见 |
| the / a | +0.27 | 中性对，不动 |
| cat / dog | +0.57 | 无关对，不动 |
| blue / red | +0.06 | 无关对，不动 |
| 异属性 δ（long/short）作用于 good/bad | −0.47 | 不迁移 |

### 10.20.5 结果 C：语言方向（同一接口，换对比对）

δ 由 6 对法/英同义句构建，探针 `logit(" le") − logit(" the")`：

| layer | Δ | |
|---|---|---|
| 8/12/16/20 | +0.04 ~ +0.07 | 无 |
| **18** | **+4.53** | 强 |
| 22 | +0.26 | 弱 |

`et − and` 同向（+2.49）。**层 18 是两条通路的共同写入点。**

### 10.20.6 结果 D：正交与对照（层 18）

| δ | good−bad Δ | le−the Δ |
|---|---|---|
| 情感 δ | +2.57 | −0.36 |
| 语言 δ | −0.25 | +4.16 |
| 随机 δ（同范数）| +0.36 | +0.22 |

`cos(情感 δ, 语言 δ) = 0.012`，`cos(情感 δ, 随机) = −0.011`。
**两条方向近似正交 → 可叠加**（与 Knowledge Packs 的 "cos≈0 可组合" 一致）。

### 10.20.7 失败了两次的对照设计（§11.8 教训）

第一次写的"打乱标签"对照**数学上恒等**：

```
mean(V_pos_i) − mean(V_neg_j) 与配对无关
=> 打乱标签后 δ 完全不变, 这个对照不可能失败
```

真正的对照必须是：① 随机 δ（同范数）② 异属性 δ（long/short）③ 交叉探针。
三者都通过，上面的效应才算成立。

### 10.20.8 边界：logit 层成立，行为层未观测到

- 生成层（α∈{0,2,4,6,8}，T=0.8，3 seeds）：法语功能词占比 0.00 → 0.15 → 0.00，
  且 α≥6 输出崩成乱码（"unta, que, una" / "ench, lived Sixy"）。
- 结论：**这个 0.6B 基座在方向变成连贯行为之前就先退化了。**
  能交付的是**logit 级旋钮**（可用作打分/重排/拒答），不是行为层。
- 与权重写入（§10.16）的差别：V 通道不碰模型字节，**零工件、可开关、可叠加**；
  代价是只在 L18、只在线性探针上可验证。

### 10.20.9 与文献的对应

| 文献结论 | 我们的复现 |
|---|---|
| RoPE 只转 K → V 可加 | ✓（δ 在 V 上直接生效） |
| 中层 33–66% 最有效 | ✓（层 18 = 64%，其它层≈0） |
| 方向近似正交可组合 | ✓（cos=0.012） |
| 对比差可改行为 | **⚠ 仅 logit 层**，行为层因基座容量未观测到 |

## 10.21 方向读出：候选重排（2026-10-24）

§10.20 用的是**干预**（V += α·δ，改输出分布）。本节用**读出**：
`score = mean_t(V_t · u)`，`u = δ/‖δ‖`。**模型字节、计算图、生成过程都不变**，
每个候选只多一次 forward。

### 10.21.1 先记一个没有分辨力的测法

第一版用"采样 8 条续写，投影 vs 词表极性"：合并 n=32，
`rho=+0.16`，随机方向 `rho=+0.11` — **无差异**。
原因还是标签方差：32 条续写里只有 4 条含情感词（0.6B coder 不写影评）。

> 判据本身没有方差时，相关性没有意义（§11.4）。换**构造句**：标签由人给定。

### 10.21.2 结果 A：句级分类（12 正 / 12 负，主题互不相同）

| 读数 | AUC | 正类均值 | 负类均值 |
|---|---|---|---|
| mean over tokens | **1.000** | +0.12 | −0.14 |
| last token | **1.000** | +0.07 | −0.34 |
| 随机方向（同范数）| **0.431** | — | — |

12 对逐句差值全部为正（+0.210 ~ +0.290），**没有一条反例**。
正负句共用骨架、只换情感词与主题，方向能把两者完全分开。

### 10.21.3 结果 B：重排

每组 4 个候选（2 正 2 负，跨主题），按投影降序取第一：

```
命中 6/6  (随机期望 3/6)
top-1 与末位的 margin: +0.261 ~ +0.352
```

### 10.21.4 这个能力值多少（诚实评估）

- 候选集**极易分**（AUC=1.0），所以 6/6 不证明它在难任务上也行；
  **混合情感**（"环境好但服务差"）未测。
- 真正的新东西是**成本结构**：重排不需要生成，每候选 1 次 forward；
  干预需要完整解码，且 α≥6 就崩（§10.20.8）。
  **读出比干预稳得多**：不碰分布，只排序。
- 方向仍是一维的：换属性（正式/简洁/代码/自然语言）要重新构建 δ，
  但流程相同，且 §10.20.6 已验证不同属性的 δ 近似正交（cos=0.012），
  **可分别打分或用线性组合**。

### 10.21.5 与知识写入的关系（不要混淆）

| | 知识（§10.10–10.19）| 行为/风格（§10.20–10.21）|
|---|---|---|
| 写入位置 | FFN 权重 / KV 前缀 | V 通道方向 |
| 零训练 | ✓ | ✓ |
| 可交付工件 | GGUF / `.kvblk` | **无**（运行时一个向量）|
| 能改变"答什么" | ✓（事实）| ✗ |
| 能改变"怎么答" | ✗ | ✓（语气/措辞）|
| 可组合 | ✗（§10.15）| ✓（正交方向）|

**结论**：这两条通路解决的是不同问题，不能互相替代。
"让模型知道 1974 年世界杯在德国" 只能用知识通路；
"让回答更积极" 只能用 V 通道。

## 10.22 读出方向的边界：混合、否定、强度（2026-10-24）

§10.21 的 AUC=1.000 是在"单极性、单子句"的句子上得到的。本节压测三种更难的输入，
目的不是再刷一个分数，而是**划出这个线性方向管什么、不管什么**。

### 10.22.1 混合情感（两子句各含正负词，只改主从顺序）

```
"The service was awful but the food was delicious."   主句=正
"The food was delicious but the service was awful."   主句=负
```

词袋极性恒为 0（每句一正一负），所以**任何词袋式读数都只能得 0.5**。

| 指标 | 结果 |
|---|---|
| 逐对胜出（主句正 > 主句负）| **9/10** |
| AUC | 0.950 |
| 唯一失败 | "The staff were helpful although the wait was long."（−0.051 vs +0.013）|

**结论：读数跟随主句，不是词袋。** 但 `although` 这种后置从句会翻车一次，
说明语篇连接词没有被完全编码进这一维方向。

### 10.22.2 否定（线性探针的经典失败模式）

| 对 | 肯定 | 否定 |
|---|---|---|
| The meal was good / not good | +0.092 | −0.054 |
| I liked the film / did not like | +0.056 | −0.112 |
| The staff were helpful / not helpful | +0.067 | −0.082 |
| The room was clean / not clean | +0.015 | −0.064 |
| The story was interesting / not interesting | +0.105 | −0.039 |

**5/5 正确**（随机 1/2，p≈0.03）。词袋读数在这里会打成平手，
所以这一维确实承载了"否定后的语义"，不只是关键词。

### 10.22.3 强度（这里失败）

```
"The meal was slightly good / good / extremely good / amazingly good."
"The meal was slightly bad  / bad  / extremely bad  / amazingly bad."
```

| | slightly | — | extremely | amazingly |
|---|---|---|---|---|
| 正面 | +0.042 | +0.092 | +0.081 | +0.098 |
| 负面 | −0.088 | −0.109 | −0.086 | −0.059 |

**不单调**，且正面在 "good" 之后几乎不再增长；负面反而在高强度处**回落**。

> 解释：RMSNorm 会归一化残差尺度，强度信息要么不在这一维，要么被归一化抹掉。
> **这个方向是极性轴，不是强度轴。** 需要强度时得另找方向（如构建
> "extremely good vs good" 的对比对），不能指望把 α 调大。

### 10.22.4 边界总结

| 输入类型 | 是否可用 | 证据 |
|---|---|---|
| 单句单极性 | ✅ 完全可分 | AUC 1.000 (n=24) |
| 两子句混合、主从清晰 | ✅ 基本可用 | 9/10 (n=10) |
| 否定 | ✅ 可用 | 5/5 (n=5) |
| 强度/程度 | ❌ 不可用 | 非单调 |
| 语篇连接词（although 后置）| ⚠ 会翻车 | 1 例 |
| 长文/多段 | 未测 | — |

**噪声声明**：n=10 与 n=5 的集合只能做方向判断；9/10 的 p≈0.011，
5/5 的 p≈0.031，都不足以支撑"稳定的 95%"这类表述。

## 10.23 属性模板扩展：currency / language / continent（2026-10-24）

§10.19 的分解式只覆盖 `capital`。本节把"属性"做成注册表，
**记忆仍只做第一跳（年份→国家），第二跳全部交给模型**，看它能延伸到多远。

### 10.23.1 属性注册表

```python
ATTR_TEMPLATES = {
  "capital":   ["The capital of {v} is", "{v}'s capital city is"],
  "currency":  ["The currency of {v} is", "{v}'s currency is"],
  "language":  ["{v}'s official language is", "The official language of {v} is"],
  "continent": ["{v} is located in the continent of", "The continent of {v} is"],
}
REVERSE = {"capital": "{c} is the capital of",
           "currency": "{c} is the currency of",
           "language": "{c} is the official language of"}
```

- 属性由问句关键词识别（capital/currency/language/continent）。
- 两个模板并行；首实体冲突时用反向模板仲裁（continent 没有干净的反向关系，跳过）。
- 模板不是猜的：先在 4 国上试跑，`The continent of {v} is` 会答成
  "a place of many rivers"，换成 `{v} is located in the continent of` 才可用。

### 10.23.2 结果（10 国 × 4 属性）

| 属性 | 命中 | 失败项 |
|---|---|---|
| capital | **10/10** | — |
| currency | **8/10** | Italy→lira、Germany→mark |
| language | **9/10** | Italy→"Romance language" |
| continent | **8/10** | Mexico→South America、Spain→South America |
| 四属性全对 | **6/10** | — |

（检索侧全部 sim=1.00、10/10 命中，所以差异**全部来自第二跳**。）

### 10.23.3 失败的性质：全是模型知识，且是"过期知识"

- Italy/Germany 的货币错误（lira/mark）不是随机错，是**欧元前的知识**。
  模型知道这两个国家，但知识停在旧年份。
- Spain→South America、Mexico→South America 是**地理混淆**（西班牙语国家 →
  南美），不是检索错。
- Italy→"Romance language" 是把属性答成了语系。

**这一类错误，权重写入/KV 注入/方向读出都修不了**（§10.15 已证明闭式写入
无法改变既有回答）。要修只能训练（SPPM 的 300 步/条）或换更大的基座。

### 10.23.4 一次打分口径事故（必须记）

第一版用**整段 24 token 做子串匹配**，得到 4 属性全 10/10。
那是假阳性：Italy 的 currency 先说 `lira`，后文继续生成时才出现 `Euro`，
子串匹配就判对了。

改为 **只取前 6 个 token** 后真实结果是 8/10、9/10（currency 的
`U.S. dollar` 还会被 `U.S.` 的句点切断，所以最终用 token 数而不是句号）。
（`U.S. dollar` 里 `U.S.` 的句点还会把按句切分切断，所以最终用 token 数而不是句号。）

> 又一次验证 §11.4：**指标口径比模型能力更容易出错**，而且错的方向总是"更好看"。

### 10.23.5 结论

```
端到端 = 检索（10/10）× 第二跳（capital 100% > language 90% > currency 80% = continent 80%）
```

分解式不依赖第二跳的具体内容，**换属性只需加模板**；
天花板由基座对"国家→属性"的掌握决定，可以逐属性测量、逐属性定价。

## 10.24 第二个方向：代码 vs 散文（2026-10-24）

§10.20–10.21 只用"情感"一个方向。本节用**完全相同的流程**建第二个方向，
检验它是不是可复用的机制，而不是对情感词表的偶然拟合。

### 10.24.1 构建

对比对 = 同一意图的两种形态（代码 / 散文），8 对：

```
"def add(a, b):\n    return a + b"
vs "To add two numbers, write a function that returns their sum."
```

方向 δ 仍取 V 在最后一位置的对比均值差，层仍是 18。

### 10.24.2 结果

| 判据 | 值 | 对照 |
|---|---|---|
| 构造句 AUC（10 code / 10 prose，主题互不相同）| **1.000** | 随机方向 10 次：mean 0.531，max **0.940**，0 次达 1.000 |
| token 数基线 AUC | 0.740 | 代码带换行/缩进，**长度本身有判别力** |
| 长度方向 δ（long/short 散文对）作用于 code/prose | **0.570** | 不是长度代理 |
| cos(style δ, length δ) | **0.036** | 正交 |
| 重排（每题 4 候选，1 code + 3 prose）| **6/6** | 随机期望 1.5；随机方向 0/6 |

### 10.24.3 怎么读这张表

- **随机方向 AUC 方差很大**（0.09–0.94，mean 0.53）。所以"随机 0.70"那一次
  只是抽样波动，不是"任何方向都能分开"。10 次随机里**没有一次到 1.000**。
- **长度这一项必须交代**：token 数基线就有 AUC 0.740（代码的换行/缩进 token 更多），
  所以"能分开 code/prose"这件事本身不稀奇。真正说明问题的是
  **长度方向 δ 作用其上只有 0.570**、且 **cos=0.036** ——
  这个方向抓的不是长度，是"形态"。
- **重排的候选集是 1 code + 3 prose**，所以随机期望 1.5/6。
  6/6 对 1.5/6 的 p = 0.25⁶ ≈ 0.0002。

### 10.24.4 结论

**流程可复用**：换一组对比对 → 换一个方向 → 同样的三步
（构建 δ → 构造句 AUC + 随机/长度对照 → 重排）。
已验证两个互不相关的方向：

| 方向 | 留出词对 AUC | 与另一方向 cos |
|---|---|---|
| 情感 | +3.07（good/bad）| 0.012（与语言）|
| 语言 | +4.53（le/the）| 0.012 |
| 代码/散文 | 1.000（AUC）| 0.036（与长度）|

**仍不解决的事**（回到 §10.21.5）：这些方向改的是"怎么答"，
改不了"答什么"。事实注入仍然只能靠 FFN 权重或 KV 前缀。

## 10.25 为什么 V 通道方向烘不进 GGUF（2026-10-24）

§10.20–10.24 的方向目前只能运行时用。想做成交付物（像赫布写入那样烘进模型），
先要回答"这个方向在权重里对应什么"。

### 10.25.1 理论上等价于注意力输出偏置

V 上的常数偏移 `V_t += δ`（所有位置）经注意力求和后变成：

```
attn_out_L = Σ_t a_t (V_t + δ) = Σ_t a_t V_t + (Σ_t a_t) δ
                                     └──────┬──────┘
                                   位置相关的标量 × δ
```

即：**等价于在注意力输出上加一个"每位置一个标量"的 δ 偏置**。
若注意力分布接近均匀，就近似一个常数偏置。

### 10.25.2 但 Q4T 格式没有 bias 张量

实测基座张量表（`read_packslim`）：

```
n_tensors 196
bias: []            ← 没有任何 bias
blk.0: attn_k / attn_output / attn_q / attn_v / ffn_down / ffn_gate / ffn_up  (全 weight)
```

没有 bias 就没有位置可塞常数项，而 GGUF/llama.cpp 的计算图也不读 bias。
**结论：要烘进模型就得改格式 + 改加载器 + 改 Q4T 重打包器**，代价远超
"一个向量"本身。

### 10.25.3 另一条思路及其代价

想用 FFN 制造常量偏移：FFN 输出是 `W_down · act(W_up·rmsnorm(x))`，随位置变化，
要在所有位置产出同一向量需要 bias（同样没有）。
或走 `ffn_up` 的"常数激活"（SiLU 在 0 处导数非零 → `u≈0` 时 `g≈0`，
但 `g/(1+exp(-g))` 的 1/2 项仍产生偏置）——这需要精确的定点改写，
且 §10.14 已记录 `QXN_GGML=1` 破坏收敛。**不划算。**

### 10.25.4 结论

**方向读出/干预是运行时能力，不是交付物。**
它的价值在：候选重排（每候选 1 次 forward）、答案后处理、拒答/打分，
而不是"改模型"。要交付"改模型的风格"，只有训练（LoRA/小模块）那条路。

## 10.26 ★ 多事实（不同模板）：能做，但代价随事实数上升；并**推翻旧交付的"干净"结论**

### 10.26.1 把问题精确化

§10.11.6 判死的是"**同模板**只差一个 token"（cos 0.98）。**没测过**的是
"**不同模板**的多条事实"（1L18 只验证过 2 条）。

预筛 16 条候选事实（模板各不相同），实测这些 key 之间 φ 的两两 cos：

```
min 0.364   mean 0.568   max 0.826
```

比同模板的 0.98 好一个数量级 —— 条件完全不同，值得单测。

基座预筛：16 条里 **15 条 base rank>0**（即基座不认识，写入不是空转）；
只有 `Au`（金的化学符号）base 已经知道，被剔除。

### 10.26.2 新工具

`tools/hebb_multifact.py`

```
--prescreen              基座知识预筛 + φ 两两 cos
--build --layout layers|single --orth --c-list ...
--verify <gguf>          事实 rank / 串扰 / holdout 污染
```

### 10.26.3 布局：同样的振幅，铺到更多矩阵损伤更大

同一事实集、c=60、总振幅都是 300：

| 布局 | 碰几个矩阵 | rank0 | 串扰 | holdout 污染(6条口径) |
|---|---|---|---|---|
| `single`（全写层 18）| 1 | 4/5 | 0 | **0/6** |
| `layers`（每条一层，18-22）| 5 | 4/5 | 0 | 1/6 |

⇒ 与 §10.9.2「层数有独立效应」一致：**同样振幅，碰更多矩阵 → 损伤更大**。

### 10.26.4 ★ 正交化（`--orth`）：去掉 φ 的共性分量

动机是 §10.11.6 的反面：那里去混淆失败，是因为"模板共性**既是**泛化来源
**又是**混淆来源"。但**多事实场景不需要改写泛化**（每条事实只用原句问），
所以把共性分量正交掉是**纯赚**。

做法：逐层，对其它事实的 φ 做一次 Gram-Schmidt。

| 配置（同 c=60, single）| rank0 | 串扰 |
|---|---|---|
| 无 orth | 4/5 | 0 |
| **有 orth** | **5/5** | 0 |

注意一个反直觉的副作用：`1/|φ|²` 归一化让 `|φ|` 变小反而**放大**写入幅度
（|ΔB| ∝ c·|v|/|φ|），所以加 orth 后要**同时降 c**（60 → 45）才不污染。

### 10.26.5 ★★ 推翻旧结论：6 条 holdout 不够，采样口径也不够

**旧口径**：6 条 holdout + 采样（T=0.01）→ 1L18 判"2/2 rank 0 + holdout
**0/6 逐字一致**"，`hebb_deliver.py` 也按这个口径打印 PASS。

**新口径**：20 条 holdout + **贪心解码**。

```
基座自身 换 seed(0 vs 1) 就差 1/20   → 采样口径的噪声底 5%
贪心解码噪声底 0
1L18 在新口径下: 6/20 不同 (其中 3 条是复读退化)
```

⇒ **"交付件 0/6 污染"是 6 条样本的假象，不是方法干净。**
§10.9 的"干净窗口"定义（2/2 rank 0 且 holdout 0/6）同样要按新口径重算；
`tools/hebb_verify.py` 已改为 20 条 + 贪心。

### 10.26.6 最终结果表（20 条 holdout, 贪心）

| 交付 | 事实数 | rank0 | 含值 | 串扰 | holdout 污染 | 其中复读退化 |
|---|---|---|---|---|---|---|
| `rStar-Coder-hebbit-1L18` | 2 | 2/2 | 2/2 | 0 | 6/20 | 3 |
| **`rStar-Coder-hebbit-multi5`** | **5** | **5/5** | 5/5 | **0** | **7/20** | 2 |
| `rStar-Coder-hebbit-multi8` | 8 | 7/8 | 8/8 | 0 | 10/20 | 4 |

- `multi5`：5 条事实**全部 rank 0、零串扰**，比 2 条只多 1/20 污染 → **性价比最好**
- `multi8`：8 条中 7 条严格 rank 0（`franc` rank 1，但生成里是 "the franc franc"，
  语义正确）；污染升到 10/20，**边际代价明显变陡**
- 8 条无 orth 时出现过**语义串扰**（blue 的答案里混进 nitrogen）→ orth 修掉了

### 10.26.7 "污染"这个指标本身要打折看

20 条里 3 条是**复读退化**（rep 1→3/4），其余是 token 级差异；
而基座在这些提示上的输出本来就是垃圾（`' 1] 22233445'`、`' 2344445
45'`）。

⇒ 「污染」把"两份垃圾之间的差异"也算进去了。**要量化真实损伤需要语义级判据**
（可执行 / 不执行），这是待办（侧支 #35）。

### 10.26.9 ★ 噪声底自查：上表多数差异**不可分辨**（§11.4）

`M = 2.8·sqrt(p(1-p)/n)`（95% 最小可分辨差异）：

| 比较 | 观察差 | 噪声底 M | 判定 |
|---|---|---|---|
| rank0：无 orth 4/5 vs 有 orth 5/5 | 20pp | n=5, p=0.8 → **50pp** | **不可分辨** |
| 污染：1L18 6/20 vs multi5 7/20 | 5pp | n=20, p=0.3 → **29pp** | **不可分辨** |
| 污染：1L18 6/20 vs multi8 10/20 | 20pp | 29pp | **不可分辨** |
| 污染：multi5 7/20 vs multi8 10/20 | 15pp | 29pp | **不可分辨** |

配对视角（同一批提示，base vs edited）也不救：污染集中在**同样那几个提示**上
（`for i in range` / `with open` / `return [x*2` / `for k,v`），multi8 比 multi5
多污染 3 条，配对符号检验 p≈0.25。

⇒ **必须降级的说法**：
- ❌「orth 把 4/5 提到 5/5」→ 只能说"未观测到差异"
- ❌「8 条边际代价变陡」→ **未观测到差异**（20pp < 29pp）
- ✅ 仍然成立的是**方向性观察**：多事实配置**没有**出现串扰（0/5、0/8，两处独立
  配置），且 §10.26.5 的"1L18 是 6/20"是**相对基座自身**的对照（base 换 seed
  差 1/20，贪心 0）——这条比较是干净的。

⇒ **真正的缺陷是 holdout 样本量**：20 条无法给 5~6pp 的差异定级。
要分辨"多几条事实多 3 条污染"这种量级，配对设计大约需要 **80~100 条提示**
（McNemar: b≈10, c≈2 才到 p<0.05）。**下一步必做**（侧支 #35）。

### 10.26.8 结论

1. **不同模板的多事实可以做**：5 条全部命中、零串扰，污染只比 2 条多 1/20。
2. `--orth` 是关键技巧：**多事实场景不需要泛化 → 共性分量可以正交掉**。
3. 成本曲线：2 条 6/20 → 5 条 7/20 → 8 条 10/20。**到 8 条边际代价变陡**。
4. **旧的"0/6 干净"结论作废**，诚实口径是 20 条 + 贪心。
5. 同模板多事实仍然不可解（§10.11.6 不变）：cos 0.98 时正交掉共性等于删掉事实本身。

## 10.28 ★ 用新口径重测"论文白化"，并给出它的机制（2026-10-24 深夜）

§10.9.4/10.9.5 的结论（"白化大幅优于我们的单点归一化"、"干净窗口整体上移加宽"）
**是用 6 条 holdout 测的**——§10.26.5/§10.27 已证明这个口径会漏判。

### 10.28.2 机制：白化方向是"稀有方向"，稀有到近乎噪声

⇒ `cov` 秩 ≤ 30，**零空间有 3042 维**，白化把这些方向放大 1/λ。
结果：写入方向主要落在**辅助集的零空间**里 →

- 对代码提示几乎不激活 → **通用行为损伤小**（6/106）✓
- 但也不携带"这条事实"的语义分量 → **召回弱**（rank 9）✗
- 振幅越大越糟：c=80 → 2/5、c=150 → 1/5（**放大噪声反而压过事实**）

这与 §10.9.6「论文 raw_readout 在 Q4T 上不可用」是同一类问题的两面：
**在 F=3072、辅助集几十条的条件下，白化缺少足够的统计支撑。**

## 10.29 ★ 收缩主方向：假设被证伪 + 全部配置的定稿对比（2026-10-24 深夜）

### 10.29.1 假设

§10.28.2 观察到：白化方向"稀有 → 不伤通用行为"。反推一个可检验的假设：

> **写入方向的损伤来自它落在"典型事实句"子空间（辅助集 cov 的主方向）里。
> 那么压低主方向（不取逆、不放大噪声）应该既保召回又减损伤。**

做法：`cov` 的特征分解，取前 k 个主方向 `e_j`，把 φ 的该分量乘以 s（0=全压低）：

```
φ_shrunk = φ − (1−s)·Σ_{j≤k} (φ·e_j) e_jᵀ
```

（cov 谱：主方向 1383，次之 135/115/77/73，**99% 特征值 ≈0**，秩 ≤30）

### 10.29.2 结果（106 条 holdout，配对 McNemar）

| 配置 | 事实 rank0 | 逐字不同(106) | vs multi5 |
|---|---|---|---|
| multi5（norm+orth，基线）| 5/5 | 28 | — |
| orth + shrink(k=8, s=0.2) | 5/5 | 32 | b=10 c=6 **p=0.45 不显著** |
| shrink only(k=8, s=0.2) | 5/5 | 37 | b=13 c=4 **p=0.049 略差** |
| orth + shrink(k=32, s=0.0) | 4/5 | **64** | b=45 c=9 **p<0.0001 明显更脏** |

⇒ **假设被证伪**：压低主方向**没有**减少损伤（32 vs 28，不可分辨），
纯收缩甚至更脏；压得越狠（k=32, s=0）**严重更脏**（64/106）。

**推论**：**损伤不是"方向落在主子空间"造成的**。
（§10.28.2 的解释因此也只对了一半：白化之所以不伤，可能不是因为"稀有"，
而是因为它把写入变成了一个**近乎随机、且几乎不与任何实际提示相关的方向**——
但**这个方向也召不回事实**（blue rank 9），机制**尚未解释**（侧支 #39）。）

## 10.30 ★ 侧支 #39 结案：白化的"低损伤"是归一化 bug 的假象（2026-10-24 深夜）

### 10.30.1 数学：白化让读出系数偏离 1

写入形式 `ΔB = outer(pk, c·v)/‖pk‖²`。在**事实自己**的 key 上，读出是

```
read = φ·pk / ‖pk‖² · c·v  =  r · c·v
```

- `pk = φ`（不白化）⇒ `r = 1`，读出**恒为 c·v**（这就是单点归一化的全部作用）
- `pk = φWt`（白化）⇒ `Wt` 不幂等 ⇒ `r = (φWtφ)/(φWt²φ) ≠ 1`

### 10.30.2 实测 r：随事实剧烈漂移（层 18，λ=0.1）

| fact | r | φ 在辅助子空间占比 | 后果 |
|---|---|---|---|
| Jupiter | **0.10** | 0.99 | 衰减 10× |
| blue | **0.10002** | 0.43~0.59（零空间为主）| **衰减 10×** → 召不回 |
| Africa | **12.6**（层 22 达 **55**）| **1.000**（落在辅助子空间）| **放大 12~55×** → 多事实时泄漏 |

两条渐近线：φ 落在零空间 ⇒ `r ≈ λ`；φ 落在特征值为 μ 的方向 ⇒ `r ≈ μ`。

**这同时解释了 §10.28.3 的多事实白化灾难**：Africa 被放大 55× →
"串扰 3~4/5、污染 20/20"不是白化的性质，是**非洲那条事实被放大了两个数量级**。

### 10.30.3 修法：分母改用 `φ·pk`

对任意 `pk`，取分母 `φ·pk` 则 key 上读出**恒为 c·v**：

```
ΔB = outer(pk, c·v) / (φ·pk)
```

`hebb_deliver_build.py --norm-key`（默认关，不影响历史可复现）。

### 10.30.4 结果：修好后**召回回来了，优势也消失了**

| 配置 | 事实 rank0 | 106 条损伤 | vs 旧白化 |
|---|---|---|---|
| 旧白化（分母 ‖pk‖²）| **1/2** | **6** | — |
| 白化+`--norm-key` c=24 | **2/2** | **29** | p<0.0001 **显著更脏** |
| 白化+`--norm-key` c=80 | 2/2 | 62 | 灾难 |
| norm 18-22（2 条 c=24）| 2/2 | 21 | — |
| multi5（5 条，norm+orth）| 5/5 | 28 | p=1.00 不显著 |

**结论（推翻 §10.28.1 与 §10.29.2 的解释）**：

> 白化的 6/106 **不是"方向稀有所以不伤"**，而是**写入被衰减 10 倍、几乎没生效**。
> 把强度修正到设计值后，白化的损伤与 norm 相同（29 vs 21，p=0.13），
> **召回与损伤都不比我们的单点归一化好**。论文白化在这个注入场景下**没有优势**。

### 10.30.5 修正表（今晚第二次主动推翻自己的结论）

| 原说法 | 位置 | 实际 |
|---|---|---|
| "白化显著更干净（6/106），是低损伤/弱召回的取舍点" | §10.28.1 | **假的**：那是 10× 衰减，不是方向性质 |
| "损伤不是主子空间造成的"推理，"白化不伤因为稀有" | §10.29.2 | 同上，机制解释作废 |
| "多事实白化失败因为需要多个稀有方向" | §10.28.3 | 真因是 **Africa 被放大 55×** |
| 论文白化"全面更优"/"干净窗口上移" | §10.9.4/10.9.5 | 从未在正确强度下成立过 |

**仍未跑**：5 条事实 + `--norm-key` 的白化。按 2 条的结果（无优势）预期与 multi5 等价；
如实测更优再改交付。

## 10.31 运行时记忆层的规模与脆弱性（2026-10-24 夜）

**背景**：§10.19 的分解式记忆层只在 10 条 FIFA + 10 条留出集上验过。
本节测 159 条真实事实 + 841 条干扰事实（至 1000 条），检索引擎**与模型无关**
（IDF 加权 token/bigram 重合），所以规模测试是纯字符串运算。

### 10.31.1 检索命中率（N=1000，只查询真实事实集，159 条）

| 查询形态 | 硬拒绝（现状默认）| **软拒绝 + 数字守卫** |
|---|---|---|
| Q1 精确 key | **100%** tie 0 | **100%** tie 0 |
| Q2 完整问句 `What is the capital of France?` | **0%**（159/159 被拒）| **100%** |
| Q3 前置语序 `France's capital is` | 0% | **11.3%**（129/159 并列）|
| Q4 key + `?` | 0% | **100%** |
| Q5 只给实体 `France` | 0% | **3.8%**（129/159 被拒）|

精确 key 随规模**完全没有退化**（N=159/500/1000 都是 100%，平均 margin 0.260→0.210，
tie 0）。**瓶颈不是规模，是查询形态。**

### 10.31.2 三个具体缺陷（都已定位到代码行）

**① 硬拒绝 = 任何自然语言查询全灭**

```python
if any(self._df.get(t, 0) == 0 for t in q): return 0.0
```

问句里的 `What`、`?`、`'s` 任一未在 key 中出现 → 整条查询对所有事实归零。
**该层实际只支持"逐字模板 key"**，这与"能回答用户问题"差得很远。

**② 软拒绝会凭空编造记忆（已修）**

去掉硬拒绝后，查询**未存入**的 `1955`（库里只有 1954/1958）→ 两条都 1.0 并列，
返回 1954 的答案。这不是"没检索到"，是**伪造记忆**。
修法：用**原文数字串**做守卫（不依赖分词——`1955` 会被 tokenizer 拆成多个 token）：

```python
if set(re.findall(r"\d+", query)) - self._nums: return 0.0
```

实测：`1955` → 0.0 拒绝；`1954` → Germany 1.0；`What won the 1954 World Cup?` → Germany 1.0。
（`_nums` 在 `add()` 里维护）

**③ 实体查询被分词器的上下文差异击穿**

`France`（裸查询）与 `France`（在 `The capital of France is` 里）**分词结果不同**
（无前导空格 vs `ĠFrance`）→ 5 个案例里 129/159 被判为"库外"。
⇒ 只给实体名的查询基本不可用，需要"去前缀空格"的归一化匹配。

### 10.31.3 槽位冲突:没有任何策略

同一 key 存两个 value：

```
add("The capital of France is", "Paris"); add(..., "Lyon")
retrieve(...) -> [(1.0, 'Lyon'), (1.0, 'Paris')]   # 两者并列
```

`sims.sort(reverse=True)` 在**并列时按索引降序** → **后插入者胜**，
且不报告冲突、不记录版本。这是隐式"最后写入赢"，不是设计。

### 10.31.4 一次自我纠错（记入日志）

本节第一版脚本把命中率算成 `ok / n`（`n` = 事实池大小），而不是 `ok / 查询数`，
于是 N=500/1000 显示"精确 key 命中崩到 31.8%/15.9%"。**分母写错，结论完全相反**。
修正后是 100%。——这是 §11.1「实现是不是在骗我」的又一例。

### 10.31.5 结论

| 项 | 判定 |
|---|---|
| 精确 key 检索随规模扩展 | ✅ 1000 条仍是 100% |
| 自然语言查询 | ❌ 默认配置 0%；`soft=True` + 数字守卫后 100% |
| 前置语序 / 只给实体 | ⚠️ 11% / 4%，属**真歧义**（同实体多属性）而非 bug |
| 槽位冲突 | ❌ 无策略，靠并列时的索引顺序 |
| 换词改写（同义不同词） | ❌ 按设计不可用（无 embedding 检索）|

**因此"记忆层能规模化"只在"用户按模板提问"时成立**；要真正可用，缺的是
查询归一化（去标点/去前缀空格/数字守卫）+ 属性消歧 + 冲突策略，而不是更大的索引。

## 10.33 记忆层收尾：冲突策略 + 命令行交付（2026-10-24）

### 10.33.1 冲突策略：同 key 才消解，不同 key 一律标记歧义

`retrieve()` 现在区分两种"top-1 并列"：

| 情况 | 行为 |
|---|---|
| **同一个 key 存了不同 value**（真冲突）| 按策略选一个，`resolved="conflict:<策略>"` |
| **不同 key 并列**（只给实体名，如 `France`）| **不猜**，`ambiguous=True`，交回模型 |

策略（`HebbMemory(resolve=...)`）：

| 策略 | 选择 | 实测（Paris 先写、Lyon 后写）|
|---|---|---|
| `latest`（默认）| 时间戳最大 | Lyon，`resolved='conflict:latest'` |
| `uses` | `accepted` 多者，再按时间 | Lyon（无证据时退化为 latest）|
| `off` | 不消解 | 仍返回 Lyon 但 `ambiguous=True` |

`conflicts()` 可列出全部冲突：`{'k is': ['a', 'b']}`。

**关键点**：`off` 时虽然仍返回列表首项，但带 `ambiguous=True`，
`answer()` 会路由到 `route="ambiguous"`——**不会再静默取后插入者**。


## §10.34 检索区分力：用模型自身激活做赫布式检索（2026-10-26）

**问题**：§10.31 的记忆层靠字符串归一化，换词改写必然 0%。能否不训练、不引入外部
embedding 模型，只用模型自己的激活做 key 检索？——这正是赫布写入里 `φ·key` 那个点积，
只是**不改权重**，改为建一个外置索引 `M = Σ v_j ⊗ φ_j`。

### 10.34.1 门控阈值我一开始设错了

先用 `tools/diag_retrieval.py` 算 AUC（正例=同事实改写，负例=同模板异实体）：
最佳 AUC=0.903（L26 res/mean），看着"过线"。

**这个门槛是错的**：AUC=0.9 意味着约 10% 的负例得分高于正例；N=1000 时
`P(top-1) ≈ 0.9^999 ≈ 0`。**AUC 0.9 在检索任务里等于不可用。**

改用**应用判据**（`diag_retrieval2/3`）：直接测 12 条查询在 79/200 条干扰下的 top-1。
结论完全不同——**AUC 最差的 L6 反而最好**，AUC 最好的 L26 只有 17%。

| 层/池化 | N=79 top-1 | N=200 top-1 |
|---|---|---|
| L4 φ/mean | — | **12/12** |
| L6 φ/mean | 11/12 | 8/12 |
| L22 φ/mean | 6/12 | — |
| L26 res/mean（AUC 最高）| 2/12 | — |

### 10.34.2 真实事实池上的定稿测量（N=490）

30 国 × 3 属性 = 90 条真实事实（真实国名）+ 400 条同类真实干扰
（另 110 国 × 3 + 100 个年份），每条事实一个换词改写。`tools/diag_retrieval4.py`：

| 配置 | top-1 (n=90) | capital | currency | language |
|---|---|---|---|---|
| L4 φ/mean | 82.2% | 30/30 | 30/30 | 14/30 |
| L6 φ/mean | 73.3% | — | — | — |
| L8 φ/mean | 36.7% | — | — | — |
| L4 + 0.75·L6 | 86.7% | 30/30 | 29/30 | 19/30 |
| **cos(L4) + cos(L6) 平均** | **88.9% (80/90)** | **30/30** | **30/30** | **20/30** |

**16 个错误全部是"不同实体"，0 个是"同实体错属性"**；且**全部集中在 language**。

### 10.34.3 为什么中心化会毁掉结果（反直觉，但重要）

| 处理 | top-1 |
|---|---|
| L4 原始 | 82.2% |
| L4 减全局均值 | 35.6% |
| L4 逐属性去模板 | **0.0%** |

**模板方向本身是信号**，不是噪声：查询与 key 共享属性（capital/currency/language）
才判得对；去掉共性方向后只剩实体，而实体之间本来就不可分（与 §10.11.6 的 cos≈0.98 一致）。
所以这里**不要**套用白化/中心化的直觉。

### 10.34.4 language 的失败是"改写距离"，不是"概念缺失"

| 改写 | 命中 |
|---|---|
| `What is the official language of X?`（共享 "language of X"）| **30/30** |
| `What language do they speak in X?`（共享 "language"）| 25/30 |
| `What tongue do people speak in X?`（无共享内容词）| 20/30 |

误差样例：Kenya 的 "tongue" 查询 top-1 是 Ghana/English（0.9211），Swahili 排第二（0.9194）
——**英语确实是肯尼亚官方语言**，属于真实歧义而非实现错误。

### 10.34.7 对旧结论的修正

**§10.11.6「φ 余弦对同模板不同实体无区分力（cos≥0.955）」是位置特定的，不是普遍的。**
那次测的是**末位 token** 的 φ；本次测的是**全位置均值池化的早期层（L4）φ**，
在 N=490 上 82%~89% top-1。旧说法保留，但必须限定为"末位 token、深层"。

### 10.34.8 过程中的两个坑（成本纪律）

   本机仅剩 123 MB 空闲 → 进程被杀，看起来像"挂死"。改为**采集时只留需要的层并均值池化（float32，37 KB/条）**。
2. **import 副作用**：`from diag_retrieval import PAIRS` 会执行整个脚本（无 main 守卫），
   每次白跑一遍 AUC 表 → PAIRS 抽到 `tools/retr_pairs.py`。

## §10.35 注入仿真的判决：零训练注入不能跨改写（2026-10-26）

**问题**（§10.34 之后）：检索能跨改写（88.9%），但那是**外置索引**。把同样的信息
写进权重（`ΔB = c·v⊗φ/|φ|²`）后，能不能跨改写？——不写权重，纯数学仿真即可判定。

读出数学形式（与真实注入一致）：`s_j = (φ_q·φ_j)/|φ_j|²`；对照组用余弦。

数据：90 条事实（30 国 × 3 属性）。三个文本集：`key`（陈述句原句）、
`A`（§10.34 用的改写）、`B`（**更远的改写**，不含属性词）。

| 写入 | 探测 | L14 | L18 | L22 | L26 | 判读 |
|---|---|---|---|---|---|---|
| key | key | 90/90(cos) | 90/90 | 90/90 | 90/90 | 自匹配平凡完美 |
| key | key | 71(inj) | 76 | 71 | 86 | `1/|φ|²` 已开始失真 |
| key | A | 3~4 | 1~3 | 7~12 | 4~11 | **≈ 随机（1.1%）** |
| key | B | 0 | 1~2 | 1 | 5~8 | 0 |
| key+A | B | 2 | 1 | 2 | 13 | **多写一条 key 无帮助** |
| A | A | 39~90(cos) | 90 | 90 | 90 | 同句自匹配 |
| A | B | 2~4 | 2~4 | 2~23 | **37(inj)/59(cos)** | 仅"问句间相似"，非问句↔陈述句 |

### 10.35.1 结论

1. **精确 key 写入对改写零迁移**：`key→A` 最好 12/90（13%），`key→B` 最好 8/90。
2. **多写一条改写 key 不能泛化**：`key+A→B` 最好 13/90 → 这不是"覆盖模板空间"，只是多存一条。
3. **`1/|φ|²` 归一化在多事实下本身就在输**：精确 key 的余弦是 90/90，注入读出只有 71~86/90
   ——§10.28 的 `r = (φWtφ)/(φWt²φ)` 放大问题在 90 条规模上直接显现。
4. `A→B` 在 L26 的 59/90 是**问句之间的相似**（A、B 都是问句），与"陈述句 key 触发"无关。

**机制原因**：注入的读出在**答案位置的最后一个 token**；检索用的是**整个查询的早期层
(L4) 均值池化**。改写信息不在前者的表示里，所以写多少条都补不上。

### 10.35.2 这条路的地图（零训练）

| 想要 | 可行做法 | 是否"权重里" |
|---|---|---|
| 精确模板召回 | 注入 key（已验证 5/5）| ✅ |
| 任意改写召回 | 外置激活索引（§10.34，88.9%）| ❌ 在文件里 |
| 任意改写 + 权重里 | **只有训练**（LoRA/继续预训练）| ✅ |
| 任意改写 + 零训练 + 权重 | 运行时按**查询本身**的 φ 注入（等价 soft-prompt）| ⚠ 权重不动，每次查询现写 |

### 10.35.3 对"教会了吗"的回答（更新）

**没有。** 在 90 条规模上，零训练注入既不能跨改写（≤13%），又会因 `1/|φ|²` 放大
使精确召回从 90/90 掉到 86/90。要"权重里有 + 换词泛化"，只能训练。

## §10.36 运行时 query-keyed 注入：退化为 logit 偏置（2026-10-26）

**想法**（侧支 #42）：把 ΔB 的 key 换成**用户查询本身**的末位 φ，等价 soft-prompt，
零训练覆盖任意改写。

### 10.36.1 代数上它就该坍缩

key 与读出**在同一位置**，所以
`ΔB·φ_q = c·v·(φ_q·φ_q)/|φ_q|² = c·v`，
与查询内容无关。剩下的只有"往末位残差加 c·v"这一项。

### 10.36.2 实测：用错误查询作 key，答案照样被顶上去

10 条单词答案首都，L=18，c=60（与 1L18 交付件同参）：

| 条件 | 平均 rank | top-1 |
|---|---|---|
| baseline（不注入）| 17.0 | 0/10 |
| matched：自己的查询作 key | **0.0** | **10/10** |
| mismatch：**别的国家的查询**作 key | 0.5 | **5/10** |

mismatch 照样把排名从 17 拉到 0.5 —— **注入几乎不读查询**。
（Doha / Muscat 不是单 token，已跳过。）

### 10.36.3 结论

1. `query-keyed 注入` 不是"模型学会了回答改写"，而是"**外部先决定答案，再把该 token 顶上去**"。
2. 要决定答案，仍然依赖 §10.34 的外置检索索引 → 与 `hebb_memory.answer()` 的 logit 偏置同质。
3. **零训练路线至此三条全关**：

| 形态 | 结果 |
|---|---|
| 固定 key 注入（权重里）| 只认原句，跨改写 ≤13%（§10.35）|
| 外置激活索引 | 88.9%，但知识在文件里（§10.34）|
| 运行时 query-keyed 注入 | 退化为 logit 偏置，且答案要外部先给（本节）|

**"权重里有 + 换词泛化"只剩训练一条路。**

结论：**在本机不可行**。

## §10.38 从零 + 赫布：随机特征 + 闭式读出，实测不可行（2026-10-26）

**问题**：容量可以靠稀疏/伪逆/现代 Hopfield 大幅提升（0.138N → N → 2^(d/2)），
那么"不用梯度、只用广义赫布规则（最小二乘/伪逆）从零建语言模型"是否可行？

### 10.38.1 做法

冻结**随机初始化**的全部权重，只对读出层做岭回归（闭式，一次写进所有样本，
等价于广义赫布规则）。配置与梯度基线完全一致：V=2400, L=4, d=64, ffn=256（0.57M）。
特征两种：`final-hidden`（最终 norm 后 64 维）与 `multi-layer`（各层残差 + 最终 5×64=320 维）。
拟合 512k token，评测最后 5% 的不相交区间（64k token）。`taskset -c 7`，拟合 137 s。

### 10.38.2 结果

| 模型 | CE | ppl | top1 |
|---|---|---|---|
| 随机权重（不拟合）| 7.7945 | 2426 | 0.0% |
| **随机特征 + 闭式读出（multi-layer 320 维）** | **7.7219** | 2257 | 18.8% |
| 随机特征 + 闭式读出（final-hidden 64 维）| 7.7306 | 2277 | 16.9% |
| unigram（纯频率表，不用模型）| **5.4452** | 232 | 6.4% |
| **梯度训练基线（同架构同数据）** | **3.4054** | **30** | **37.9%** |

### 10.38.3 判读

1. 闭式读出只比随机权重好 0.07 CE，**比 unigram 还差 2.28 CE**。
2. top1 18.8% 明显高于频率表的 6.4% → 特征里**有**一点信息；但 CE 更差说明
   最小二乘对 one-hot 目标 + 相关特征的标定崩了（过于自信）。
   注意岭回归的 λ 路径到不了 unigram 解（λ→∞ 时连 bias 一起缩到 0 → 均匀分布 logV=7.78），
   所以 7.72 就是这一族的最好值。
3. 与梯度训练的差距是**两个数量级**（ppl 2257 vs 30）。数据预算差异
   （512k vs 5.7M~10.2M token）解释不了这个差距。

### 10.38.4 结论

**容量不是从零建模型的瓶颈，"表示"才是。** 没有梯度训练就没有有意义的特征，
闭式读出再强也只能在线性组合随机特征。因此：

- 赫布/联想记忆的合法位置是**组件**：已训练模型里的记忆写入（§10.34–10.36）、
  以及读出层的一次性拟合；
- 它**不能替代梯度训练**从零建语言模型；
- 现代 Hopfield 的指数容量也不改变这一点——它的 Q/K/V 投影仍是训练出来的。

## §10.39 真 RAG 链路：检索 + 0.6B 生成（2026-10-27）

**问题**：§10.34 的检索 88.9% 只是"找得到"，实际产品要的是"找到后模型能用它回答"。
本节测整条链路：检索 → 拼进 prompt → 贪心生成。

### 10.39.1 做法

`RetrievalMemory`（L4+L6 均值池化，490 条）取 top-1，拼成
`Fact: <key> <value>.` + `Question: <改写查询>` + `Answer:`，贪心生成 5 token。
9 条事实 × 4 条件，0.6B Q4T，单核。

实测成本：prefill 4.2 s，增量 **0.31 s/token**（head 151936 词表是主要开销）。

**先踩了一个实现 bug（§11.1）**：最初把 key 里的 `" is"` 剥掉再拼，得到
`Fact: The capital of France Paris.`——语法坏了，模型自然不跟。
修正为保留原 key 后结果完全改变。**结论只认修正后的版本。**

### 10.39.2 结果

| 条件 | 结果 |
|---|---|
| A 真检索 context | **4/6**（检索命中也是 4/6 → **检索对时 4/4 全对**）|
| B 错 context（另一条事实）| 盲从 1/6，仍答对 3/6 |
| C 无 context | 3/6（参数记忆），**编造池内事实 0 次** |
| D 正确事实 + 3 条同类干扰 | **6/6** |

样例：`What city is the capital of France?` → `'Paris.'`；
`What money is used in France?` → `'Euro.'`

**编造实体对照**（参数里不可能有的知识）：给
`Fact: The capital of Zorbania is Quux.` → `'Quux is the capital of'`；
**不给 context** → `'Zorbania?\n\nA'`（不会，也没有瞎编）。
真事实 + 错 context（Japan/Tokyo 问 France）→ 复述 `'Tokyo is the capital of Japan'`。

### 10.39.3 判读

1. **生成端是听话的**：检索对 → 4/4 答对；编造事实也能复述；加 3 条干扰不掉分。
2. **瓶颈完全在检索**：A 的 4/6 就等于检索的 4/6，两次失败都是 language 类
   （§10.34 已知的弱项）。产品上要提升的地方是检索，不是模型。
3. **不会瞎编**：C 条件 0 次编出池内事实；不知道就答"不会"。
4. 参数记忆确实存在（3/6 无 context 答对），所以"著名事实"上链路优势被掩盖；
   真正的增量在**模型没背过的事实**上（编造实体证明了这一点）。

**结论：真 RAG 链路可用。** 0.6B coder + 外置 490 条索引已能提供可用的离线事实记忆，
全部零训练，索引 24 KB/条，查询 ~1 s。

### 10.38.5 复检：7.72 是设计问题吗？（2026-10-27）

§10.38 的结论必须接受这个质疑：7.72 可能是**我的设计坏**，不是随机特征的天花板。
本节按承诺做了三个改进 + 两个此前缺失的对照。

**改进**：① 投影矩阵 gain∈{1,2,5,10}（RMSNorm 使输入尺度失效，真正起作用的是 gain）；
② 特征 z-score；③ 温度校准（val 选 T，用到 test）。
**对照**：unigram / **bigram**（不用模型，但用了上下文）。

| gain | 有效秩 | test CE 原始 | 校准后 | top1 |
|---|---|---|---|---|
| 1 | 39.4 / 320 | 7.711 | 7.250 | 20.1% |
| 2 | 53.7 | 7.717 | 7.298 | 19.0% |
| 5 | 77.2 | 7.725 | 7.352 | 18.1% |
| 10 | 73.6 | 7.725 | 7.354 | 18.1% |

对照（同一次运行、同一 test 切片）：**unigram 6.1156 / bigram 4.2969 / 梯度训练 3.4054**
（unigram 与 §10.38 的 5.4452 口径不同：这里只用 128k 计数，不可跨表比）。

**判读**：

1. **gain 无效**：秩从 39 提到 77，CE 反而微升（7.711→7.725）。尺度不是问题。
2. **温度校准只救 0.46 nat**：7.711→7.250，仍比 unigram 差 1.13、比 bigram 差 2.95。
3. **有效秩 39~77 / 320** 解释了 §10.38 里"多层拼接没有提升"——随机初始化的
   Transformer 特征本身就是近退化的。
4. **修正此前说法**：§10.38.3 写"最小二乘对 one-hot 目标过度自信"是**错的**。
   最优 T=0.14 < 1 表示需要**锐化**，即原始 logits 偏平（欠自信）。
   真实原因是"特征信号弱 → 拟合出的权重小 → logits 平"，不是校准炸了。
5. 未测的一项：**logistic（softmax）读出**。最小二乘 + 温度是其近似，
   但不能完全排除；这是本节唯一剩下的设计口子。

**结论加强**：在已测的三个维度（尺度、标定、特征预处理）上，7.72 不是设计伪影；
随机特征 + 线性读出**连 bigram 的边都摸不到**（差 3 nat）。"从零 + 赫布不可行"
这一判断保留，但措辞应限于"这个规模、这种随机初始化、线性读出"。
