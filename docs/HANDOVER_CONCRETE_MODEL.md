## 2. 已知错误（勿重犯）

### 2.1 渲染陷阱

`tools/topng.py` 的 `render()` 会给路径坐标乘 `72/25.4`。但 `sp.pkl` 里的坐标**已经是 pt**，再乘会全部跑飞（叠图错位曾三次误判为"偏移基准漏加"）。

```python
# 错
topng.render(sp, ...)        # sp 已是 pt, 内部又乘 K
# 对
# 用 crop.py / 本目录 ov.py, 单位全程 pt
```

**`crop.py` 收 pt，`mmcrop.py` 收 mm。** 混用会 MemoryError（把 mm 当 pt 则尺寸放大 35 倍）。

### 2.2 单位混用陷阱

`walls.json` 同一记录里混两套坐标系，必须先归一：

```
c, gap_pt  → 页面绝对坐标 (pt)
cm, lo, hi → 工程坐标 (mm, 相对 A1)
th         → mm
```

已归一化版：`walls_mm.json`，每条带自检字段。

### 2.3 判别器证伪记录

| 假设 | 实测 | 结论 |
|---|---|---|
| 墙内部有填充，可用填充率区分墙/轴线 | 真外围墙填充率 0.01–0.02；被判为墙的 0.5–1.0 全是内部设备 | **证伪**。本图墙是空心双线，剖面线是描边 |
| 投影密度低值处即为视图边界 | X 方向 ≥20 的列占 93%，无中间低谷 | **证伪**。尺寸链横跨全页，投影法前提不成立 |
| 外围墙检测漏了 | 外墙是**多点折线**，被 `len(q)==2` 过滤丢掉 | 检测器 bug，非图元缺失 |

### 2.4 栅格化偏差

墙/柱面积**不能用栅格算**（每边外扩半格，600 墙高估 13%）。

```
栅格墙面积 307.5 m²  →  解析并集 257.2 m²  （高估 19%）
```

模型里的墙柱面积用解析法（扫描线 + Y 区间合并）。

### 2.5 数据源坑

```
axis_grid.json  X1=308.9   → 偏 13.4mm，8 条墙独立反解均为 308.525，用 308.525
components_col.json 38 座  → 旧三角形结果，废弃；现为 39
columns.json 37 根         → 缺 A4 与骑斜墙的 B5 位，实际 39
ledger.json 的 text 类      → 实为笔画（中位 1.44×2.04pt），不是文字对象
```
