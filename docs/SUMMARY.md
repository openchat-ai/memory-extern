## 1. 目标与最终状态

**原始目标**：在手机上训练一个可用的低比特小 coder（1-bit 或混合精度）。

**实际达成**：
- ❌ 没有得到能写出**语义正确**代码的模型
- ✅ 得到一条**可交付的压缩路线**（§33.20 / §39：0.29M 的 1-bit = **206 KB**，5.50× 压缩，推理数值正确）
- ✅ 找到并修复 **4 个静默 bug**，其中一个影响全部历史训练
- ✅ 把「0.29M–0.57M 在本机能做什么」这一区间**测清楚了**

## 2. 可交付的工程结论

### 2.1 1-bit 导出（项目最初的问题，已回答）

| 项 | 值 |
|---|---|
| 模型 | 字节级 0.29M（L=4 d=64 ffn=256 V=182） |
| fp32 原文件 | 1134 KB |
| **1-bit 导出** | **206 KB，压缩 5.50×** |
| 导出正确性 | logits 相对误差 **0.47%**，验证通过 |
| 对比 | Q4T 的 223 MB → **1/1000** |

**但 1-bit 不提升能力**：CE 3.13 vs fp32 2.51，top1 25.0% vs 39.6%（§35）。
**1-bit 省的是内存和带宽，不是能力。**

### 2.2 推理参数（跨模型不可照搬）

| 项 | 值 |
|---|---|
| 最优解码 | `TEMP=0.7  TOPK=25  REP=1.0(关闭)` |
| 重复惩罚 REP | **有害**（token 级越大越差）；字节级上曾有效 —— **不能跨模型照搬**（§44.6） |
| 采样实现 | `lg - lg.max()` 平移，**不能用 `lg / lg.max()`**（§41.2） |

## 3. 关键定量结论

### 3.1 各方案横向对比

| 模型 | 表示 | V | 参数量 | steps | CE | top1 | 生成 |
|---|---|---|---|---|---|---|---|
| **TK** | token 级 | 2400 | 0.57M | 11200 | 3.41 | 37.9% | **最好**（有真实英文与结构） |
| BY6 | 字节级 | 182 | 0.29M | 11200 | **1.82** | 53.5% | 字母汤 |
| BY5 | 字节级 | 182 | 0.29M | 11200 | 2.28 | 50.1% | 字母汤 |
| BY3bn | 字节级 1-bit | 182 | 0.29M | 5000 | 3.13 | 25.0% | 第二行即退化 |
| TKB | token 级 1-bit | 2400 | 0.57M | 5600(停) | 6.19 | 10.8% | **学不动** |
| TKB' | token 级 1-bit (lr 扫描最好值 2e-4) | 2400 | 0.57M | 1200 | 5.39 | 9.9% | **仍学不动** |

### 3.2 **CE 会给出与生成相反的排名**（最重要的一条）

各自对自己的 n-gram 基线定标：

| | unigram | bigram | trigram | 模型 | 相对 trigram |
|---|---|---|---|---|---|
| 字节级 BY6 | 3.392 | 2.686 | 2.108 | **1.822** | 好 14% ✓ |
| Token 级 TK | 5.698 | 3.455 | 2.939 | 3.405 | 差 16% ✗ |

**CE 说字节级更好，生成说 token 级好 1.9 倍。**

单位对齐（平均 1 token = 2.91 字节，teacher-forced top-1）：

```
字节级  56.5%/字节  → 整 token 全对 19.0%
Token级 36.1%/token → 整 token 全对 36.1%     ← 1.9×
```

原因：trigram-over-tokens 本身就是极强的复制机；而**生成质量取决于能否保持在分布上**——
token 级选错 token 渲染出的仍是一个合法的词，字节级选错一个字节整个词就毁了。

> **§44.3：CE 不是生成能力的可靠代理，且方向可能相反。**

### 3.3 1-bit 的边界条件

| 词表 | 1-bit 结果 |
|---|---|
| V=182（字节级） | 接近可用（CE 差 0.62） |
| V=2400（token 级） | **学不动**（CE 6.19，自 1400 步起平台，低于 unigram 基线） |

**已补 lr 扫描（§46）**：2e-5 / 6e-5 / 2e-4 三档，均学不动

| lr | CE | 相对 unigram(5.698) |
|---|---|---|
| 2e-5 | 7.288 | -28% |
| 6e-5 | 6.183 | -8% |
| 2e-4 | **5.386** | 只好 5% |
| *fp32 对照* | *3.405* | *好 40%* |

> ✅ **公平性保留意见已关闭**：不是 lr 选错，换 lr 也救不回来。
> 1-bit 在 V=2400 下只学到了「哪些 token 常见」，没学到分布结构。
>
> 与字节级对照（矛盾未解）：词表大 13 倍，1-bit 与 fp32 的差距
> 从 0.62 涨到 **1.98**。原因未验证，但两个数据点一致。

### 3.4 环境事实：`online` 文件不可信

`cat /sys/devices/system/cpu/online` 显示 `0-4,7`，但 cpu7 实际不可用
（`taskset: Invalid argument`）。**必须逐核 `taskset -c N true` 探测**（§46.5）。

### 3.5 速度（本机，单核 cpu7）

| 配置 | ms/step | tok/s |
|---|---|---|
| 筛选一组（4 路并行等效） | — | **2.80 s/组** |
| V=2400 fp32 / bitnet | 307 / **272** | 1667 / 1880 |
| V=182 fp32 | 216 | 2371 |

**1-bit 在大词表下仍快 11%**（§35.2 说「加速归零」是错的，已修正）。

## 4. 查出的 4 个静默 bug（都不报错）

| # | bug | 影响 |
|---|---|---|
| 1 | `compress_vocab` off-by-one，最高频 token 被丢成 UNK | 词表覆盖 56%→**92%** |
| 2 | 评估脚本 `block_size` 硬编码 512 | 位置嵌入一直随机 |
| 3 | FFN 的 `dW1` 漏 GELU 导数（ggml 分支对、非 ggml 分支错） | 梯度偏大 **2×** |
| 4 | **CE 梯度把减法写成赋值**（`put_along_axis` 覆盖而非减 1） | 所有梯度偏大 9%，**只作用在正确 token 上 → 过度自信** |

bug 4 的修复效果（同配置 11200 步）：

| | CE | ppl | top1 |
|---|---|---|---|
| 修复前 BY5 | 2.2801 | 9.78 | 50.1% |
| **修复后 BY6** | **1.8219** | **6.18** | **53.5%** |

**这些 bug 之所以躲过去，是因为训练能收敛、loss 能下降、不报任何错。**
只有有限差分对拍能发现。

## 7. 方法论（详见 `AGENTS.md` §10）

**当晚六次「拿便宜的代理指标代表昂贵的东西」**：

| 代理 | 被当成 | 真相 |
|---|---|---|
| 筛选 2.8 s/组 | 训练速度 | 50 步根本不训练 |
| CE | 生成能力 | §44 方向完全相反 |
| loss 在降 | 梯度正确 | §43 差 9% |
| 覆盖率 56% | 词表大小决定 | 藏了 off-by-one |
| 合成任务 99% | 能做语法分类 | 只看了 1 个字符 |
| 200 步没发散 | lr 可用 | 恰好停在最优点 |

**只有两个判据不是代理**：端到端生成实测、有限差分对拍。
其余一切（loss / CE / top1 / 覆盖率 / 耗时 / 收敛曲线）都是代理。

**代价**：约 4 小时训练与排查全部落空。

## 8. 如果继续，应该从哪开始

1. **先跑 `tools/selftest.py`** —— 任何训练之前
2. **任何性能判断以生成实测为准**，CE 只能当诊断信号
3. 1-bit 的 lr 扫描已补（§46），结论成立：换 lr 也救不回来
4. 换架构（RoPE / SSM / 指针网络）是唯一的模型侧出路，
   但那是新方向，需要重新评估，不要用今晚的代理指标去论证它
