## 2.x 结构二分探针实验（board_top_probe.v / build_probe.tcl，无 SDC，0/0）※ 关键新证据
| lane | PROBE_MODE        | elapsed | 结果                     |
|------|-------------------|---------|--------------------------|
| 64   | 3 完整引擎        | 352s    | PNR-DONE ✅（曾误判死循环）|
| 64   | 1 仅 MAC 阵列     | 353s    | PNR-DONE ✅（acc_bus 全宽扇出防 sweep）|
| 64   | 2 仅归约树        | 117s    | PNR-DONE ✅ |
| 32   | 3 完整引擎        | 186s    | PNR-DONE ✅ |
| 128  | 3 完整引擎(+SDC)  | >15min  | 真死循环 ❌（watchdog 实证，见 §4）|

关键推断：
- 早期"MODE=1 仅阵列 62s 通过"是假通过：acc_bus 除 [31:0] 外全悬空，阵列尾级被 DCE sweep。
- "死循环"判定的早期样本均观察 <5min，而 352s 收敛案例显示 Routing 有一段 2-3min 日志静默期，
  此后才继续推进 → 早期全部"死循环"结论被推翻。
- 64-lane 引擎（含阵列+树全连、真实 acc_bus 全宽扇出）352s 收敛，128-lane 同结构 15min 不收敛 → 
  触发因子是 lane 规模跨越 64→128 触发的布线引擎崩溃，而非 SDC/结构组合/归约树。

## 4. 死循环实证（watchdog 采样）
- 128-lane：log 行数恒 74 不再增长；gw_sh CPU 单核持续满转：892(10:40)→951.8(10:41)→1011(10:42)；
  连续 15+ min 无进展；进程不退出，需手动 kill。
- 收敛对照（64-lane 352s）：log 也有 2-3min 静默期但 CPU 至 ~350s 后果断突破（10:18:35 116→10:19:35 148 行）。
- 判据修正：单看"log 恒定 + CPU 满转"不足判定死循环，必须等 >5min（或 CPU>400s）才可下结论。

## 5. 排除项（已实测推翻）
- 非 SDC 语法错误（已修 set_clock_group→set_clock_groups，TA2000 消失后仍卡）
- 非 SDC 存在与否（无 sdc 对照 #4 同样卡）
- 非 place/route 选项（0/0、3/2 均卡）
- 非 enable_dsrm（1 仍卡）
- 非 RTL 版本（上游最新 7f85de0 含分层归约树/PIPE_IN/PIPE_MUL 仍卡）
- 非全局频率（global_freq=200 与 SDC 均指向 200MHz，无 100MHz 兜底混入）
- 非归约树 RAM 抽取（syn_ramstyle="registers" 无效、Extracting RAM 仍在；且 MODE=2 117s 收敛）
- 【推翻】早期"引擎整体不可收敛"结论——64/32-lane 收敛，1320s 级即可完成

## 6. 现存假设
根因指向 Gowin 布线引擎在 engine 128-lane（4096 累加器总线、约 4.5 倍 64-lane 结构密度）下的
工具级布线不收敛：
- 证据链：32/64-lane 同 RTL 结构收敛（186s/352s）→ 128-lane 同结构 15min 不收敛 = 规模阈值
- 【A实验】128-lane 改 2组×64（GROUP_LANES=64，恢复顶层 TOP_LANES=4→2，engine_core/reduction_tree
  增 GROUP_LANES 参数透传）→ Routing Phase 1 依旧死循环（CPU≈墙钟满转，5.3min 停 [60%] Phase 0）。
  → 死循环与归约树分组/顶层合并规模无关，是 128 lane 数据通路本身宽度/扇入引发布线不收敛。
- 【96-lane 否决】96/160/192 等非 32×2^k 规模在 PA 阶段报 DPB WRITE_MODE=2'b10（reduce_group
  LANES 非 2 幂→stage 数组抽 DPB 落不支持区间），非死循环而是独立设计盲区，非合法 PnR 点
  → "64→128 精确到 lane 数拐点"无法用合法中间规模测量，拐点判定锁定为 64 收敛 / 128 死
- 下降方向：需上游在 128-lane 下进一步拆分（如归约树段间插 reg、acc_bus 分 2 组并行归约），或确认工具版本限制
