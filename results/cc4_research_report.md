# CC4 格式研究完整报告

日期:2026-10-06
状态:终版 — 发明线关闭, 方法论沉淀已入库。

## 0. 结论速览

| 维度 | 结果 | 相对基准 |
|---|---|---|
| 保真度 (med.max) | 0.0806 (CC4-256) | Q4_0 0.0615, 差 +31% |
| 字节 | 0.508 B/elem | Q4_0 0.5625, 省 9.7% |
| 解码速度 | 2.80 GB/s | Q4_0 4.45 GB/s, **慢 1.57×** |
| 判定 | **不值得替换** | — |

CC4 的全部卖点(省字节)被两样东西吃光:共享 scale 带来保真度损失 + 解码计算开销。
在计算受限设备上不存在"省字节=更快"。发明目标没有达成。

## 1. 动机与设计

目标: 发明一个比现有 4-bit 格式更好的存储格式。
设计: Clustered Columnstore 4-bit (CC4) — 借数据库 columnstore/投影索引思想:
- superblock = 256 元素
- scale 列 (fp16) 与 4-bit code 列分离 (投影索引)
- 可调 grain (32/64/128/256): grain 越大 scale 越省、共享越广

动机来自三个被先后证伪的假说:
1. "视觉机理"格式 (EYE/FOVEA): 只描边界、权重大部分平坦 → 实测 平坦率仅 4.4%, 熵下限 3.0 b/elem, 权重缺乏空间冗余 → 证伪。
2. "diff 残差": 用锚点+差异描述 → 需保留参考权重, 与量化语义冲突 → 弃。
3. "共享 scale = 免费": 每大 grain 一个 scale 只省字节不伤保真 → 验真后证伪 (见 §3)。

## 2. 验证方法 (可复现, 全部入库)

- 基准: qwen3-0.6b-q8_0.gguf (参考曲线), 6 个候选 gguf 同源 requant。
- 度量: med.max / med.mean 相对误差, 分母 = 32 块内 max|W|, 与 cmd_distort 参考曲线同尺度。
- 真量化器: 官方 gguf 0.19 `Q4_0.quantize_blocks`; 手写 Q4_0 编码器与之 **字节级一致** (576/576 字节无差异)。
- 采样: 同 256-block 窗口, 同度量, 真实权重 + 真实文件字节。

## 3. 关键过程: 三个被当场抓出的假结果

1. **0.0624@0.508B 的"免费省字节"** → 假象。那是每 32 独立 scale 的包装, 不是真共享; 真共享后 med.max 涨到 0.0806。
2. **速度"CC4 快 1.88×"** → 假象。基准代码溢出 bug (激活因子随块下标增长) + 缓存热身序偏置; 修复后 CC4 反而慢 1.57×。
3. **CC4-256 保真度持平 Q4_0** → 假象。编码器广播 bug (idl[:,None] 多一维, 3D 矩阵导致相对误差 1.4), 修复后才是真值 0.0806。

这三次都是"自洽但假"的测量 —— 恰恰是为什么"验真"是论文级交付的必备环节。

## 4. 速度拓扑: 真正的发现 (非 CC4, 但同批跑出)

本机 (骁龙 8 Gen 1 / taro, 4×A510 + 3×A710 + X2):

| 配置 | t/s | 相对 |
|---|---|---|
| 全 8 核 (默认) | 3.15 | 1× |
| **绑 cpu4-7 + 4 线程** | 28.68–31.84 | **×9–10** |
| 仅大核组 3× | 18.67 | ×5.9 |
| 仅 X2 单核 | 11.92 | ×3.8 |

格式间差异仅 ±5% (Q4_0 28.6 / IQ4_NL 26.5 / MXFP4 26.7 / Q2_K 27.2 / Q3_K_S 25.8)。
结论: 速度主变量是核心拓扑, 不是格式。封装: `run_llama_pinned.sh` (实测 31.84 t/s)。

## 5. K3 场景外延 (非下结论, 供参考)

K3 专家 (1.45 TB) 原生 MXFP4, 每 token 需读 ~26 GB 激活专家。机械盘顺序带宽 100–200 MB/s →
~170 s/token, 物理墙, 索引放内存救不了带宽。CC4-256 对 MXFP4: 省 4.4% 字节、med.max 0.081 vs 0.138
(尾部误差改善), 但 med.mean 略差且无原生 tensor-core 路径 → 工程上不构成替换理由。

## 8. Q4F8/Q4F8-nl 新格式 (CC4 线关闭后的增量发明)

CC4 线关闭后, 以相同方法论发明了 Q4F8 (1B log-scale + encoder-aware codebook):

| 格式 | B/elem | med.max | med.mean | 解码速度(rel Q4_0) |
|---|---|---|---|---|
| Q4_0 | 0.5625 | 0.0611 | 0.0305 | 1.00× |
| IQ4_NL | 0.5625 | 0.0626 | 0.0273 | ~0.93× |
| **Q4F8** (线性码本) | **0.5312** | 0.0622 | 0.0324 | **0.98×** |
| **Q4F8-nl** (IQ4 非线性码本) | **0.5312** | 0.0623 | **0.0296** | **~0.95×** |
| MXFP4 | 0.5312 | 0.1383 | 0.0360 | ~1.0× |
| CC4-256 | 0.508 | 0.0806 | 0.0410 | 0.64× |

关键设计:
- **1B 对数 scale** (7-bit log2 ∈ [-12,-4]) 取代 Q4_0 的 2B fp16 scale, 省 5.6% 字节。
- **encoder-aware codebook**: 编解码时在 17 个候选 scale 间选最小化块内 max 误差者 —— 补回 1B scale 的保真损失 (naïve 独立量化会崩到 0.1031)。
- **非线性码本零成本**: 标量实现 Q4F8-nl 慢 12% 是**查表假象**; NEON `vqtbl1q_s8` 把 16 项查表变成单指令, 非线性版反而比线性快 ~6%。

速度验证纪律 (§7.3) 延伸: 本轮发现骁龙 8 Gen 1 的 walt 调速器空闲降频 (cpu4-6→1.88GHz, cpu7→787MHz), 需 `dd` 热身拉起满频后再测, 否则格式间对比失真。

结论: **Q4F8-nl 是"省字节 + 保真追平 + 速度不输"三者兼得的真增量**; 数据与工具已入库 (`tools/q4f8_codebook.py`, `tools/q4f8_neon_bench.c`)。

### 8.1 命名与归属 (Q4T)

格式以发明者姓氏 (唐) 命名 **Q4T**, 技术正式名 **Q4_e7m0_nl** (结构自描述):
- Q4 = 4-bit 数值, e7m0 = 7-bit 幂指数 scale (2^l, l∈[-12,-4], 1B), nl = 非线性码本
- 部件归属: Q4_0 布局 (ggml 官方), IQ4_NL 码本 (llama.cpp), e8m0 幂 scale 思路 (OCP MX)
- **原创贡献仅一处**: encoder-aware scale 选择 (17 候选按块内重构误差反选 scale)。不足以构成专利; 价值在生态与论文署名。

### 8.2 全位宽扫描 (QxT 家族, `tools/qxt_fidelity_scan.py`)

QxT = 各 bit 位宽沿用同结构: 1B e7m0 scale + 32b/8 字节 code, 块=32, 称 Q1T/Q2T/Q3T/Q4T/Q8T。
三种码本: lin (均匀), lloyd (数据驱动 k-means, 训练/测试窗口分离), kval (IQ4 采样)。
训练=前 14 tensor (3584 块), 测试=后 6 tensor (1536 块) —— **out-of-distribution 泛化数**。

| 位宽 | lin med.max/mean | lloyd med.max/mean | kval med.max/mean | 现有真实最优 | lloyd vs 现有 |
|---|---|---|---|---|---|
| Q8T | 0.0038/0.0019 | 0.0109/0.0031 | 0.0630/0.0294 | 无对照 | 自设基线 |
| Q4T | 0.0630/0.0323 | 0.0887/0.0310 | 0.0630/0.0294 | Q4_0 0.0611/**0.0302** | kval 略优 (Q4T-nl 即此) |
| Q3T | 0.1340/0.0681 | 0.1522/0.0602 | 0.1345/0.0600 | Q3_K_S 0.1184/**0.0529** | 仍输 (分块双 scale 无法补) |
| Q2T | 0.3211/0.1586 | 0.3143/0.1192 | — | Q2_K 0.1790/**0.0700** | 输, 但 lloyd mean 拉近 33% |
| **Q1T** | **1.000**/0.2507 | **0.6453/0.2163** | — | 无 | **突破** |

关键发现:
1. **Q1T lloyd 突破** (med.max 1.0 → 0.645): 1-bit 对称双值码本 `[-a,a]` + per-block e7m0 scale, 块峰被精确表示, 数据驱动分布在训练/测试分离后仍稳 → 真实泛化。
2. **2/3-bit 的 lloyd only 提升 mean, max 仍输**: 低位宽物理上需要分块双 scale (如 Q2_K), 单 e7m0 补不了。
3. **Q4T-nl 仍是全家桶中最强增量**: 4-bit 场景省字节 + 挖均值 + 不降速度。

结论: QxT 家族价值排序 = **Q1T (突破) > Q4T-nl (挖均值) > Q8T (基线)**; 低 bit 战场的真正船票是 1-bit 双值 + per-block e7m0 结构。

## 7. 方法论红利 (这才是本次研究的最值产出)

1. 真实工件 + 真量化器验证, 抓出 3 个自洽假结果。
2. 同度量对比框 (cmd_distort), 跨 6 格式可复现。
3. 速度测量的防坑纪律: volatile sink 防死码消除、缓存序互换、合法指令集 (不 -mcpu=native)。
4. 本轮新增: 数据驱动码本必须**训练/测试窗口分离**评估, 否则 in-distribution 上界伪装成泛化数。
